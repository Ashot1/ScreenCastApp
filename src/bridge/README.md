## Модель ABI6 и плагины ABI2 (24C / ADR-022)

`ambient_model.h` v6 заменяет v5 (все 17 экспортов переименованы): `ambient_model_v6_dispatch(op, token, keys, count, root, out)` — `root` (абсолютный UTF-8 путь 1…1024 байт без NUL, иначе 1 до Core) — корень частных папок локальных серверов. `dispatch_with` создаёт `LocalHost` после захвата `busy`, поэтому на любом пути выхода процессы останавливаются до его снятия; после цикла неподтверждённые остановки записываются в журнал вызовов (`record_unconfirmed_stops`). Ключ локального сервера — компактный JSON значений переменных (та же проверка ASCII 33…126 ≤16 KiB). Тестовый `ambient_model_test_dispatch` получил `root`. `ambient_plugin.h` v2 заменяет v1 (11 экспортов переименованы) и добавляет описатель операции: `operation_begin` (≤64), `operation_cancel` (запрос остановки, флаг необратим — на каждое обнаружение свой описатель), `operation_close` (4, пока вызов на нём идёт). `discover(memory, op, root, plugin, server, generation, key, …)`: Core выбирает цель, Store не держится во время обнаружения, JSON со статусом, хвостом stderr и `stop_confirmed`. Таблица описателей — единственное состояние моста плагинов. Тесты: `tests/plugin_abi.rs` (корень, описатель), `src/plugin_tests.rs` (локальный сервер: обнаружение без значений и с ними, вызов моделью через `test_dispatch`, процесс остановлен до возврата, секрет не в SQLite и журнале; отмена обнаружения через описатель, `close` — 4 до возврата).

## Model ABI4 / 08B — текущий договор

`ambient_model.h` заменяет model ABI3 целиком; старые v3 exports и result/receipt getter удалены. Memory3/auth1/local-source1/Codex1 не меняются. Один прежний handle/Store обслуживает prepare, одноразовый dispatch/cancel/close, ledger, read-only feed/details, visibility, clear discussion, проверку адресата и copy. Exact discard-preview принимает process request ID и не отменяет более новый preview.

Фиксированные layouts: Attempt80/Summary128/Completion96/Preview48/Request48/ProposalTarget16 bytes, alignment8; Span8/alignment4. Completion содержит только учётную попытку и необязательные task/workspace revision успешной публикации. Это не capability и не постоянный receipt. Request явно задаёт Continue или NewContext, ожидаемые task/workspace versions и optional точный proposal/content revision для ответа. Все буферы принадлежат caller; capacity проверяется до side effects, ошибки сохраняют outputs.

JSON существует только как Core-produced output: exact context<=256KiB, полный feed<=128rows/4MiB с каждой строкой<=32KiB, отдельные details<=256KiB. Native не передаёт JSON для мутации. Feed/details не требуют High и не занимают model transport. Copy возвращает только проверенный текущий message<=16KiB; validate проверяет актуальный адресат голоса без copy/POST. Show/Continue/copy/validate повторно проверяют process session/report/High/pause и все основания; hide/clear discussion — локальное управление. Старый receipt не восстанавливается после restart.

Публикация полного набора следует за учётом расхода и атомарно перепроверяет все fences. Цель черновика — ProposalId/content revision, а workspace revision защищает область целиком. Никаких callbacks, cross-language allocations, скрытых retries или сохранённых credentials/capabilities. Production app не включает test-support hooks. Прежние разделы ABI2/ABI3 ниже — исторические контракты заменённых срезов. Проверки: `target/verification/08b/`; Windows/C# и native UI отдельно не проверены.


## Codex ABI1 / 14A

[`ambient_codex.h`](include/ambient_codex.h) добавляет15 конкретных typed операций `ambient_codex_v1_*` на существующем memory handle. Memory3/auth1/local-source1/model3 layouts прежние. Header/window входы проверяются до доступа/копирования:256KiB+1/1MiB+1. Output window<=128records/256KiB, preview16KiB, saved metadata<=50rows/256KiB. Caller владеет всеми живыми выровненными непересекающимися буферами; ошибок с частичными outputs нет. Нет callbacks или cross-language allocations.

Begin/permit/plan/finish разделяют Core admission и native I/O. Cancel выставляет отдельный Core atomic без ожидания Store; actual FD cleanup предшествует finish/abort, release остаётся busy до него. Cursor — Core token, не внешний offset. Bind принимает только индекс текущего Core window, повторно проверяет настройки/задачу/session/High/pause и атомарно пишет evidence/metadata/revision. Saved metadata возвращается вместе с evidence ID; generic memory ABI не содержит Codex-полей. Исторический охват всегда local_records_only/local_window. Structured status — app projection, не цитата и не подтверждение пользовательской задачи.

Статусы source1 дополнены16 format/17 conflict только в Codex ABI. Реальные временные round-trip и Swift/Core/SQLite/localHTTP/copy проверки описаны в `target/verification/14a/`; C#/Windows/UI/live parity не заявлена.


Auth использует отдельную ABI v1 в [ambient_auth.h](include/ambient_auth.h), реализация `src/auth.rs`. Она не меняет memory ABI v3 ниже. `begin` принимает bounded типизированный снимок и возвращает новый handle; `prepare`, `callback`, `dispatch` следуют одноразовой последовательности Rust. Регистрация и credentials передаются полями/spans, без JSON/SDK типов. Fixed record содержит до 64 scope spans, а caller-owned bytes capacity не меньше 65 536 проверяется до сетевого вызова, поэтому маленький output не требует повторного POST. Ошибки не содержат секретов.

Auth registry отделён от памяти; lookup освобождает общий lock перед I/O, отдельный busy guard удерживает операцию до возврата. `cancel` выставляет atomic flag без ожидания сетевого mutex; `close` возвращает BUSY во время принятого вызова. Native обязан сначала дождаться Rust и listener/connections, затем close. Handle не переиспользуется. Никаких callbacks или native указателей в Rust. Срок операции — 5 минут; timeout запроса не означает завершение DNS cleanup. `AuthCoordinator` сериализует Keychain commit/logout и запрещает поздний commit по поколению и сроку.

Узкий типизированный C ABI v3 для памяти ADR-004/005. `ambient-bridge` собирается как `staticlib`/`rlib`, unsafe изолирован здесь. Договор: [include/ambient.h](include/ambient.h); типы Rust: `src/abi_types.rs`. Прежние ABI v1/v2 удалены. Память, ID, ревизии, лимиты и решения принадлежат `ambient-core`.

`ambient_v3_open` принимает абсолютный путь UTF-8 без NUL (1–16 384 байт). Каждый успешный open возвращает непрозрачный ненулевой `uint64_t` handle и требует close. Handle не переиспользуется в процессе; повторный close/поздний вызов получает `INVALID_HANDLE`. Registry и Store защищены отдельными mutex. Все вызовы синхронные вне UI actor; lookup клонирует Arc и освобождает registry до Store lock. Закрытие ждёт принятую синхронную запись, удаляет handle и отменяет model check; отдельная принятая model operation удерживает Store для позднего учёта. Фоновых workers, callbacks и асинхронной отмены нет. Паники не выходят в C, poisoned registry возвращает ошибку.

Операции: глобальная пауза, дела, пользовательские заметки, изменение/перенос/удаление сведений, явные симметричные связи и решения пользователя. Историческое поступление источника и явная пользовательская привязка — отдельные типизированные функции. Исторический импорт не создаёт дело, не выбирает новый ID сведения и не выдаёт себя за пользовательское подтверждение. Исходы `AmbientIngest`: applied (ID), forgotten, protected user confirmation. Подключений сервисов здесь нет.

ID/ревизии положительные до `INT64_MAX`; UTC-время — знаковые Unix-секунды, optional поля имеют отдельный флаг 0/1. C enum-теги проверяются на входе. Ключ/версия и текст передаются отдельными указателями с длиной, без JSON. UTF-8 текст не обрезается и может содержать внутренний NUL; ключ/версия — непустые без NUL. Точные размеры и все флаги описаны в заголовке.

Списки используют `AmbientPage` и отдельные caller-owned массивы фиксированных записей/байтов. `AmbientSpan` задаёт offset/length в байтовом буфере. `bytes_used` — только длина этого строкового буфера; общий предел 256 KiB включает также метаданные записей. До 50 элементов, продолжение `next_after` при `has_more=1`; byte cap может уменьшить страницу. Нет неограниченного полного снимка памяти. Только `BUFFER_TOO_SMALL` возвращает метаданные требуемого размера без частичных массивов/текста; остальные ошибки сохраняют outputs. Слишком маленький буфер мутации не запускает.

Удаление получает ожидаемую ревизию основного дела и точный массив дополнительных затронутых дел/ревизий. `deletion_impact` позволяет прочитать их страницами; Core повторно вычисляет набор и проверяет его в транзакции. Максимум 1 023 дополнительных живых дела. Перенос/связь проверяет обе ревизии. Связь возвращает текст и ревизию другого дела, поэтому UI не подменяет показанную ревизию свежим чтением перед изменением.

Коды `uint32_t`: 0 OK, 1 INVALID_ARGUMENT, 2 INVALID_UTF8, 3 TOO_LONG, 4 BUFFER_TOO_SMALL, 5 STORAGE_ERROR, 6 UNSUPPORTED_SCHEMA, 7 INVALID_HANDLE, 8 PANIC, 9 RESOURCE_LIMIT, 10 NOT_FOUND, 11 DELETED, 12 STALE_REVISION, 13 TASK_COMPLETED. Указатели остаются собственностью caller, не сохраняются после вызова; выходные области должны быть живыми, выровненными и не пересекаться между собой или с входами. Проверка null/длины не доказывает доступность произвольной памяти C. Cross-language allocate/free нет.

`cargo test --workspace --locked` проверяет реальные БД через Rust exports; `yarn test:swift` проверяет настоящий импорт/layout и Swift–C–Rust путь. C#-оболочка и parity ещё не проверены. Общие решения: [ADR-004](../../docs/decisions/0004-multiple-tasks-and-source-memory.md), [ADR-003](../../docs/decisions/0003-foundation-storage-and-native-boundary.md).

План использует отдельные страницы `steps/checks/dependencies/references`. `AmbientPage.task_revision` — ревизия владельца снимка, 0 только для глобальной страницы; `plan_completeness` — 0/1/2. Lifecycle и suppression входят в `AmbientTask`, а состояние связанного дела — в `AmbientLink` (64 байта). Проверки unknown/passed/failed содержат отдельный флаг пользовательского времени; шаг содержит вычисленный ready и отдельные flags точного optional prompt/reference. Отсутствующее поле имеет flag 0/length 0; присутствующее пустое значение отвергается.

Команда завершения принимает точный итог, массив выбранных уже связанных дел, до 32 точных ссылок и все ожидаемые чужие ревизии из `completion_impact`. Preview исключает сохраняемые связи; commit повторно вычисляет тот же удаляемый набор внутри транзакции. Завершение, reopen, suppression и все мутации плана — самостоятельные типизированные операции; каждый вызов проверяет ревизию владельца. Копирование в clipboard остаётся только в native UI и не исполняет ссылку/промпт. Схемы1/2/3/4/5/6 отклоняются read-only; совместимости и автоматической смены пути нет.


## Model ABI2 / 06F (исторический контракт, заменён ABI3 ниже)

`ambient_model.h` заменяет model ABI1 целиком. Memory ABI3 и auth ABI1 неизменны. Layout/ownership ABI2 закреплены до реализации: Attempt80 bytes (purpose заменяет прежний reserved), Summary128, Receipt40, Completion128, Preview32, Citation32, Result88, alignment8 кроме Span8/alignment4. Только fixed-width поля, закрытые enum tags, flags0/1, reserved0 и caller-owned буферы. Ошибки сохраняют outputs; недостаточный buffer проверяется до one-shot begin/dispatch. Preview до256KiB точного JSON Core, result buffer320KiB/citations32, copy16KiB.

Один прежний model registry/Store lease обеспечивает session facts, prepare/begin/dispatch/cancel/close/summary/result/copy. Native передаёт process-local nonzero epoch и текущие session/report facts без credentials; только committed High Fast connectivity открывает помощь. Model begin принимает закрытый Low/High и request ID:0 connectivity, ненулевой — одноразовый Core snapshot/High. Сам текст запроса от native не принимается. Preview собирает Core в одной read transaction; полный HTTP body проверяет provider до dispatch. Receipt связан с request/attempt/task/revision/epoch; Core повторно проверяет его при выдаче текста копирования.

Registry lock освобождается перед Store/operation mutex и HTTP. Begin резервирует один допуск на Store; dispatch commit possible-send unknown предшествует POST. Busy длится до реального transport/runtime/accounting return. Cancel закрывает публикацию/копирование; close требует actual return и освобождает допуск. Native сохраняет generation fence после close. Memory close отменяет новые действия, но Arc lease сохраняет SQLite для позднего usage. Итоговый commit с ошибкой не стирает durable unknown. Никаких callbacks или cross-language allocations.

Тестовая feature `model-test-support` добавляет только loopback transport hook для отдельной Swift–C–Rust интеграционной сборки. Production app его не включает; endpoint/model/prompt не конфигурируются production ABI. Ни реальные model/token POST, ни пользовательские данные для этих проверок не нужны.

Сигнал отмены сохраняется вместе с capability и snapshot после release. Отмена, пришедшая во время commit, не может сделать receipt/допуск действующим; конечный ABI completion повторно видит тот же flag. Закрытие уже завершённого допуска сохраняет его проверенный результат, закрытие неиспользованного — отменяет и освобождает preview.

Проверка06F (19 октября2026): полный `yarn verify` exit0 —8 tooling/83 Rust/48 Swift; отдельный сквозной test-support прогон8 tests exit0. Code Simplicity Review с целевыми исправлениями — PASS. App build/strict signature exit0; test hook и старый model ABI1 отсутствуют во всех трёх Mach-O images,11 v2 exports присутствуют. Checkpoints63/63 побайтово сохранены, семь подписей действительны. Новый checkpoint не создавался. Полные06/08, live/UI и Windows этой локальной приёмкой не закрыты.


## Local-source ABI1 / 11A

[ambient_source.h](include/ambient_source.h) документирует новый отдельный типизированный ABI1; memory3/auth1 и текущий model3 сохранены. Он использует тот же memory handle/Store. Settings get/at/save/delete принимают actual root и bounded prefixes; begin выдаёт process-local operation ID для явного task/root выбора после Core High/session/report/pause проверки. Permit проверяет закрытый relative allowlist и исключения перед каждой native I/O порцией. В Rust нет filesystem adapter или JSON input.

Native удерживает busy до фактического возврата I/O и закрытия operation descriptors. Cancel закрывает допуск/публикацию, не завершает I/O. Только после cleanup вызывается finish (типизированные spans/байты/счётчики/время/reasons) или abort; release до этого возвращает busy. Один Core observation выдаёт bounded branch records и exact text preview, bind принимает только его индекс. Пределы: config64KiB,HEAD/loose4096,packed512KiB; всего1MiB/256files/256dirs/4096shared entries/256branches, depth16/relative path2048. Output settings16spans/16KiB, observation256records/1MiB, preview16KiB; capacities проверяются до side effects. Ошибки не раскрывают raw Git bytes.

Настройки получают постоянную общую возрастающую ревизию: delete/recreate не оживляет старый grant/snapshot/receipt. SourceKey отделён от разрешения; terminal deleted task/key нельзя связать повторно. Source citation использует tag5 в текущем model ABI3 record. Core остаётся владельцем context/receipt/copy; native выполняет только прежнее явное копирование. Неподдерживаемые Git формы не расширяют чтение. Swift test callback существует только под AMBIENT_MODEL_TEST_SUPPORT; обычная app его не компилирует.

## Model ABI3 / 08A

Текущий `ambient_model.h` заменяет modelABI2 целиком: все14 публичных операций имеют префикс `ambient_model_v3_`, старых v2 exports нет. Memory3/auth1/local-source1 сохраняются; текущая schema7 описана выше. Existing fixed layouts не меняются, кроме Citation:40bytes/alignment8, добавлен optional model_question span. Для Reply kind6 text содержит только user reply, model_question — отдельную цитату модели, item_id — parent request ID, а не EvidenceId; обычные citations имеют нулевой model_question span.

Новые `prepare_reply`, `clear_reply`, `suppress` используют прежний memory handle. Prepare принимает receipt и1..16384 точных UTF8bytes, возвращает прежний32byte Preview и context<=256KiB; полный body<=320KiB проверяется до подтверждения pending. Ошибка body освобождает только pending и сохраняет parent. `begin(request)` одноразово потребляет актуальный pending через прежние допуск/transport/ledger. Output capacities проверяются до замены pending; ошибки не меняют outputs. Suppress проверяет полный receipt, затем меняет только initiative_suppressed точного TaskVersion. Подготовка и разговор не записываются в memory; показ текста/copy всегда требуют действующих исходных fences.

## ABI интеграций v1 (23A)

`ambient_integration.h` заменяет `ambient_jira.h` (14 производственных экспортов + test-only dispatch под `AMBIENT_MODEL_TEST_SUPPORT`). Виды фиксированы в заголовке (local-projects1, codex2, github3, jira4); экспорты по виду принимают в 23A только jira4, с 23B — также github3. По виду: profiles (конверт `kind/instance/profiles/exclusions` ≤1MiB), scope_excluded, saved_metadata (страница по делу и виду). Типизированное сохранение: `jira_profile_save` (имя, Cloud ID). По ID операции: dispatch с двумя `AmbientText` секрета (второй может быть `{NULL,0}`), cancel/abort/release, window, preview, bind. Цикл dispatch не содержит своей константы шагов и заканчивается, когда Core отказывает (в том числе после `max_requests`); неверная форма секрета даёт INVALID_ARGUMENT до сети и прерывает неиспользованную операцию. ## Jira ABI1 /12A (историческое, заменено 23A)

`ambient_jira.h` добавляет14 операций на прежнем memory3 handle: profiles/profile save, Core-first credential begin, confirmed profile delete finish, independent site exclusion, begin/dispatch/cancel/abort/release/window/preview/bind/saved metadata. Текущая schema10 заменяет9; memory3/auth1/model4/local-source1/Codex1/GitHub1 сохраняются. Layouts: ProfileRef24, Read64, Batch280bytes.
