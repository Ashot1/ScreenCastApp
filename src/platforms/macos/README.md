# macOS / Swift

## macOS 26 и слой оформления (25A / ADR-023)

Приложение и голосовой помощник требуют macOS 26 (D72): `.macOS(.v26)` (PackageDescription 6.2), `MACOSX_DEPLOYMENT_TARGET = 26.0` в Xcode и `scripts/macos.sh`, CI на `macos-26`. `Design/Theme.swift` — помощник `Color(light:dark:)` на `NSColor(name:dynamicProvider:)`, четыре смысловые пары (готово, устарело, ошибка, уточнение; в тёмной теме — системные цвета) и оттенок `Theme.ink`. `Design/Styles.swift` — `AmbientInsetGroupBoxStyle`, `View.ambientTheme()` (без общего оттенка с 26B) и `View.ambientPrimary()` (главная кнопка — чёрная капсула со своим `.tint(Theme.ink)`); `ambientTheme()` стоит на трёх корнях со своей средой: окно `memory`, `Settings` и `NSHostingView` ленты у края. Новый отдельный корень (`NSHostingView`, другая сцена) получает `.ambientTheme()` сам. Роли шрифтов, радиусы и компоненты появляются в задачах их первых потребителей. `LocalizationTests` сверяет наборы ключей EN и RU. Пробы R1–R4 и снимки: `target/verification/25a/`.

## Сборка «Ambient Visual» для сверки с макетом (26A / ADR-024)

Отдельная сборка для снимков на тестовых данных; ежедневная `yarn build:macos` и Release тестового кода не содержат. Подмена `PRODUCT_NAME`/`PRODUCT_BUNDLE_IDENTIFIER` из командной строки ломает ресурсные пакеты SwiftPM (все цели получают одно имя), поэтому в проекте есть конфигурация «Debug Visual»: только у цели приложения имя «Ambient Visual», идентификатор `dev.ambient.foundation.visual` и `AMBIENT_VISUAL_FIXTURE`; пакеты собираются как Debug (имя содержит «Debug»). Отдельный идентификатор отделяет `UserDefaults` (папку моделей голоса), TCC, пункт входа и одобрение снимков. `AmbientAppDelegate.init` под флагом берёт папку из `AMBIENT_VISUAL_ROOT`: только абсолютный путь внутри `target/verification/`, иначе сообщение в stderr и выход с кодом 1, без отката на настоящие данные. В папке лежат `memory.sqlite3` и домашняя папка поиска плагинов Codex (`.codex/plugins/cache`); служба ChatGPT в связке ключей — `dev.ambient.foundation.visual.chatgpt` (`ChatGPTModel.init(session:chatGPTKeychainService:codexHome:)`). Записи интеграций и плагинов привязаны к экземпляру памяти, у тестовой памяти он свой; секреты не заводятся. Общая временная папка голоса (`$TMPDIR/dev.ambient.voice`) не разделяется.

Команды (`scripts/macos.sh visual …`):
- `build` — сборка в `target/verification/design/build`;
- `seed` — тест `seedVisualFixtureTemplates` (включается только `AMBIENT_VISUAL_SEED_DIR`) пишет шаблоны в `target/verification/design/templates`: `empty` (первый запуск), `corrupt` (испорченная память), `cases` (дела по макету: план, шаги, проверки, зависимость, заметки, связи, сведения источников под своим пространством `visual-fixture` — пространства интеграций ядро резервирует за ними, — завершённое дело; с 26D — отклонённая связь, журнал переноса, заметка локального проекта и сохранённые настройки тестовой папки и файла Codex из `target/verification/26d/fixtures/`, если они есть). Без model-test-support — только методы `MemorySession`; наполнение ленты описано в 26E ниже;
- `open <шаблон> <сессия>` — свежая копия шаблона в `target/verification/design/sessions/<сессия>` и запуск `open -n … --env AMBIENT_VISUAL_ROOT=…`;
- `fingerprint <метка>` — отпечатки данных пользователя (только чтение).

Порядок сессии сверки:
1. Настоящий Ambient закрыт. Отпечатки данных пользователя до сессии: `scripts/macos.sh visual fingerprint <метка>` (sha256 и время изменения `memory.sqlite3` и `-wal`, хэш `defaults export dev.ambient.foundation`, хэш атрибутов записи `dev.ambient.foundation.chatgpt` без секрета).
2. Пользователь одобряет computer-use для «Ambient Visual»; снимки только `app_screenshot`/`app_list_windows` по его окнам. Фон стекла — обои пользователя, оттенок сравнивается приблизительно; `cacheDisplay` стекло не передаёт.
3. Снимки рядом со страницами PDF в `target/verification/26x/compare/`; «Ambient Visual» закрывается.
4. Отпечатки после сессии совпадают с отпечатками до.

Не нажимать: вход в ChatGPT и Google, подключение сервисов, запуск плагинов, «Включить» запуск при входе — это сеть или системные изменения. Состояния со входом, расход, ключи, «Требует одобрения» у запуска при входе, запись голоса и загрузка памяти проверяет только пользователь.

## Окно, боковая панель и строка меню (26B / ADR-024)

Окно `memory` — `NavigationSplitView(columnVisibility: .constant(.all))`: боковую панель нельзя скрыть ни кнопкой, ни меню, ни перетаскиванием. Фон окна — системный материал `containerBackground(.ultraThinMaterial, for: .window)` (стеклянного `ShapeStyle` в SDK нет, своё стекло запрещено D72); содержимое — белый лист `textBackgroundColor`, радиус 20, отступы 8 сверху, справа и снизу, поверх области заголовка (`.ignoresSafeArea(edges: .top)`). `.toolbar(removing: .title)` на корне и `.toolbar(removing: .sidebarToggle)` на `List` убирают панель инструментов; значок настроек — часть боковой панели (`overlay` по размеру кнопки на ряду кнопок окна: `safeAreaBar(edge: .top)` встаёт ниже заголовка). Внизу листа дела — подпись `memory.help` с замком. Проба: `target/verification/26b/probes/`.

Боковая панель (F10): «Предложения N», строка «Дела» (заголовок для доступности) с круглым стеклянным «+» (прежнее действие и охрана «Новой задачи»; обычная строка, а не заголовок секции: заголовок секции боковой панели сворачивается и прячет кнопку от доступности), строки дел, раскрывающийся `DisclosureGroup` «Завершённые N» (раскрыт сам, пока показано его дело), листание, капсула статуса. Строки дел — кнопки `.plain`, а не выбор `List`: при фокусе списка система закрашивает выбор цветом акцента, и ни `.tint`, ни `.focusable(false)` этого не меняют (сверка 26B). Показанное дело — белая скруглённая подложка `listRowBackground`, признак `.isSelected` и полный текст в `accessibilityLabel`. Нажатие идёт прежним путём: то же дело без нового дела — только раздел дела, иначе `requestSelection(.task(id))`, поэтому окно несохранённого и «Отмена» прежние. Белая подложка выводится из состояния модели, поэтому после «Отмена» строка не расходится с моделью. Перехода между делами стрелками нет (Tab и VoiceOver доходят до строк). У списка нет своего оттенка: единственный местный оттенок в окне — у главной кнопки. Пустая память (F18) — `ContentUnavailableView` в `overlay` списка: «Дел пока нет», пояснение, «Новое дело»; на листе — редактор нового дела, который модель открывает сама. Ошибка открытия памяти — прежний `Callout` вверху листа.

`SidebarStatus` — компактная капсула (`glassEffect`): кольцо, короткий статус («Помощь по делу» в обычном состоянии, иначе `statusKey`), подпись «Наблюдение и голос недоступны» (полный `status.cloudUnavailable` — в подсказке и в «Основном») и одна круглая стеклянная кнопка: пауза (`AssistantPauseButton`, `canToggleManualPause`) или «Прочитать сохранённую паузу», пока пауза неизвестна. Текст кнопок — в `accessibilityLabel` и `.help`. `pause.help` виден в «Основном».

Строка меню (стр. 14): статус, при выходе — отдельная неактивная строка пояснения (у пунктов меню нет системного подзаголовка), пауза, «Прочитать сохранённую паузу» только при неизвестной паузе (как в капсуле; охрана `busy || closing`), ошибка, «Открыть память дел», «Настройки», «Выйти из Ambient» без значка. Окно смены дела — тексты стр. 20, кнопки и роли прежние.

## Дело, план, шаг и завершение (26C / ADR-024)

Шапка дела (`CaseHeader`): точка и «Открыто» или серая метка «Завершено», «напоминания отключены» при `initiativeSuppressed`, крупный заголовок целиком (переносится и выделяется; отдельного повтора текста нет), у завершённого дела — кнопка «Открыть снова», меню «⋯» (изменить, завершить, напоминания с подсказкой `lifecycle.suppressionHelp`, удалить) с прежними охранами. Блок «Следующий шаг» (`NextStepBlock`) с 26E виден над вкладками только при показанном «Плане»; вкладки — системный сегментный `Picker` по размеру содержимого, «Заметки N» и «Связи N» только для целиком загруженного списка (`MemoryPage.wholeCount`).

Номера шагов — позиции в плане (решение оркестратора по 26C вместо ID из 25C): `MemorySnapshot.stepPositions(fromStart:)` / `AssistantModel.stepPositions` известны, только когда весь план загружен с первой страницы; иначе номер не показывается. Страница шага держит весь план: `selectPlan` грузит шаги с первой страницы, выбранный шаг за её пределами `MemorySession.load` догружает отдельно. Отсюда «N из M», «Шаг N из M», «После шага N», «Шаг N ждёт этот шаг» (`waitingDependents`), «Изменение шага N», выбор шага «Шаг N · текст» в «Новой зависимости» и строки «Шаг 2 → Шаг 3». «ID шага» в интерфейсе нет. Принятый предел: страница шагов — 50, а ядро допускает до 64 шагов; в плане из 51–64 шагов номера не показываются, а выбор шага в «Новой зависимости» видит только первые 50.

План: значок статуса и текст (статус — в значении доступности), «После шага N», «+ Новый шаг», «План может быть неполным. Подтвердить план» (кнопка скрыта в подтверждённом плане; подсказка — следующий шаг только в подтверждённом плане), тихий список зависимостей. Капсула ссылки показывает саму ссылку и копирует её. Страница шага: назад, «План · дело», «Шаг N из M», «⋯», статус, заголовок, действия, «Промпт», «Проверки · N из M» (пройдено из всех; проверки шага грузятся целиком) с результатом в системном `Menu` в виде капсулы тона. Правка шага заменяет содержимое страницы: «Текст шага», переключатели перед подписью, «● Не сохранено».

Завершение: «Дело · название», «Завершение дела», «Итог», «Сохранить связи», «Полезные ссылки N из 32», видимая строка о том, что удалится (`lifecycle.cleanup`), «Подтвердить завершение». Строки ссылок читают черновик через безопасную по индексу привязку: отмена очищает массив раньше, чем строки обновятся (сбой сверки 26C). Завершённое дело: заголовок — итог, «Полезные ссылки» с «Копировать», вкладки «План / Заметки / Связи». Диалоги удаления дела и повторного открытия — системные с текстами стр. 20 и `dialogIcon`; удаление заметки — тексты стр. 20 (26D, ниже). Сверка: `target/verification/26c/compare/`.

## Заметки, связи, источники и помощь (26D / ADR-024)

Заметки (стр. 5): строка метаданных «вид · полнота · время · происхождение». Происхождение — «от вас», «из источника» или «из истории Git/Codex/GitHub/Jira/Todoist»: кнопка-ссылка раскрывает под строкой сохранённые сведения источника (адреса у заметки нет). Встроенный источник заметки — `MemoryEvidence.source` по пространству привязки; тот же набор решает, выбирается ли заметка в «Помощи». «+» новой заметки стоит рядом с вкладками (прежняя охрана). «⋯» видна на каждой строке. Следующие страницы и журнал переноса — под «Ещё заметки и журнал переноса», без числа: ядро даёт только курсор. Диалог удаления цитирует начало заметки.

Связи (стр. 6): вставной список; строка открывает дело, «⋯» — «Открыть дело / Убрать», у отклонённой связи — метка «Отклонено» и статус дела без даты (время отказа — не дата связи). Статусы — `case.open/completed`, как в шапке. Ниже — выбор открытого дела и «Добавить связь».

Источники: вторая строка — системный `Picker(.palette)`, только названия (D73). Локальный проект и Codex — строка пути (путь через «~», полный — в подсказке): до сохранения области кнопка «Сохранить область», затем «Сканировать / Сканировать снова» или «Прочитать / Обновить» (прежние охраны); «⋯» — выбор папки/файла и сохранённые настройки со значком удаления; исключения — раскрывающийся блок. Ветки и события — `Picker(.radioGroup)`: выбор показывает модель (`selectedIndex`), нажатие просит у модели предпросмотр. «Привязать ветку/событие» видна всегда и недоступна без предпросмотра; «Предпросмотр» показывает его текст. Сноски — видимая строка о том, что читается и что сохраняется, и `DetailsFootnote` «Подробнее» с прежними пределами. Диалоги удаления настроек папки и файла — тексты стр. 20, «Отмена» и значок. GitHub, Jira, Todoist — одна колонка: «Профиль» (меню), поле ссылки, одна кнопка чтения («Обновить» после первого чтения), покрытие, объекты с флажками «Выбрано N из 32», предпросмотр, JSON, «Сохранить», сохранённые метаданные. Ключи с переменной частью собираются сложением строк: литерал `LocalizedStringKey("a.\(b)")` становится ключом-форматом «a.%@» и показывал сырые ключи.

Помощь (стр. 9): «Выбрано сведений: N из 32», видимая строка о составе отправки (текст дела, план и выбранные сведения) и «Подробнее»; переключатели слева, метка «история интеграции»; «Начать заново и показать предложения» и «Сбросить предпросмотр и выбор»; карточка предпросмотра с «Точным контекстом для отправки» и чёрной капсулой отправки; `WorkRow` («Отменяю…» при отмене); блок ошибки без «Повторить» (такого действия нет).

Чтение источников и предпросмотр помощи допускаются только с сессией ChatGPT, поэтому в «Ambient Visual» эти состояния не видны (сверены по коду, проверяет пользователь). Тестовые папка и файл: `target/verification/26d/fixtures/`, их сохранённые настройки пишет сеялка. Сверка: `target/verification/26d/compare/`.

## Лента по макету и тестовое наполнение (26E / ADR-024)

`AssistanceCardView` сохраняет общие карточки окна и края, одну прокрутку и прежний выбор развёрнутой карточки. Вид: строка «вид · название дела», номер в подсказке, короткая кнопка у свёрнутой строки, «Закрыто», меню «⋯» и «У края / Показать у края». Главная кнопка уточнения — ответ; его прежнее копирование остаётся в меню. Главные действия используют чёрную `ambientPrimary()` без общего оттенка. После D107 `EdgeCardController` сохраняет ширину 420 точек (или существующую ширину), а высоту подгоняет под содержимое до 600 точек и доступного экрана. Стекло и условия показа прежние. Без текущего подключения карточки окна читаются, действия и строки краевой ленты остаются за прежним допуском. Само стеклянное окно может показывать уведомление; оно не объявляет сохранённую ленту пустой, если карточки скрыты допуском или закрыты.

Размер сообщает `onScrollGeometryChange` у той же прокрутки: полная высота содержимого плюс системные отступы, без смещения прокрутки. Контроллер хранит только последнее измерение геометрии для повторного ограничения при смене экрана; сохраняет верхний край и горизонтальное положение, затем ограничивает рамку `visibleFrame`. `NSHostingView` и дерево редактора не заменяются, второго наблюдателя за моделью или таймера нет. Короткое уведомление уменьшает панель; длинное содержимое остаётся в одной ограниченной прокрутке. Три проверки геометрии и native host тест проверяют рост, уменьшение после длинной ленты, оформление окна, прокрутку и сохранение редактора/фокуса при ограничении экрана.

Общий черновик показывается внутри его развёрнутой карточки; если её нет среди показанных, редактор остаётся отдельно. Короткая видимая строка говорит, что ответ сохраняется с авторством пользователя и не становится фактом дела; «Подробнее» хранит прежнее полное пояснение, включая неподтверждённую предпосылку вопроса. Точный состав отправки, сброс черновика и локальность диктовки остаются рядом с управлением. Папка моделей — компактная строка со своей кнопкой выбора. «Следующий шаг» есть только на «Плане»; проверки готовности и первой страницы прежние.

`VisualFeedFixtureTests.swift` дополняет `cases` только при `AMBIENT_MODEL_TEST_SUPPORT`: настоящий Swift → C → Rust прогон с `AssistanceHTTPServer`, `AssistanceTestStore`, `LocalAssistanceBridge` сохраняет три карточки. Уточнение относится к первому делу; закрытое предложение — к ревью (план в этом feature-шаблоне подтверждается, иначе Core справедливо запрещает предложение); устаревшее — к делу о пределах после правки его текста. Закрытие идёт через `setProposalVisibility(false)`. Перезапуск проверяет все состояния и четыре локальные попытки (проверка + три запроса). Сервер и тестовые credentials в приложение не входят. Обычный `visual seed` создаёт прежние шаблоны без карточек.

После сборки моста с `--features model-test-support` в отдельном каталоге наполнение выполняется так (из корня; скрипты проверки 26E задают путь моста и Swift-флаг):

```sh
bash target/verification/26e/feature-bridge.sh
AMBIENT_VISUAL_SEED_DIR="$PWD/target/verification/design/templates" \
  bash target/verification/26e/swift-feature.sh --filter seedVisualFixtureTemplates
bash scripts/macos.sh visual open cases 26e-review
```

Сверка и её ограничения: `target/verification/26e/compare/comparison.md`. Состояния со входом и запись голоса проверяет пользователь; приложение не получает обход допуска ради снимков.

## Подсветка места на экране (27F / ADR-025)

Принят локальный `@MainActor HighlightOverlay`: `public init()`, `show(normalizedRect:displayKey:)`, `hide()`. UUID дисплея определяется из `NSScreenNumber` через ColorSync; нормализованный прямоугольник Vision с началом снизу слева переводится в points `NSScreen.frame`, включая Retina. Один повторно используемый прозрачный пассивный `NSPanel` скрывается при неизвестном дисплее. Подключение к приложению добавлено в 27E ниже; сама рамка не следит за экраном. Четыре детерминированных Swift-теста проверяют координаты, UUID/неизвестный дисплей и пассивные свойства окна. Настоящие focus, Spaces, fullscreen и несколько физических дисплеев проверяются в 27H; 27F не подтверждает захват, TCC или модельные вызовы.

## Управление фоновым наблюдением (27G / ADR-025)

Девятый раздел настроек использует тот же нативный `Form.grouped` на белом листе, что и26F. AppDelegate хранит единственный `ObservationSession`; настройки и меню читают его внутреннюю `@MainActor @Observable` проекцию состояния, ошибки и снимка журнала Core. Закрытие, ручная пауза и неизвестная пауза имеют прежний приоритет в меню. Подготовка, отсутствие разрешения, ожидание сессии и ошибка не называются наблюдением. Полный reload дел/ленты остаётся только в прежнем callback результата, не на каждом кадре.

Явный Start сохраняет started/credit и выбранный предел, затем просит Screen Recording через `FrameSource` на MainActor. Отказ оставляет намерение включённым; повторный явный запрос не сбрасывает предел. Обычный запуск читает сохранённую политику и восстанавливает прежний цикл без запроса разрешений, перезаписи предела или ручной проверки подключения. Обычный Ambient Visual всегда запускает только очистку журнала, даже если тестовая политика включена. Разрешение, действующая сессия и ручная пауза по-прежнему ограничивают фактическую работу.

Предел1–60 меняет только perHourLimit без остановки захвата. Команды сериализуют полное чтение/запись политики, поэтому смена предела не возвращает включённое намерение после Stop. Удаление журнала сначала отменяет допуск Core, затем ждёт фактического завершения захвата/отправки и возобновляет прежний режим; это не Stop/Start. Политика, попытки и неизвестный расход сохраняются. Журнал показывает настоящие исходы и выданный tier; `other` остаётся неизвестным уровнем, не заменяется Fast. Неверные числовые outcome/tier отвергаются при декодировании существующего JSON FFI.

Всегда видимое предупреждение описывает весь выбранный дисплей и возможную передачу видимого содержимого через ChatGPT. Текст журнала хранится до суток; снимки — только в памяти до отправки, паузы или остановки. Сведения, уже добавленные в дела, сохраняются отдельно до удаления. Журнал не открывает снимки. Локальные проверки используют только тестовые SQLite и localhost HTTP; настоящие экран, TCC, подписка и модель остаются для27H.

## Локальный путь наблюдения (27E / ADR-025, D106)

`ObservationSession` владеет одним циклом журнала/наблюдения; решения о сроке следующего кадра, допуске отправки и рамке принимает Rust. `FrameSource` использует ScreenCaptureKit, исключает окна Ambient и выбирает дисплей по переднему подходящему окну активного приложения. Vision распознаёт русский и английский текст; ограниченный JPEG остаётся в памяти. Отправка имеет отдельную задачу и не ждёт завершения локальной обработки. Остановка сначала отзывает допуск ядра, затем ждёт фактического завершения захвата/отправки; выход завершает наблюдение перед закрытием авторизации и памяти.

AppDelegate владеет сессией и рамкой. После локальных изменений, способных убрать рамку, `MemorySession` прямо ожидает уведомление единственного слабого подписчика, завершив синхронную работу FFI и заимствование буферов. Ошибка чтения результата после уже выполненной записи не теряет уведомление. Ревизии сессии и показа не позволяют позднему ответу вернуть рамку после выхода или отмены; простые несвязанные изменения памяти не отбрасывают свежий кадр.

При приёмке27E обычный запуск временно выполнял только очистку журнала. В27G это заменено восстановлением сохранённого намерения, описанным выше; обычный Ambient Visual остаётся journal-only. Явный отладочный флаг был проверен сборкой, но такая сборка не запускалась. Живые экран, TCC и модель —27H. Локальная приёмка 27E: `target/verification/27e/handoff.txt` и `target/verification/orchestration/27e-parent-inspection.md`; последующие общие проверки с D107: 8 tooling / 394 Rust / 125 Swift и расширенные 181 Swift, сборки/подписи/аудит PASS.

## Каркас главного окна (25B / ADR-023)

`AssistantView` — корень окна `memory`: `NavigationSplitView` с боковой панелью `CaseSidebar` (244) и белым листом содержимого (компоновка 26B — выше). На корне остаются блокировка `.disabled(model.busy || model.closing)` (покрывает и боковую панель), окно несохранённого на `pendingSelection`, подтверждение удаления и оба прежних `.onChange`. Раздел содержимого (`MainSection`: «Предложения» или дело) — `@State` корня; он переключается на дело по `.onChange` выбранного дела и `isCreatingTask`, поэтому следует за любым путём выбора, а «Отмена» в окне несохранённого оставляет пользователя на месте. Группа «Завершённые» раскрывается сама, пока выбрано её дело. Состав боковой панели и капсулы с 26B — в разделе выше. Компоненты `Design/`: `Callout` (блок ошибки), `StatusRing` (три состояния сохранённой паузы и завершение, всегда рядом с текстом), `PageControls` (кнопка «В начало» только не на первой странице, ряд скрыт, если листать некуда). Пустые состояния — `ContentUnavailableView`.

## Вкладки дела и отмена чтений (25C / ADR-023)

`CaseDetailView`: шапка дела `CaseHeader` (точка и статус, усечённый текст дела 26 pt, полный выделяемый текст ниже, меню «⋯» из прежних действий с прежними охранами: изменить текст — режим правки (25D), завершить или открыть снова с подтверждением, напоминания, удалить) и системный сегментный `Picker` `CaseTab`. Вкладка — `@State` корня окна; строится только показанная. У завершённого дела вкладок «Источники» и «Помощь» нет, скрытая вкладка показывает план. Доступность помощи (`reloadAssistanceAvailability`) обновляется по открытому делу на любой вкладке, как раньше при показе дела.

Отмена чтений источников (D76) живёт в модели: `didSet` у `snapshot` (смена ID или ревизии выбранного дела, в том числе после собственной привязки источника) и у `manualPause` вызывает `cancelSourceViews()` для всех пяти источников. Корень окна добавляет `assistanceReady == false` и `.onDisappear` (закрытие окна, проба R3). Экраны источников своих обработчиков отмены не имеют, кроме `.onChange(of: source.target)`. Переход между вкладками, разделом «Предложения», открытие шага или редактора чтение не отменяют. Тест `CasePlanTests` смотрит счётчик поколения (`generation`, только чтение снаружи) каждого источника.

Вкладка плана: блок «Следующий шаг» (`MemorySnapshot.nextStep` — первый готовый по Core и не выполненный шаг загруженной страницы, иначе скрыт; с 25D только на первой странице шагов), шаги со значком статуса (с 26C без метки `Pill`), подпись «После шага N» (с 26C по позициям, см. 26C; `waitingSteps`: невыполненные предшественники, только когда загружены все зависимости с первой страницы и сами предшественники), новый шаг, полнота плана, зависимости под списком, `PageControls` для шагов, зависимостей и ссылок.

## Страница шага и страницы редакторов (25D / ADR-023)

Страницу дела выбирает `AssistantModel.casePage` по приоритету: редактор (`editorKind` — проекция закрытого `Editor` без данных; кроме правки дела и шага), затем выбранный шаг (`snapshot.selectedStep`), затем вкладки. Проверка и новая проверка загружаются с шагом, поэтому их редактор важнее страницы шага, а отмена возвращает на страницу шага. Редакторы — одна страница за раз (`DraftEditor`): новое дело, заметка, новый шаг, новая проверка, проверка, зависимость, завершение; «Отменить изменения» на них доступна всегда — это и путь назад.

Строка шага в плане открывает страницу шага (`requestSelection(.step)`): навигация «Назад к плану» (`requestSelection(.task)`), меню «⋯» (изменить, удалить), статус, текст, «Ждёт шаг N», копирование промпта и ссылки, выполнение, точный промпт и ссылка, проверки (`StepChecks`: результат — системное меню из трёх прежних значений, дата `confirmedAtUTC`, если есть; описание открывает редактор проверки). У завершённого дела план очищен ядром, страница шага недостижима.

Режимы правки текста дела и шага — `editingTask`/`editingStep` в `@State` корня `AssistantView`, поэтому переход в «Предложения» их не теряет. Модель уже в правке (`editor == .task`/`.step`), признак только показывает поля; несохранённый черновик виден всегда. Признаки сбрасываются при сохранении, отмене, кнопках «Сохранить»/«Не сохранять» окна несохранённого, смене дела и смене шага (`.onChange` корня). После действия плана на странице шага (выполнение, результат проверки) модель возвращается в правку дела, поэтому «Изменить шаг» сначала снова открывает шаг.

«Следующий шаг» (D81) — `AssistantModel.nextStep`: только при `stepsAfter == 0`. `PlanDraftFields` листает связи завершения через `PageControls`.

## Заметки, связи, источники и помощь (25F / ADR-023)

Вкладки дела — отдельные файлы: `NotesTab`, `LinksTab`, `SourcesTab`; «Помощь» — прежний `SelectedAssistanceView` (защита предпросмотра 08B по `taskID`/`revision` не менялась).
- **Заметки:** строка заметки — текст, строка метаданных (вид · полнота · время · «Пользователь»; столбцом, если не помещается через `ViewThatFits`), происхождение интеграции и раскрытие внешнего источника. Системное меню «⋯»: «Изменить» (без охраны, как раньше), «Переместить в задачу» (раскрывает в строке прежний выбор задачи и «Подтвердить перемещение» с прежней охраной, #17), «Удалить». Охрана — `hasUnsavedChanges`.
- **Связи:** строка открывает целевое дело; под текстом статус цели (`otherTask.lifecycle`) и для связанных «связь с <дата>» (`MemoryLink.actionAtUTC` — время решения пользователя о связи, день и месяц). Отклонённая связь — нейтральная метка `Pill` с прежним текстом; «Не связаны» — отдельная кнопка рядом со строкой.
- **Источники:** второй сегментный `Picker` по `BuiltInIntegration.allCases`, только имена (#4, #5); выбор — `@State` корня окна рядом с вкладкой дела. Строится только показанный источник; переключение источников чтение не отменяет: обработчиков отмены в экранах нет, а `loadProfiles`/`loadMetadata` при повторном показе не трогают цель и поколение (D76). Ошибки источников и помощи — `Callout`; листание сохранённых метаданных GitHub/Jira/Todoist — `PageControls`.

## Google Диск и Документы (24B / ADR-022, D71)

«Добавить Google» берёт байты встроенного пакета из моста (`ManagedServers.builtin`) и ведёт обычным путём просмотра и установки. `PluginServerKind.managed(id:)`; `startsProcess` (локальный или управляемый) запрещает автоматическое обнаружение при установке и раскрытии настроек. Просмотр и настройки показывают тексты ADR-022 для Google (скачивание, защита и её предел, сеть, права, данные, prompt injection, тестовый режим, обновление с выпуском) и утверждённые тексты локальных программ. `ManagedServers` (своя очередь) вызывает статус, установку на `PluginOperation` с «Отменить», вход и отзыв; «устанавливается» — состояние интерфейса. Нет `uv` — показывается официальная команда установки (Ambient её не выполняет). «Удалить сервер» и удаление плагина Google удаляют `<plugins>/google-workspace-mcp`, только пока не идут установка, обнаружение, проверка или помощь. Вход: `ChatGPTLoopback(path: "/")` на 127.0.0.1, браузер, Rust проверяет `state` и `iss` и меняет код; токены — `PluginSecret.oauth(access, refresh, expires_at, refresh_issued_at)` в `PluginSecretOwner` (Core первым); verifier и `state` живут только в памяти одного входа. Перед помощью и обнаружением токен, истекающий раньше чем через 300 s, обновляется под `mutating` без смены поколения; `invalid_grant` — отзыв ключа в Core, удаление из Связки ключей и «Войдите снова». Выход и удаление сначала отзывают грант у Google (без повтора), затем всегда отзывают ключ в Core и удаляют его из Связки ключей; неудачный отзыв у Google показывается строкой `plugins.google.revokeFailed`. Тесты: `GooglePluginTests.swift` (конверт `oauth`, «Добавить Google» без запуска, обновление токена без смены поколения и `invalid_grant`, отзыв при выходе и удалении с успехом и отказом, удаление папки сервера, test-support: ответ Google с чужим `state` отвергнут без сети и Связки ключей).

## Локальные серверы плагинов (24C / ADR-022)

`AmbientProcess.launch()` — первая строка `AmbientAppDelegate.init`: игнорирует SIGPIPE, чтобы запись в stdin уже вышедшего локального сервера давала `EPIPE` → «недоступен», а не завершала приложение (тест вызывает именно эту функцию и проверяет, что без неё процесс тестов убит сигналом 13). Корень частных папок локальных серверов — `dev.ambient.foundation/plugins` рядом с базой (`MemorySession.pluginServersRoot()`), передаётся в `ambient_model_v6_dispatch` и `ambient_plugin_v2_discover`; папка `<root>/<plugin id>` удаляется после удаления плагина в Core. Подписи доступности SwiftUI до кнопки строки меню не доходят (проба H1, `target/verification/25h/probes/`), поэтому VoiceOver читает «Ambient», а статус — в меню. Вход ChatGPT и предоставленные права не включают анализ. Меню открывает существующее окно `memory` и Settings. Quit сначала вызывает `AssistantModel.beginClosing()` (`closing = true`: модель больше не принимает ввод, пока закрывается вход), затем прежний delegate shutdown, ожидающий auth и память; если память не закрылась, `close()` сбрасывает `closing`. Пока идёт выход, открытое окно памяти показывает полосу хода «Завершение…» над листом без затемнения; своего окна у выхода нет.

Пауза читается и записывается через прежний MemorySession/ABI3 без загрузки содержания дел. Одна UI-проекция `manualPause: Bool?` независима от `MemorySnapshot`: nil означает неизвестное значение. Ошибки сохраняют неизвестное или последнее подтверждённое значение и черновик. Меню, окно и Settings используют одну команду, выключенную при unknown/busy/closing. Начальное чтение запускается в `applicationDidFinishLaunching`; одновременно открытое окно присоединяется к нему и затем загружает страницы. Параметры reload вычисляются после ожидания. Общая отслеживаемая операция включает применение результата и освобождение busy; закрытие ждёт её и запрещает позднюю публикацию.

Кнопка Settings проверяет только права текущего процесса через `CGPreflightScreenCaptureAccess()` и `AXIsProcessTrustedWithOptions` с явным prompt=false. До нажатия оба результата неизвестны; повторное нажатие заменяет только локальные результаты. Нет запросов прав, чтения контента, polling, сохранения результата или дополнительного чтения Keychain. Не предоставленный доступ не объясняется выдуманной причиной.

`CLocalPermissions` содержит только static-inline accessor системного ключа Accessibility. SDK объявляет ключ изменяемой C-глобальной переменной, недоступной из strict Swift 6; accessor возвращает заимствованный CFString с явной ownership-аннотацией. Словарь с false и сама проверка остаются в Swift. Новый экспортируемый C-символ или версия memory/auth ABI не вводятся; Core и bridge не меняются. `nil` options не используются: документация Apple не обещает эквивалентность явному false.

Тесты паузы работают с реальной временной SQLite; тестовый gate удерживает actor, чтобы проверить совместный старт и ожидание принятой операции при закрытии. Проверки permission UI используют тестовые значения и не фиксируют текущее TCC-состояние машины. Приложение для визуального прогона не запускалось; menu/focus/Spaces, macOS14 hardware и Windows остаются непроверенными.

Все36 файлов checkpoints побайтово сохранены. Xcode сообщил системные предупреждения CoreDevice/CoreSimulator, не блокирующие macOS build. Code Simplicity Review — без замечаний.

## Собственный вход ChatGPT (06B)

Настройки предлагают Continue with ChatGPT, явные refresh/cancel и локальный выход по [ADR-006](../../../docs/decisions/0006-native-chatgpt-session.md). `ChatGPTBridge` выполняет синхронные auth ABI1 вызовы на собственной `DispatchSerialQueue`; память и UI не ждут эту очередь. `ChatGPTCoordinator` на отдельном serial executor владеет записью и поколением попытки. Startup/показ настроек читает только свой локальный вход, без сети и автоматического браузера.

`ChatGPTKeychain` использует один generic-password envelope: service `dev.ambient.foundation.chatgpt`, account `installation`, без синхронизации. Для текущей ad hoc подписи SecItem использует file-based Keychain: добавление в default keychain, точный запрос service/account по системному search list. Ни default, ни список приложение не меняет; это не обещание конкретного login keychain. Data Protection selector/access groups не используются: они требуют разрешённых provisioning profile entitlements, которых у development target нет. Система создаёт обычный ACL; приложение его не ослабляет. Гарантия `WhenUnlockedThisDeviceOnly` этому режиму не приписывается. UUID host хранится внутри той же записи и создаётся только при явном первом входе после `notFound`. Ошибка/повреждение не создаёт новую регистрацию. Выданный client ID сохраняется до exchange; неизвестный исход динамической регистрации требует явного подтверждения восстановления. Local sign-out убирает credentials/hint/nonce, сохраняя host и issued binding, и не отзывает серверное подключение. После пересборки ad hoc designated requirement меняется и система может снова запросить доступ; это отдельно от перезапуска той же сборки.

`ChatGPTLoopback` использует IPv4 `127.0.0.1`, случайный порт и `/auth/callback`; `NWListener` принимает максимум 8 соединений за попытку, обрабатывает максимум 2 одновременно. На соединение — 5s и 8 KiB до системного CFHTTPMessage parser. Срок попытки — 5 минут. Статический ответ браузеру имеет `no-store`; query не отражается. Остановка ждёт terminal состояния listener и всех принятых connections. При завершении приложения app delegate ждёт как память, так и настоящий auth shutdown; поздний результат после cancel/logout/TTL не сохраняется.

Refresh сначала проверяет публичную metadata/JWKS, затем атомарно удаляет прежние access/refresh из envelope до единственного POST. Ошибка подготовки/удаления запрещает POST. Потеря ответа, отмена или ошибка проверки/сохранения не восстанавливают старый rotating token. Новая сессия сохраняется целиком до отображения «Вход сохранён».

Native integration tests создают отдельный временный Keychain через test-only C helper и адресуют его явно, не меняя default/search list/ACL и не читая пользовательские записи. C helper сохраняет видимыми предупреждения SDK о deprecated `SecKeychainCreate/Delete`; production использует SecItem APIs. В файловой песочнице системная служба может возвращать `-25294`; такой тест требует разрешённого запуска вне песочницы. Это отличается от проверки пользовательского Keychain ACL.

Настоящие native consent/аккаунт/refresh, пользовательский ACL, визуальный UI, macOS14 hardware и Windows здесь не подтверждены. Автоматический анализ и подтверждённый доступ Fast отсутствуют; синтетическая явная проверка06D описана ниже. Изолированный IdP не считается реальным входом пользователя.

Модельная интерпретация, автоматические связи и инициативные предложения остаются открытыми критериями 07. Пользовательская БД не использовалась для разработки/проверок; тесты выбирают временные пути.

`ManualPlanView` показывает вычисленные Core доступные шаги, проверки и направленные зависимости одного дела; никакого waves engine или scheduler нет. Формы шага/проверки/зависимости/итога используют тот же независимый черновик AssistantModel с исходными ID/ревизией. Переключение предлагает save/discard/cancel, ошибка и смена страницы не приклеивают черновик к другому ID. MemorySession проверяет, что отдельные страницы относятся к одной ревизии; он не пересчитывает готовность и не хранит вторую память.

Завершение явно предупреждает об очистке подробностей и принимает итог, выбранные полезные связи и точные ссылки. Completed показывает итог/связи/ссылки; reopen предупреждает, что старые сведения и план не вернутся. «Не актуально» отдельно сохраняет preference для будущих напоминаний, не запускает таймер. Копирование известного текста — кнопка `NSPasteboard.clearContents`/`setString`; false показывается как ошибка. Ссылка не открывает внешний URL или приложение.

Для native clipboard integration test используется отдельный именованный pasteboard, а не пользовательский. Ограниченная файловая песочница может блокировать службу pasteboard даже с `--disable-sandbox` SwiftPM; прямой пробник подтверждает false внутри/true вне. В таком окружении полный native test требует разрешённого запуска вне файловой песочницы. Это не визуальная проверка UI. Пользовательская БД не читается; checkpoints 06 и 07A не изменяются.


## Явная проверка Luna Low Fast (06D)

Settings использует существующие ChatGPTModel/ChatGPTCoordinator и тот же MemorySession, что окно/меню памяти. Только coordinator хранит once-per-process user_reported сообщение о проверенном запрете дополнительных списаний: это не прочитанная API настройка. UI показывает read-only проекцию, решения допуска принимает coordinator/Core. Новый вход, sign-out и shutdown сбрасывают сообщение; refresh сохраняет его только при той же проверенной host/client/issuer/subject привязке. В envelope/Keychain и SQLite это сообщение не добавлено.

Явная кнопка отправляет одну фиксированную синтетическую проверку через model ABI3/Rust/HTTP/тот же SQLite Store. Нет запросов при старте/Settings/reload/снятии паузы; нет рабочих данных, чтения дел для проверки, capture/голоса/файлов, automatic refresh/retry/fallback. Кнопка ведёт к официальному ChatGPT UI для управления использованием без обещания точного deep link. Нужны saved неистёкшая сессия, сообщение пользователя, снятая пауза и доступный журнал. Проверка не включает анализ.

ModelCheckBridge выполняет синхронный Rust request на отдельной serial queue. Единственный coordinator сериализует auth/model операции; token попадает только в принятую операцию. Cancel, sign-out и shutdown инвалидируют generation, сохраняют busy до actual return/close и запрещают позднюю публикацию. Пауза отменяет через Core/тот же флаг. App shutdown сначала ждёт coordinator/auth/model cleanup, затем закрывает память. Никакой registry lock не удерживается в сети; model lease сохраняет Store для accounting после memory close.

EN/RU показывают отдельный функциональный исход, requested/actual конфигурацию, последний outcome и известный/неизвестный расход native журнала. Это не остаток подписки или общий расход аккаунта. Known usage не теряется при mismatch/cancel; старые unknown не исчезают после новой успешной проверки. Локальные temporary SQLite/HTTP и изолированные native test seams не подтверждают собственный native consent, пользовательский ACL, реальный refresh/модельный POST/Fast. UI, macOS14 hardware и Windows остаются непроверенными. Стенд01 и пять checkpoints не изменялись.


Code Simplicity Review06D: модельный HTTP срок принадлежит только Rust transport; native проверяет поколение/закрытие после actual cleanup и не подменяет timeout своим auth-expiration. Чтение журнала хранится как отдельный Result: успешное перечитывание убирает прежний read error, но ошибка записи выполненной проверки остаётся отдельной диагностикой. Регрессионный native test действительно удерживает test seam61s и проверяет сохранение timeout после этой очистки.


## Запуск при входе в macOS (06E)

Settings содержит отдельный `LoginItemView` с небольшим `@MainActor LoginItemModel`. Постоянным значением владеет `SMAppService.mainApp`: UI хранит только снимок native `Status` и локализованную ошибку, без UserDefaults, Core-флага, helper или LaunchAgent plist. Статус перечитывается при появлении блока, возвращении scene в active и после явного register/unregister; polling и автоматических повторов нет.

Для notRegistered доступно включение, для enabled — выключение. RequiresApproval означает необходимость разрешения в macOS: доступны системная страница Login Items и удаление регистрации. NotFound и будущий неизвестный статус показывают недоступность с возможностью перечитать. Успех или ошибка API не подменяют системный статус; raw NSError/пути не выводятся. Открытие System Settings само по себе ничего не регистрирует. Ошибка остаётся видимой при автоматическом перечитывании; следующее явное действие, включая кнопку обновления, снимает прежнюю ошибку.

Production closures вызывают настоящие ServiceManagement API. Восемь тестов с test-only closures проверяют отсутствие регистрации при создании/refresh, внешний отзыв, ровно выбранную операцию с последующим чтением, approval вместо ложного enabled, ошибки, явный повтор и разницу явного/автоматического обновления после ошибки, неизвестный статус, переход в системные настройки и сохранённую ручную паузу через временную SQLite. Новых contracts/ABI/packages нет.

Автозапуск не снимает ручную паузу и не включает анализ. При старте приложения и входе ChatGPT register не вызывается. Интеграция первого включения после полноценной настройки остаётся открытой; неиспользуемый hook не добавлен. Во время разработки приложение не запускалось, register/unregister/open System Settings на машине пользователя не выполнялись. Реальная регистрация с текущей ad-hoc подписью и следующий macOS login, native UI, macOS14 hardware и Windows не проверены. Подробности: [ADR-009](../../../docs/decisions/0009-login-item-settings.md).

## Помощь выбранному сохранённому делу (06F / ADR-010)

## Ручной обзор выбранных локальных веток (11A)

`LocalProjectsView/Model` добавляют выбор NSOpenPanel (только одна папка, resolvesAliases=false), показ фактического расположения и независимый черновик относительных исключений. Выбор/настройки не читают Git content; панель и metadata root запускаются только явным действием. Сохранённые настройки можно показать/удалить отдельно с предупреждением об исключениях и сохранении истории. Scan — отдельное явное действие для открытого дела; единственный ChatGPTCoordinator перечитывает текущую сессию/report перед begin и bind. Старый UI availability сам по себе не является допуском. Автоматических model calls и фонового чтения нет.

`LocalGitReader` владеет FD на отдельной serial queue. Root открывается покомпонентно с nofollow; actual path берётся strict UTF-8 F_GETPATH/MAXPATHLEN. Перед I/O и принятием результата проверяются F_GETPATH, повторное nofollow открытие исходного пути и dev/ino. Это обнаруживает удаление даже при stale F_GETPATH, rename и replacement, но не гарантирует атомарность/отсутствие move-out-and-back или последующих гонок. Успешный security scope сбалансирован; bookmarks/restore после restart отсутствуют.

Только direct .git directory и config/HEAD/packed-refs/refs/heads. File open использует O_RDONLY/O_NOFOLLOW/O_NONBLOCK/O_CLOEXEC; regular-file/nlink1 проверяются до первого read, dev/ino/size/nanosecond mtime/ctime/mode/nlink сравниваются после. Нет чтения рабочих материалов, index/objects/includes/commondir targets, Git CLI или записи. Исключения проверяются до дочернего open; любое исключённое refs/heads subtree пропускает весь packed-refs. HEAD исключённой ветки не публикует её имя как основание других веток. Все byte/count/depth/path limits применяются до следующего чтения/накопления, потери показаны явно.

Один reader и bounded observation. UI cancel/смена task/window close запрещают поздний импорт; source busy остаётся до фактического I/O/FD cleanup. O_NONBLOCK защищает от FIFO, не задаёт I/O deadline. Shutdown ждёт reader перед прежним MemorySession.close. Синхронного I/O на MainActor нет. EN/RU показывают полноту, причины, интервал, точные сведения выбранной ветки и отдельную кнопку сохранения; черновик основного редактора сохраняется. Импорт не запускает помощь автоматически. 06F показывает exact исторический source context, использует прежний transport/ledger и Core-validated copy; изменения source settings запрещают старые preview/result/copy без удаления истории.

Текущая Schema7 отвергает1–6; local-source ABI1 использует прежний memory3 handle, auth1 и model3 сохранены. Cancel использует тот же Core atomic через короткий bridge lock, не ждёт Store/SQLite на UI; release выполняется MemorySession actor. Настоящий High Fast остаётся production gate. ## Локальный голосовой ответ (10A / ADR-013)

`ChatGPTModel.voice` — один `VoiceReplyModel` для общей панели и карточки. Кнопка записи доступна только для текущего уточнения; непустой ответ заменяется отдельным явно подписанным действием. Старый текст сохраняется до успешного распознавания. Разрешение AVAudioApplication запрашивается только по этой кнопке. AVAudioRecorder пишет mono PCM16/16kHz до60s и2MiB; предел закрывает запись и ждёт галочки. Во время записи ASR отсутствует, редактор и Send этого ответа недоступны. Галочка закрывает WAV, распознавание заполняет прежний draft, а отправка остаётся единственным отдельным Send08A.

Допуск читается через прежний `currentResult(receipt)` → modelABI3 → Core getter, без copy/prepare/HTTP. Native требует clarification и прежнюю версию черновика после permission, перед записью/helper и перед применением. Пауза, отзыв допуска/основания и новый результат прекращают голос; поздние callbacks не меняют другой draft. Выбор дела в редакторе памяти сам по себе не меняет адресата. Отмена и shutdown не ждут permission callback без созданных ресурсов.

`AmbientVoiceHelper.app` вложен в Contents/Helpers; запускается его фиксированный native executable, без shell/credentials. Собственный SwiftPM package закрепляет неизменённый FluidAudio0.17.7 commit503b4bd1bbf7220882de39fe8ae6716aae4132da с traits[] и Swift>=6.2. Helper включает offlineMode, проверяет21 SHA256/483105645bytes inventory04, затем использует loadLocal/v3/int8 и nonstreaming ASRConfig. Каталог моделей выбирается явно; UserDefaults хранит только выбранный путь. Поиска cache, downloader или поставки весов нет. Проверка hashes не делает последующую CoreML загрузку атомарной относительно другого процесса.

Запрос stdin ограничен8KiB, закрытый result32KiB и текст16KiB UTF8. Ошибка, пустой результат и переполнение ничего не отправляют и не обрезаются. stdout/stderr направлены в /dev/null; FluidAudio logger настроен до создания runtime. Долгая подготовка моделей входит в общий300s deadline. C-граница владеет posix_spawn, одним waitid(WNOWAIT)/waitpid reaper и сигналами под общим mutex; SIGTERM →250ms → SIGKILL не освобождает работу до фактического выхода. Голос не занимает ChatGPTCoordinator, поэтому независимый HTTP может закончиться во время остановки child.

Каждая операция имеет private0700 каталог/0600 файлы и независимые parent/helper shared flock leases. После получения lock helper сверяет исходные пути, dev/inode/owner/type/nlink до открытия WAV. Отдельный EOF thread завершает весь helper при смерти родителя даже во время зависшего compute. При запуске приложения и перед новой записью проверяется только собственный временный root: общий предел64 каталогов, включая вложенные и место новой операции, и256MiB с резервом WAV/result. Неполный обход или занятый lease запрещает запись; cleaner держит exclusive lock до удаления. Ошибка cleanup возвращает текстовый ввод и блокирует запись до явного успешного повтора. После crash возможны остатки до cleanup; физическое стирание SSD/backup не обещается. Advisory locks не защищают от несотрудничающего процесса того же пользователя.

Сборка `yarn build:macos` сначала собирает/подписывает background helper, его resource bundles и notices, затем внешнее приложение. Audio Input entitlement есть только у основного app; оба конечных bundle подписываются с runtime. Штатный FluidAudio TTS dictionary bundle (~1MB) учитывается отдельно. SwiftPM может скачать неиспользуемый Nemo build artifact, но он не входит в app/link graph. FluidAudio Apache2 и fastcluster BSD notices включены; лицензия весов/конверсии CC BY4 не подменяется лицензией runtime. Подробности сборки: [VoiceHelper](VoiceHelper/README.md).

Проверки используют только test-owned процессы/SQLite/HTTP/Keychain, mock permission/microphone и закреплённые публичные WAV04. `VoiceTestChild` — отдельный test target, отсутствующий в app. Настоящий упакованный helper проверен на RU/EN коротком/длинном WAV, тишине, invalid input, отсутствии моделей и отмене под запретом сети; global raw derivatives не появились. Сквозной Store/C/Swift/localHTTP тест прошёл clarification → настоящий ASR → редактирование → exact preview → один Send без записи в task memory. Это не проверка нового микрофонного звука, TCC denial/device routes, UI/focus/Spaces, macOS14 hardware, Windows или live Fast. Текущие schema7/memory3/auth1/source1/model3 и прежняя модельная/бюджетная политика описаны выше.
