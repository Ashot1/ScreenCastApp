# Ограниченный клиент G2

Этот документ описывает переданную сборку **v1**. Новая независимая подготовка чтения/поиска находится в [content-probe/protocol.md](content-probe/protocol.md); у неё другой путь и bundle ID. Права v1 не переносятся на v2 автоматически.

Клиент не реализует Ambient. Он печатает три no-prompt статуса прав. Только явный `--window PID --expected-bundle-id ID` при доступном Accessibility вызывает один `AXUIElementGetAttributeValueCount(AXWindows)` для выбранного процесса. PID и bundle ID должны совпасть с работающим приложением. Текст, заголовки, URL, снимки и дочерние элементы не извлекаются; сеть, ввод и навигация отсутствуют.

## Сборка и запуск

Из `/Users/gojda/Projects/ScreenCastApp`:

```sh
bash tests/feasibility/03-native/test.sh
bash tests/feasibility/03-native/build.sh
```

Готовый bundle: `tests/feasibility/03-native/.build/NativeContentProbe.app`. Bundle ID: `dev.ambient.feasibility.native-content`. Сборка требует штатного macOS SDK и Swift 6; кэш компилятора находится только в собственной `.build`. Зависимости не загружаются.

Скрипт **не перезаписывает** готовый bundle (exit 73). Это одна замороженная ad-hoc сборка; её хеш и designated requirement записаны в [client-verification.txt](../../../docs/features/assistant-behavior/evidence/03-native/client-verification.txt). Пересборка/переподпись меняет идентичность для TCC; прежние права не обещаются.

Для запуска известного bundle через LaunchServices:

```sh
probe_root=/Users/gojda/Projects/ScreenCastApp/tests/feasibility/03-native
open -g -n -W "$probe_root/.build/NativeContentProbe.app" \
  --stdout "$probe_root/.build/preflight-stdout.txt" \
  --stderr "$probe_root/.build/preflight-stderr.txt" --args --preflight
```

В ограниченном exec эта команда первоначально завершилась `kLSNoExecutableErr (-10827)`. Позже управляющий разрешил один вызов через штатную автоматическую проверку `exec_command require_escalated`: тот же неизменённый bundle выполнил preflight и записал три `false`, `mode=preflight`, `exitCode=2`; stderr пуст. Хеш до/после совпал. [Результат LaunchServices](../../../docs/features/assistant-behavior/evidence/03-native/launchservices-preflight.txt). Системные права, TCC и конфигурация sandbox не менялись.

`open` вернул 0 с предупреждением `Unable to block on application`; нельзя считать это ожиданием завершения или exit-кодом клиента. Прямой запуск бинарника ниже также работает, но имеет другой контекст запуска и сохраняется как отдельная проба.

```sh
tests/feasibility/03-native/.build/NativeContentProbe.app/Contents/MacOS/NativeContentProbe --preflight
```

Прямой запуск сейчас возвращает три `false`, `mode=preflight`, `exitCode=2`. Ни успешное выполнение preflight через LaunchServices, ни прямой запуск не подтверждают выдачу разрешений или чтение окна. Никакие разрешения или TCC-настройки автоматически не меняются.

После отдельно подтверждённого доступа можно передать PID специально выбранного тестового приложения и его точный bundle ID. Например, **заменить `12345` реальным PID тестового TextEdit**, затем использовать тот же способ запуска и аргументы `--window 12345 --expected-bundle-id com.apple.TextEdit`. Без аргументов окно не читается. Нельзя подставлять первый случайный процесс или выдавать число окон за чтение документа.

Коды результата клиента: `0` — запрошенная ограниченная проба завершилась; `2` — нужное разрешение недоступно; `3` — цель отсутствует или её bundle ID не совпал; `4` — ошибка AX; `64` — неверные аргументы/упаковка. При запуске через `open` результат самого клиента нужно брать из `exitCode` в stdout: exit-код `open` не является exit-кодом клиента.

## Оставшаяся матрица

Полный перечень и ожидаемые результаты: [matrix.md](../../../docs/features/assistant-behavior/evidence/03-native/matrix.md). Все её случаи остаются BLOCKED. Текущий клиент предназначен только для подготовки идентичности/прав; для чтения текста, исключений и навигации понадобится отдельная разрешённая тестовая реализация.

1. В каждом выбранном браузере и native-приложении открыть только подготовленные безличные материалы: видимый маркер; другой маркер ниже экрана; виртуальные строки; закрытая область. Записать версию, права, метод и реально проверенную область.
2. Отдельно проверить исключённые приложение/сайт/папку, неизвестную область и смену вкладки/окна перед чтением и передачей. При неопределённом источнике чтение/передача запрещены.
3. По новому явному поиску проверить прокрутку и безопасное раскрытие. Между шагами — ввод человека и Stop. Следующий шаг запрещён; старый поиск автоматически не продолжается.
4. Проверить пассивное наблюдение без изменения фокуса/окна/данных, затем отзыв ранее выданного права в работающей операции. Это не доказано отсутствием права на старте.
5. Для каждого результата указать одно: найдено; нет в полностью проверенной ограниченной области; неполно; невозможно прочитать. Не делать вывод о полном документе по снимку.

## Будущий disposable Jira target

1. Использовать только заранее разрешённую тестовую Jira и отдельное тестовое окно/профиль. При отсутствии реального доступа — BLOCKED; REST не заменяет UI.
2. Открыть диалог создания **новой тестовой задачи**, не редактируя существующую. Вписать безличный маркер `AMBIENT-G2-DRAFT-20261018` в несохранённый редактор. Не нажимать Create/Save/Submit и не публиковать комментарий.
3. Будущий content-reader должен определить текущие приложение/окно/вкладку и разрешённый сайт до чтения; прочитать маркер из настоящего UI, привязать точный фрагмент к текущему редактору и зафиксировать ограниченный охват. Нынешний счётчик окон этого не делает.
4. Проверить переключение в исключённую вкладку и возврат: прежний контекст чтения не переносится. В сеть тестовый текст не отправлять; журналировать только результат и безличные метки.
5. Закрыть тестовый диалог штатной отменой без создания задачи. Если отмена требует отдельного решения или нельзя подтвердить отсутствие записи, остановиться и записать ограничение.
