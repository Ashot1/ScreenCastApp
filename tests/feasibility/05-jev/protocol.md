# Jev: протокол возобновления проверки

Подготовлено 2026-10-18. **Живые испытания BLOCKED.** Тестовый клиент готов к офлайн-проверке; сам этот документ запросы не запускает.
Результат: [отчёт](../../../docs/features/assistant-behavior/evidence/05-jev/report.md).

## Условия допуска

Пользователь разделил общий баланс **$5**: **$1 — предварительные проверки**, **$1.50 — проверки во время/после разработки реального приложения**, **$2.50 — личное использование после готовности**. Этот подготовительный клиент имеет один жёсткий совокупный предел **$1** на все свои задачи/волны/попытки/неурегулированные резервы. Остальные $4 ему недоступны: переключателя этапа или бюджета нет. Прежнее разрешение $2.50 для всех наших тестов уточнено этим разделением; $5 на тесты не одобрены. Это не новый доллар на каждый запуск и не месячный лимит будущего приложения.

До первого обращения нужны существующий Jev API key в разрешённом хранилище, сверенный общий остаток, подтверждённый верхний резерв одной попытки и применимые условия аккаунта. Предоставление ключа ещё не подтверждено; верхняя стоимость и условия остаются незакрытыми. Общий остаток нельзя вывести из нулевого числа запросов только задачи 05. Не искать чужие ключи, не считать кредиты или подписку лимитом Ambient. В этом обновлении реальные обращения запрещены.

На каждую попытку записать отдельный резерв; автоматические повторы и fallback запрещены. Все сохранённые расходы и неурегулированные резервы плюс новая подготовительная попытка должны помещаться в **$1**. После обрыва неизвестный расход остаётся зарезервированным. Новая задача или волна не обнуляет общий учёт; существующий журнал не заменяется. Если прежние обязательства уже превышают $1, следующий вызов блокируется. Ошибку нельзя считать бесплатной без подтверждения. Если верхний счёт не доказан или общий остаток не сверён, запрос не отправлять. Тарифная гипотеза в отчёте не является разрешением.

## Готовые материалы

`fixtures/manifest.json` содержит SHA-256, размеры, источник обрезки и эталонные границы. Шесть PNG созданы локально через Pillow 11.1.0, без снимков экрана и личных данных. Это тестовые входы и человеческая разметка, **не ответы Jev**. Границы задаются краями пикселей: `[left, top, right, bottom)`, начало сверху слева.

- `present.png`: 800×600, красный круг `[100,120,220,240)`, оранжевый круг, синий квадрат и зелёный треугольник.
- `absent.png`: та же сцена без красного круга; оранжевый круг остаётся похожей целью.
- `ambiguous.png`: два одинаковых красных круга, второй `[540,360,660,480)`.
- `present-half.png`: 400×300, уменьшенная вдвое исходная сцена.
- `present-crop.png`: 400×400, исходная область `[80,80,480,480)`.
- `exemplar.png`: 280×280, отдельный красный круг для поиска по образцу.

Не передавать manifest или ожидаемые координаты модели. Эталон сравнивается с ответом после запроса. Данные малы и искусственны: даже успех всей матрицы не докажет качество на настоящих интерфейсах.

## Каталог доступных случаев

Это офлайн-каталог, **не план платного полного прогона**. После закрытия ключа/upper bound/условий сначала нужен только **P-ru**: один запрос на разрешённой синтетической сцене проверяет реальный доступ, изображение, русский запрос, presence/count/Box и первый usage. После него остановиться, сохранить результат и сверить расходы/резерв. Каждый следующий платный запрос допустим только ради конкретного ещё не проверенного критерия G4 с явно записанным назначением: например, отсутствие цели, образец, неоднозначность или поведение на обрезке, если это действительно осталось неизвестным. Уже доказанный случай не повторять ради заполнения таблицы; техническая ошибка сама по себе не разрешает повтор. Выбор следующей необходимой пробы делается по сохранённому результату, без автоматической матрицы или fallback.

Для каждого из первых девяти случаев использовать один и тот же смысл запроса, включая проверку присутствия и количества:

| ID | Сцена | Режим | Эталон и допустимый результат |
| --- | --- | --- | --- |
| P-en | present | английский | Один красный круг, рамка вокруг него |
| P-ru | present | русский | То же; оранжевый круг не подходит |
| P-image | present + exemplar | образец | То же, совпадение формы и цвета |
| A-en | absent | английский | Цель отсутствует; рамка не предлагается |
| A-ru | absent | русский | То же; похожий оранжевый круг не подходит |
| A-image | absent + exemplar | образец | То же |
| M-en | ambiguous | английский | Несколько целей; одну произвольно не выбирать |
| M-ru | ambiguous | русский | То же |
| M-image | ambiguous + exemplar | образец | То же |
| R-en | present-half | английский | Одна цель; пересчёт обратно даёт исходную область |
| C-en | present-crop | английский | То же после добавления смещения обрезки |
| F-stale | результат P-en, затем смена снимка/цели | локальная проверка будущего адаптера | Старый результат не разрешает подсветку |

Для английского: `the red circle in scene`. Для русского: `Красный круг на изображении scene`. Для образца: `the object in scene matching reference`. Присутствие и количество должны относиться к той же цели, включая цвет и форму. Синтаксис ссылок на поля и картинки — по [Box](https://docs.typesafe.ai/primitives/box#writing-box-questions).

## Тестовый клиент и запуск без сети

Из корня репозитория, Node 22.23.1 и установленный Vitest 4.0.18:

```sh
yarn vitest run tests/feasibility/05-jev/probe.test.js tests/feasibility/05-jev/budget.test.js
node tests/feasibility/05-jev/probe.mjs plan
node tests/feasibility/05-jev/probe.mjs preflight P-ru 'G4: initial access, Russian localization and usage'
node tests/feasibility/05-jev/probe.mjs dry-run P-image 'G4: check exemplar matching only if still unverified'
```

`plan` перечисляет 11 доступных заготовок без отправки/сохранения картинок и не назначает платный прогон всех случаев. `preflight`/`dry-run` тоже не отправляют запросы; код выхода 2 означает закрытый допуск, а не неудачу офлайн-подготовки. F-stale проверяется локально в тестах, отдельного inference-запроса для него нет. Тесты используют временные базы и HTTP-сервер только на `127.0.0.1`, с явно фиктивным ключом `test-only-key`. Эти ответы заданы тестами и проверяют клиент, а не Jev. Перенаправления запрещены, автоматических повторов/fallback нет, ответ ограничен 64 KiB, таймаут — максимум 90 s. Multipart действительно передаётся локальному HTTP-серверу, без обращения к поставщику.

Ключ будущей пробы: только переменная окружения **`TYPESAFE_API_KEY`**, заданная оператором из разрешённого хранилища; клиент не читает `.env`, другие профили или Keychain и не выводит ключ. Настройки без секретов: **`tests/feasibility/05-jev/live-settings.json`**, образец — [live-settings.example.json](live-settings.example.json). Реального файла настроек сейчас нет. `live_enabled` остаётся false; верхняя стоимость и её свидетельство, условия аккаунта и начальная общая экспозиция не заполнены, вместо них сохранены null. Непустая ссылка в настройках обозначает подтверждение оператором; программа не может сама доказать договор или тариф.

Общий журнал всех наших тестов Jev — **`docs/features/assistant-behavior/evidence/05-jev/jev-tests.sqlite3`**. Рабочий CLI не имеет опции сменить журнал, создать новую волну или обнулить расходы. Его ещё не создавали: нельзя принять нулевую общую экспозицию на основании отсутствия вызовов только в задаче 05. Перед однократным `init-ledger` нужны `opening_exposure_usd` и `opening_exposure_evidence`: сверенные общие уже потраченные суммы плюс все прежние неурегулированные резервы. Отсутствующий или повреждённый журнал блокирует отправку, повторная инициализация существующего запрещена. Начальная экспозиция не уменьшается автоматически.

`budget` показывает общий остаток и ID попыток. Перед каждой отправкой SQLite атомарно проверяет потолок **$1** и записывает case ID, обязательное назначение, модель/фактический endpoint, верхний резерв и свидетельство его оценки. В журнал не попадают ключ, тела запросов, снимки или сырые ответы. `charged=NULL` означает неизвестный расход до и после любого HTTP-исхода, поэтому весь резерв сохраняется после закрытия/повторного открытия базы. Суммы — точные целые nanoUSD, без округления и неявного нуля. Даже успешный response с usage не освобождает резерв: `reconcile ATTEMPT_ID USD RECEIPT_REFERENCE` требует явно сверенный счёт и свидетельство. Перезапись расхода запрещена; счёт выше резерва сохраняется и блокирует последующие попытки.

При открытии старого журнала его потолок $2.50 только понижается до $1 под SQLite-транзакцией; opening exposure и все старые charged/NULL-резервы остаются. Недостающие исторические purpose/model/endpoint остаются NULL: их нельзя придумать задним числом. Отрицательный остаток показывается и блокирует новый резерв. Это изменение существующего журнала, а не создание нового бюджета. Удалять или заменять журнал нельзя; подготовительные задачи используют этот единственный файл. Позднейшие $1.50 разработки и $2.50 личного использования этим клиентом не расходуются.

При достижении **$0.80 (80% подготовительного предела)** расходами плюс неурегулированными резервами, включая новую попытку, preflight возвращает `warning`. Он не печатает отдельное уведомление. После успешного атомарного резервирования запуск выдаёт ровно одно событие `budget_warning_80_percent` в stderr **до fetch**. Поле `committed_with_reservations_nanousd` и `basis` обозначают расходы вместе с резервами, а не фактическое списание. Если верхняя стоимость или общий расход неизвестны, preflight не придумывает число предупреждения и оставляет warning null. Нового механизма уведомлений или повторного сообщения от внутреннего preflight нет.

`run CASE_ID 'REASON'` предназначен только для будущей разрешённой пробы после закрытия условий допуска. Причина обязательна на каждую попытку: краткое название ещё неизвестного критерия без личного контекста/секретов, до 1000 UTF-8 байт, без перевода строки. Без неё preflight/run блокируются; автоматической причины по умолчанию нет. Сейчас реальный запуск заблокирован остальными условиями. Модульная подмена пути журнала разрешена лишь вместе с loopback-адресом и фиктивным ключом; рабочий URL Jev с другим журналом отклоняется. SQLite — встроенный `node:sqlite`, экспериментальный API в данном Node; предупреждение не скрывается. Новых пакетов, production-хранилища и второго runtime приложения нет.

Пороги presence/unique намеренно null, пока нет калибровки. Сбор разрешённых тестовых ответов возможен без придуманных порогов: классификация останется `unverified`, сохранит проверенные числовые свидетельства и **никогда** не разрешит подсветку. Только для модульных тестов используются явно синтетические пороги. Даже `candidate` означает кандидата, а не разрешённое действие. CLI выдаёт очищенную сводку в stdout; при настоящей пробе её нужно сохранять с ID попытки, не полные тела с изображениями.

## Форма запроса

Кандидат: прямой HTTP `POST https://api.typesafe.ai/v1/systemone`, Bearer key, модель `jev-1.14.0`, заголовок `TypeSafe-Danger-Zone-Images: true`; long-context header не задавать. Не устанавливать SDK ради этого протокола; не включать debug-логирование тел. Доступ аккаунта к этой версии пока не проверен. [API](https://docs.typesafe.ai/api)

В `state` поместить `scene` и при необходимости `reference`, через `assets` с уникальными ссылками и multipart PNG. В `questions` — отдельные Noul о присутствии, Choice с `none/one/several/uncertain` и Box о месте **той же** цели. Это подготовленная форма эксперимента, не проверенный запрос и не независимое статистическое доказательство: все три ответа даёт одна модель.

Размеченная сцена является отдельным основанием для оценки присутствия в эксперименте. В продукте его надёжность и связь с текущим контекстом ещё нужно подтвердить. Противоречие, `none`, `several`, `uncertain`, неверный тип/диапазон/порядок координат или неизвестная цель запрещают предложение рамки. Числовые пороги присутствия/уверенности не подобраны; не переносить пример порога из документации в продукт.

Каждую попытку сохранять отдельной строкой будущего журнала: ID случая/попытки, hash изображения, версия модели из ответа, монотонная длительность, HTTP status, проверенные ответы/ошибки, presence/ambiguity verdict, `usage.input_tokens`, `usage.output_tokens`, резерв, подтверждённый расход и сверка с биллингом. Отсутствующие значения оставлять неизвестными, не нулями. Не сохранять ключи, тела с base64 или личные изображения.

## Геометрия

Вывод из контракта Box, а не измерение Jev: для исходной обрезки `(ox, oy, cw, ch)` и нормализованного края `(u,v)` без padding/rotation: `x = ox + u*cw`, `y = oy + v*ch`. Размер отправленной копии используется для промежуточных пикселей; нельзя умножать нормализованный край на размер другого снимка.

Контрольная арифметика по разметке: P-en `(left=.125, top=.2, right=.275, bottom=.4)` соответствует `[100,120,220,240)`. На половинной копии — `[50,60,110,120)`, после обратного масштаба — исходная область. Для crop `(left=.05, top=.1, right=.35, bottom=.4)` локально `[20,40,140,160)`, после смещения `(80,80)` — исходная область. Это вычисленные эталоны, не полученные ответы.

Padding, поворот, Retina, координаты окна/экрана и несколько дисплеев требуют отдельных преобразований в 20. Привязать результат к hash/идентичности снимка, времени, окну, геометрии и версии намерения; изменения инвалидируют старый результат. Эту привязку протокол не реализует.

## Ошибки и очистка

Негативные случаи проверять локально в границе клиента и loopback, без обязательного платного прогона неверного ключа, Images header, размеров, asset, 429/529 или обрыва. Уже доказанное локально повторно не оплачивать ради матрицы. Дополнительный реальный ошибочный запрос допустим лишь когда конкретный незакрытый критерий требует именно поведения поставщика: сначала зафиксировать, почему локальной проверки недостаточно и какое свидетельство нужен получить, затем отдельный верхний резерв и допуск. Не создавать нагрузку ради 429 и не инициировать обрыв без такой необходимости. Если требуемое состояние не проверено, сохранить BLOCKED; loopback не доказывает поведение поставщика. Каждый необходимый ручной повтор — отдельная попытка, неизвестный расход не освобождать; автоматических повторов и fallback нет.

Рабочие копии картинок/ответов держать во временной папке конкретного прогона. После результата, ошибки или отмены проверить удаление всех временных копий, включая обрезки и base64; эталонные синтетические fixtures остаются тестовыми материалами. Удаление локального файла не удаляет уже переданную поставщику копию. Реальная очистка после inference пока не проверена.

Тестовый клиент и локальный допуск реализованы в `probe.mjs`/`budget.mjs`; логики нативной подсветки здесь нет. До закрытия живых условий задача 20 не получает подтверждённую рабочую интеграцию.
