# ADR-024: проход «точно по макету» для интерфейса macOS

Статус: **принят 22 октября 2026** после двух обзоров:
- **Plan Simplicity Reviewer:** PASS с исправлениями B1–B3, F1–F8, S1–S4; все внесены. Повторная проверка исправленных частей — PASS с одной поправкой о публичном инициализаторе; внесена.
- **Evidence Auditor:** пять неточностей исправлены.

Уточняет [ADR-023](0023-ui-redesign-liquid-glass.md) по решениям пользователя D83–D85.

Основание:
- [D83–D86](../features/assistant-behavior/decisions.md);
- макет — PDF `target/verification/design/ambient-design.pdf` (копия canvas «Ambient · финал», 22 страницы), опись [25-ui-design-inventory](../features/assistant-behavior/evidence/25-ui-design-inventory.md);
- снимки пользователя от 22 октября: главное окно с пустой памятью и настройки «Основное»;
- отчёты Codebase Scout (оболочка окна, данные и ключи), Pattern Librarian (пробы SDK: `/private/tmp/…/scratchpad/probe/`) и независимый план Plan Simplicity Reviewer для снимков.

## Problem Statement

25A–25H переложили экраны на системные элементы, но результат не похож на макет:
- окно — стандартная разбивка с белой областью до края и системной кнопкой сворачивания панели, а не стеклянное окно с белым листом-карточкой;
- боковая панель — чёрная кнопка «Настройки», огромный блок статуса из абзацев и чёрная «Включить ручную паузу» вместо компактной капсулы;
- тексты остались прежними и длинными («задачи», абзацы пояснений);
- настройки — прежние блоки с длинными текстами, заголовок окна и кнопка сворачивания.

Причины:
1. Правило ADR-023 «существующие тексты важнее, тексты дизайна — только для новых поверхностей» оставило почти весь старый текст.
2. ADR-023 описал окно как стандартную разбивку и не задал главное в дизайне — белый лист-карточку на стекле.
3. По D77 никто, включая оркестратора, не сравнил собранное окно с макетом. Исполнители работали по тексту плана, а не по картинкам.
4. Две прямые ошибки:
   - `.toolbar(removing: .sidebarToggle)` стоит на корне `NavigationSplitView` (`AssistantSettingsView.swift:58`) и не действует; в главном окне его нет совсем. Проба Pattern Librarian: работает только на столбце боковой панели;
   - общий оттенок `.tint(Theme.ink)` из `ambientTheme()` (`Design/Styles.swift:20`) делает стеклянные кнопки чёрными.

## Solution

Отдельный проход по экранам: каждый экран собирается, снимается на тестовых данных и сравнивается со страницей PDF, пока не совпадёт.
- Логика, модельные охраны, перечень проверок ADR-023 и тесты поведения не меняются.
- Меняются компоновка окна, вид элементов и тексты (D83).
- Сверку делают исполнители на тестовых данных (D84), пользователь смотрит итог сам.

## Implementation Decisions

### Сборка для сверки (26A)

**Отдельная сборка «Ambient Visual».** Новая подкоманда `scripts/macos.sh visual`, чтобы каждый исполнитель не набирал аргументы заново:
- `xcodebuild` с `SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) AMBIENT_VISUAL_FIXTURE'` — без `$(inherited)` пропадает `DEBUG`;
- `PRODUCT_BUNDLE_IDENTIFIER=dev.ambient.foundation.visual`, `PRODUCT_NAME="Ambient Visual"`;
- своя папка сборки `target/verification/design/build`;
- запуск `open -n … --env AMBIENT_VISUAL_ROOT=<папка>`.

Свойства этой сборки:
- **Тестовый код только здесь.** Ежедневная `yarn build:macos` и Release его не получают. `#if DEBUG` для защиты не годится: пользователь работает с Debug-сборкой.
- **Отдельный идентификатор** отделяет `UserDefaults` (в том числе папку моделей голоса), разрешения TCC, пункт входа (`SMAppService.mainApp`) и одобрение снимков. `open` при этом не активирует настоящий Ambient.
- **Отдельное имя** не путается с настоящим Ambient в доступе computer-use и в строке меню.
- **Первый шаг 26A — пробная сборка и запуск.** Нужно проверить, что подмена идентификатора из командной строки не ломает ресурсные пакеты SwiftPM, а флаг доходит до цели приложения. Если ломает — третья конфигурация проекта только для цели приложения; при сомнении — QUESTION.

**Выбор данных — только в делегате.** `AmbientAppDelegate.init` (цель приложения) под `#if AMBIENT_VISUAL_FIXTURE` строит сессию и модели. Через представления ничего не передаётся.
- Делегат видит только публичный API библиотеки. Поэтому `ChatGPTModel` получает публичный инициализатор `init(session:chatGPTKeychainService:codexHome:)` со значениями по умолчанию, равными нынешним.
- Внутри значения доходят до хранилища координатора (`ChatGPTKeychain(service:)`) и до `PluginsModel.codexFolders` → `PluginPackageReader.codexPlugins(home:)`.
- Ежедневная сборка вызывает тот же инициализатор со значениями по умолчанию; новый код в ней — только эти параметры.
- **Папка.** `AMBIENT_VISUAL_ROOT` обязана лежать в `target/verification/`. Если переменная не задана или неверна, приложение останавливается. Откат на настоящие данные невозможен.
- **Память:** `MemorySession(databaseURL: <папка>/memory.sqlite3)`; плагины и кэши `uv` следуют за папкой памяти сами.
- **Связка ключей:** переименовывается только служба ChatGPT (`dev.ambient.foundation.visual.chatgpt`): её запись не привязана к экземпляру памяти. Ключи интеграций и плагинов сохраняют имена служб и не используются: их записи привязаны к экземпляру памяти, у тестовой памяти он другой, а вход запрещён. Секреты не заводятся. Файловая связка ключей не нужна — её создание есть только в тестах.
- **Домашняя папка для поиска плагинов Codex** указывает внутрь папки сверки (параметр `codexHome` выше).

**Наполнение по потребителю** (S1):
- **26A** — небольшой тест Swift Testing через `@testable import AmbientMacOS`. Он включается только переменной `AMBIENT_VISUAL_SEED_DIR` и пишет шаблонные папки:
  - пустую (первый запуск);
  - с испорченным `memory.sqlite3` (ошибка открытия по F18);
  - с делами по макету: план, шаги, проверки, зависимости, заметки, связи, сведения источников, завершённое дело.

  Только методы `MemorySession`.
- **26E** — карточки ленты, их единственный потребитель:
  - настоящий прогон помощи через локальную заглушку модели внутри теста (`AssistanceHTTPServer`, `AssistanceTestStore`, `LocalAssistanceBridge` — в том же тестовом модуле);
  - запускается с `-Xswiftc -DAMBIENT_MODEL_TEST_SUPPORT` и мостом с признаком `model-test-support`;
  - устаревшая карточка — правкой дела после прогона; закрытая — внутренним `setProposalVisibility(false)`.

  Заглушка в приложение не попадает.
- Каждая сессия снимков копирует шаблон в свежую папку.

**Снимки:**
- Делаются через computer-use приложения Claude: `app_screenshot` и `app_list_windows` только по окнам «Ambient Visual», чтобы не снимать чужие окна.
- Доступ к «Ambient Visual» одобряет пользователь за компьютером, в начале сессии. Если у сессии исполнителя нет инструментов computer-use — BLOCKED.
- Фон стекла — обои пользователя, поэтому оттенок стекла сравнивается приблизительно; отчёт это оговаривает.
- Снимки самим приложением (`cacheDisplay`) стекло не передают и годятся только для раскладки.
- В 26A — пробный снимок нынешнего интерфейса, чтобы доказать, что стекло видно на снимке.

**Неприкосновенность данных пользователя.** До и после каждой сессии снимаются отпечатки:
- sha256 и время изменения настоящей `memory.sqlite3` и `-wal`;
- хэш `defaults export dev.ambient.foundation`;
- атрибуты записи `dev.ambient.foundation.chatgpt` без секрета.

Настоящий Ambient на время сессии закрыт. Общая временная папка голоса отпечатками не покрыта; отчёт это оговаривает.

**Правила для исполнителя.** Не нажимать:
- вход в ChatGPT и Google;
- подключение сервисов и запуск плагинов;
- «Включить» запуск при входе.

Это сеть или системные изменения.

**Только для пользователя** (не проверено агентами):
- все состояния со входом: ChatGPT, расход, GitHub, Jira, Todoist с ключом, ключи плагинов;
- запуск при входе «Требует одобрения»;
- запись голоса, отправка в процессе, загрузка памяти.

### Окно, боковая панель и строка меню (26B, D85)

- **Шаг 1 — проба по F10** до правки Ambient. Нужно проверить, что `NavigationSplitView` с фоном окна `containerBackground(_:for: .window)` и белым листом-карточкой даёт вид макета, в том числе в сцене `Settings`. Если нет — QUESTION с наблюдением; своё ручное стекло не вводится (D72).
- **Окно.** `NavigationSplitView(columnVisibility: .constant(.all))` — боковую панель нельзя скрыть ни кнопкой, ни меню, ни перетаскиванием.
  - Фон окна — стекло или материал.
  - Содержимое — белый лист: радиус 20, отступ 8 сверху, справа и снизу.
  - `.toolbar(removing: .title)`; `.toolbar(removing: .sidebarToggle)` — на `List` боковой панели. Это убирает всю панель инструментов окна, поэтому значок настроек — часть самой боковой панели, а не элемент панели инструментов.
- **Боковая панель по F10:**
  - вверху справа от кнопок окна — значок настроек;
  - «Предложения N»;
  - крупный заголовок «Дела» с круглым «+»;
  - строки дел, выбранная — белая капсула;
  - раскрывающийся «Завершённые N»;
  - внизу компактная капсула: кольцо, «Помощь по делу», короткая подпись, круглая кнопка паузы.
- **Пустая память по F18:** в панели «Дел пока нет», пояснение и «Новое дело»; на листе — редактор «Новое дело». Ошибка открытия памяти — красный блок по F18.
- **Значковые кнопки** («+», пауза, «⋯», настройки): прежний текст остаётся в `accessibilityLabel` и `.help`, прежние охраны (`canToggleManualPause`) не меняются.
- **Оттенок.** `.tint(Theme.ink)` уходит из `ambientTheme()`, то есть и с ленты у края.
  - Главная кнопка — чёрная капсула со своим `.tint`; это единственный местный оттенок.
  - Круглые значковые кнопки — стекло без оттенка, `.buttonBorderShape(.circle)`.
  - Главные кнопки ленты у края проверяются в 26E.
- **Строка меню по странице 14** (четыре состояния): меню разделяет `statusKind` с капсулой.
- **Диалоги своих экранов** — тексты макета страницы 20: смена дела при несохранённом.

### Тексты (D83)

- **Короткие тексты макета на экранах.** По-русски «дело» вместо «задача» во всём интерфейсе. По-английски остаётся «task»: один термин везде, решение Localization Mechanic.
- **Где живёт смысл.**
  - Чувствительный смысл (что хранится, что отправляется, что необратимо) остаётся видимым: коротким текстом рядом или в системном `DisclosureGroup` «Подробнее» без состояния модели. Его изменения утверждает оркестратор.
  - Подсказка `.help` — только для нечувствительных дополнений.
- **Языки.** Каждая правка — во всех языках, через Localization Mechanic.
- **Документы.** Если раскрытие сведений о данных и хранении переезжает, `docs/product.md` и `docs/privacy.md` обновляются в той же задаче.

### Что остаётся системным (D75)

- меню, диалоги, кнопки окна;
- шрифты SF Pro и SF Mono вместо Onest и JetBrains Mono;
- значки SF Symbols вместо собственных.

Это допустимые отличия от макета, остальные расхождения объясняются в отчёте.

### Порядок и владение (D86)

- **Порядок.** Задачи идут последовательно: 26A → 26B → 26C → 26D → 26E → 26F. Точки просмотра пользователя — после 26B, 26E и 26F.
- **Пути.** Каждая задача 26 перечисляет свои пути: `Sources/AmbientMacOS/*View.swift` и экраны, `Design/`, `AssistantMenu.swift`, `EdgeCardController.swift`, `CaseSidebar.swift`, ключи строк, которые правит.
- **Параллельно с 26** могут идти задачи фонового режима (ADR-025) в Rust, мосте и `MemorySession`: 26 их не трогает.
- **После 26.** Swift-задачи фонового режима, которые трогают перечисленные пути или общие модели (`AssistantModel`, `ChatGPTModel`, `statusKind`/`statusKey`), ждут приёмки нужной задачи 26.
- **Общие файлы.** Каталоги строк и документы правит только задача, которая идёт сейчас. Если понадобится настоящая параллельность в одних файлах — отдельные worktree, слияние делает оркестратор.

## Testing Decisions

- **В каждой задаче:**
  - `yarn verify`, `yarn lint:swift`, `yarn build:macos`, подписи, контрольные сборки по базе оркестратора;
  - перечень проверок ADR-023 до и после.
- **Сверка с макетом:**
  - снимки нужных состояний на тестовых данных рядом со страницами PDF (`target/verification/26x/compare/`);
  - список совпадений и объяснённых отличий;
  - отпечатки данных пользователя до и после.
- **Проверки тестового режима при приёмке 26A** (вместо тестов, которые нельзя написать):
  - в ежедневных Debug и Release нет строки `AMBIENT_VISUAL_ROOT`;
  - «Ambient Visual» без переменной и с неверной папкой завершается с ошибкой.
- **Тест равенства языков остаётся.** Новых тестов поведения нет: логика не меняется.

## Уточнения реализации 26A

Принято оркестратором 22 октября 2026 ([приёмка](../../target/verification/orchestration/26a-27a-parent-inspection.md)).

- **Сборка «Ambient Visual».** Подмена параметров из командной строки ломает ресурсные пакеты SwiftPM (проба 26A). Поэтому сборка идёт отдельной конфигурацией проекта «Debug Visual» (`scripts/macos.sh visual build`).
  - Конфигурация задаёт только для цели приложения: имя, идентификатор, отображаемое имя и `AMBIENT_VISUAL_FIXTURE`.
  - В имени есть «Debug», поэтому пакеты сохраняют `DEBUG`.
- **Команды:** `scripts/macos.sh visual build | seed | open <empty|corrupt|cases> <сессия> | fingerprint <метка>`.
- **Неверная папка.** Без переменной или с папкой вне `target/verification/` приложение пишет причину и завершается с ошибкой (`exit`), без отчёта о сбое.
- **Тестовые сведения источников** лежат в пространстве `visual-fixture`: пространства интеграций, Codex и плагинов зарезервированы. Если 26D нужны пометки «из истории GitHub/Codex», для наполнения понадобятся их ABI — решение 26D.
- **Снимок неактивного окна** показывает материал боковой панели плоским светло-серым, обоев за ним не видно. Для сравнения стекла окно снимается активным, на переднем плане.

## Уточнения реализации 26B

Принято оркестратором 22 октября 2026 ([приёмка](../../target/verification/orchestration/26b-parent-inspection.md)).

- **Фон окна** — `containerBackground(.ultraThinMaterial, for: .window)`: стеклянного `ShapeStyle` в SDK нет. Белый лист — `textBackgroundColor`, радиус 20, отступы 8, заходит под строку заголовка.
- **Значок настроек** — наложение на строку кнопок окна. `safeAreaBar(edge: .top)` ставил его ниже строки заголовка.
- **Строки дел — обычные кнопки** без `List(selection:)`. Причина: выделение списка в фокусе всегда закрашивается системным акцентом, и ни `.tint`, ни `.focusable(false)` этого не меняют (ответ оркестратора на второй вопрос).
  - Показанное дело — белая скруглённая строка с признаком «выбрано» и полным текстом для VoiceOver.
  - Логика выбора прежняя, включая окно несохранённого и «Отмену».
  - Убраны привязка выбора, чтение `pendingSelection` (R5) и второй оттенок.
  - **Объяснённое отличие:** нет перехода между делами стрелками; Tab и VoiceOver доходят до каждой строки.
- **Структура панели:**
  - «Дела» с «+» — строка с признаком заголовка: заголовок секции сворачивался по нажатию и прятал «+» от VoiceOver;
  - «Завершённые N» — `DisclosureGroup`;
  - пустая память — `ContentUnavailableView` поверх списка;
  - строки «Новая задача» больше нет — то же действие дают «+» и «Новое дело».
- **Компактная капсула** — «Помощь по делу» и «Наблюдение и голос недоступны». Полный текст доступности — в подсказке и в «Основном» настроек, `pause.help` — только в «Основном». Одна круглая кнопка.
- **Главные кнопки** — `ambientPrimary()`: `.borderedProminent`, капсула, `.tint(Theme.ink)`; единственный местный оттенок. Переключатели, списки выбора и ссылки — системный акцент.
- **Строка меню** снимком не сверена: значок прячет программа пользователя для строки меню. Проверено по коду. Пункты при выходе остаются доступными (25H) — объяснённое отличие.
- **Шаблоны сверки** после смены схемы пересоздаются: `scripts/macos.sh visual seed`.

## Уточнения реализации 26C

Принято оркестратором 22 октября 2026 ([приёмка](../../target/verification/orchestration/26c-27c-parent-inspection.md)).

- **Номера шагов — места в плане, как в макете.** Внутренние номера шагов больше не показываются. Это заменяет пометку ADR-023 «Уточнения 25C».
  - Где: «Следующий шаг · 2 из 3», «Шаг 2 из 3», «После шага 2», «Шаг 3 ждёт этот шаг», «Шаг 2 → Шаг 3», выбор шагов в зависимостях.
  - Номер показывается, только когда весь план загружен с первой страницы. Страница шага загружает план с начала (`selectPlan`, `stepsAfter = 0`).
  - В планах из 51–64 шагов номеров нет, а выбор в зависимостях видит первые 50 шагов.
- **Тексты (одобрены оркестратором):**
  - завершение — видимая строка о том, что удалится и что останется, рядом с «Подтвердить завершение»;
  - повторное открытие — правда ядра: план и прежние подробности не возвращаются, напоминания не меняются;
  - удаление дела — отдельные тексты, называющие дело;
  - вкладка «Связи».
- **Объяснённые отличия:**
  - частичный план и «Следующий шаг» вместе не бывают: готовые шаги есть только в подтверждённом плане;
  - у завершённого дела заголовок — итог, а «Открыть снова» — кнопка в шапке;
  - зависимости — тихий список под планом;
  - в капсуле ссылки — сама ссылка;
  - у проверки — маленькая корзина;
  - вкладки — системные сегменты.
- **Исправлена ошибка:** отмена завершения со строкой полезной ссылки роняла приложение. Привязка теперь проверяет границы.

## Уточнения реализации 26D

Принято оркестратором 22 октября 2026 ([приёмка](../../target/verification/orchestration/26d-parent-inspection.md)).

- **Заметки (стр. 5).** Строка сведений «вид · полнота · время · происхождение»:
  - происхождение — «от вас», «из источника» или «из истории Git/Codex/GitHub/Jira/Todoist»;
  - «из истории …» — кнопка-ссылка, раскрывающая сохранённые сведения источника под строкой (адреса для открытия нет);
  - встроенный источник определяется по пространству привязки, тот же набор решает, можно ли выбрать заметку в «Помощи»;
  - «+» — рядом с вкладками;
  - «Ещё заметки и журнал переноса» — без числа: ядро даёт только курсор;
  - «⋯» видна на каждой строке.
- **Связи (стр. 6).** Вставной список, «›» и «⋯» («Открыть дело / Убрать»). У отклонённой связи — метка «Отклонено» и статус дела без даты, а не «Предложенная связь» макета: в ядре есть только «связаны» и «отклонено».
- **Источники (стр. 7–8):**
  - второй ряд — системный `Picker(.palette)`, только названия (D73);
  - локальный проект и Codex: строка пути с «~», «Сохранить область» до сохранения, затем сканирование или чтение; «⋯» с выбором и сохранёнными настройками; исключения — раскрывающийся блок;
  - списки веток и событий — `Picker(.radioGroup)`, выбор хранит модель; «Привязать ветку/событие» видна всегда и недоступна без предпросмотра;
  - GitHub, Jira, Todoist — одна колонка, «Профиль» — меню, одна кнопка чтения: прежние две вызывали одно действие;
  - исправлена ошибка: ключи вида `LocalizedStringKey("a.\(b)")` показывали сырые ключи (`github.title`). В `PluginsView` то же исправит 26F.
- **Помощь (стр. 9).** «Выбрано сведений: N из 32», видимая строка о составе отправки, «Подробнее», переключатели с меткой «история интеграции», строка хода с «Отменяю…», блок «Не удалось выполнить» без «Повторить»: такого действия нет.
- **Диалоги (стр. 20).** «Удалить заметку?» с цитатой заметки; удаление сохранённых настроек папки и файла Codex — с «Отменой» и значком.
- **Не видели агенты:** состояния за входом ChatGPT (ветки, события, предпросмотры, ход и ошибка помощи) и подключённые GitHub и Jira. Они сверены по коду.
- **Для 26E.** «Следующий шаг» сейчас стоит над всеми вкладками, а в макете (стр. 5–9) он есть только на вкладке «План». 26E оставляет его только там.

## Уточнения реализации 26E — 23 октября 2026

- «Следующий шаг» строится только на показанной вкладке «План»; правила готовности ядра сохранены.
- В ленте по-прежнему раскрыта одна карточка: родитель черновика, выбранная строка либо первая текущая. Закрытые карточки остаются в окне и исключены у края. Название дела занимает одну строку, полный текст доступен в подсказке; при отсутствии названия сохраняется числовой идентификатор.
- У уточнения основное действие — ответ; проверяемое копирование и управление видимостью находятся в меню. У скрытой в окне карточки доступно возвращение к краю. Редактор находится внутри родительской карточки, а самостоятельный черновик без видимого родителя — отдельно.
- Сохранённые, но недопущенные к показу у края карточки больше не описываются как отсутствующие: пустая иллюстрация у края требует действительно пустой сохранённой ленты. Пользовательский снимок подтвердил исправление отдельно от снимков главного окна.
- D107 заменяет прежнюю фиксированную высоту из ADR-023: высота по содержимому, максимум 600 точек и доступная область экрана, прежняя ширина и один прокручиваемый список. Изменяется тот же экземпляр панели; верхний край, редактор и фокус сохраняются. Штатное измерение содержимого SwiftUI не зависит от смещения прокрутки.
- Общие проверки после D107: 8 tooling / 394 Rust / 125 Swift, расширенные 181 Swift; сборки, аудит и подписи PASS. Scout, Pattern Librarian и Code Simplicity Reviewer завершили проверку D107 без открытых замечаний. Пользовательский снимок новой отдельной панели подтвердил компактное уведомление без лишней пустой области. Основные доступные экраны проверены; заполненные Источники, вид меню (пункты подтверждены AX) и пользовательские состояния ответа/голоса остаются ограничениями сверки. Локальный тест скрытого нативного окна не заменяет эти проверки.
