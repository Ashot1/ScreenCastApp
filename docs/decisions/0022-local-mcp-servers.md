# ADR-022: локальные MCP-серверы плагинов и Google через workspace-mcp

Статус: **принят для задач 24C и 24B, 21 октября 2026.** Finished Plan Review — PASS с исправлениями (два блокера закрыты текстом), Evidence Audit — неверные утверждения исправлены, Type Scaffolder (только чтение) — рекомендации по типам внесены. Повторные проверки исправленных частей: Plan Simplicity Reviewer — PASS с поправками без блокеров, Evidence Auditor — поправки фактов. Все внесены, решений пользователя не осталось (раздел «Решения обзоров»). **24C принят 21 октября 2026** ([приёмка](../../target/verification/orchestration/24c-parent-inspection.md)): локальные серверы для любых плагинов, схема 15, модель ABI v6, `ambient_plugin.h` v2 (14 экспортов); см. «Уточнения реализации 24C». **24B принят в локальном объёме 21 октября 2026** ([приёмка](../../target/verification/orchestration/24b-parent-inspection.md)): Google через управляемый `workspace-mcp`, `ambient_plugin.h` v2 — 21 экспорт; живой пилот ждёт пользователя.

## Problem Statement

Официальные удалённые MCP-серверы Google Drive/Docs доступны только участникам Developer Preview с аккаунтом Google Workspace. До общего доступа их нельзя распространять. На обычном Gmail каждый вызов инструмента отклоняется «нет прав». Удалённого MCP-сервера, который работает с обычным Gmail и не пропускает документы через стороннюю компанию, нет.

Кроме того, многие плагины, в том числе из кэша Codex, объявляют сервер командой запуска на компьютере, а ADR-021 такие серверы отвергает.

## Solution

Плагин может объявить локальный сервер — команду запуска на Mac (D69). Перед первым запуском пользователь видит:
- точную команду, её аргументы и имена переменных окружения;
- честное предупреждение: это программа с его правами, и Ambient её не ограничивает.

Команды вида `npx -y …`/`uvx …` разрешены с отдельным предупреждением: они скачивают код при каждом запуске (D70). Локальный сервер работает только во время запроса помощи, которому он нужен, и останавливается вместе с ним.

Google Drive/Docs работает через открытый сервер `workspace-mcp` (D68), путь пользователя такой:
1. Кнопка «Добавить Google» в настройках плагинов открывает встроенный плагин «Google Диск и Документы» по обычному пути (D71).
2. Пользователь один раз ставит `uv`.
3. Кнопка «Установить» ставит сервер в папку Ambient строго по закреплённым версиям и хэшам.
4. Ambient сам входит в Google, хранит ключ в Связке ключей и передаёт серверу свежий токен в каждом запросе.

Сервер слушает только 127.0.0.1, работает на чтение Drive и Docs и учётных данных не хранит. Сам он при этом обращается к Google по сети.

Правила D64 сохраняются: модель вызывает только одобренные и закреплённые инструменты «только чтение». Для сервера Google дополнительно действует список разрешённых имён.

## User Stories

1. Добавляю плагин Codex с командой запуска и вижу точно, что будет запущено и с какими правами.
2. Ввожу ключи, нужные локальному серверу; они хранятся в Связке ключей и не попадают в базу, журналы и командную строку.
3. Нажимаю «Запустить и показать инструменты» и выбираю инструменты «только чтение».
4. Во время помощи модель сама вызывает инструменты локального сервера; сервер запускается и останавливается без моего участия.
5. Отмена, пауза и выключение плагина останавливают сервер, и Ambient дожидается его завершения.
6. Нажимаю «Добавить Google» и ставлю сервер одной кнопкой, если `uv` уже установлен; без `uv` вижу понятную инструкцию.
7. Вхожу в Google в браузере; токен хранится в Связке ключей, а не у сервера.
8. Модель ищет и читает мои документы Google на обычном Gmail, без Preview.
9. Подменённый пакет при установке сервера Google не устанавливается.
10. Обновление сервера Google приходит только с выпуском Ambient.

## Implementation Decisions

### Решения развилки

Обе схемы сошлись:
- процессами управляет Rust providers;
- два провода: stdio для команд из пакетов и HTTP через loopback для сервера Google;
- процесс живёт один `dispatch`;
- секреты передаются через окружение, их значения хранятся в Связке ключей;
- установка — закреплённые хэши через `uv`.

Приняты отличия независимой схемы:
- нет реестра PID и уборки «сирот»;
- список разрешённых инструментов Google хранится в Core;
- установка идёт во временную папку `.partial` с переименованием, папка названа хэшем файла требований;
- запуск — интерпретатор venv, без `uv run`/`uvx`;
- частные `HOME` и `TMPDIR`.

Отклонены:
- Swift-супервизор с передачей дескрипторов или мостом stdio↔HTTP: жизненный цикл разошёлся бы между языками и повторился бы в C#. Голосовой помощник запускается из Swift, но это собственный код Ambient без канала MCP;
- тёплый пул с таймерами простоя;
- запуск процесса на каждый вызов;
- `sandbox-exec`;
- запуск скриптов из папки пакета;
- значения переменных окружения из пакета;
- PATH из профиля оболочки (`zsh -lc`);
- подтверждение каждого запуска;
- встроенное в приложение Python-окружение (противоречит D69 и требует подписи сторонних бинарных файлов);
- ссылки сторонних пакетов на управляемый сервер (D71).

### Владельцы и типы

- **Core** решает, что можно запускать, и хранит это в сохранённом пакете:
  - `PluginServerSpec { key, kind: ServerKind }`;
  - `ServerKind` — перечисление с явной меткой `kind` (`#[serde(tag = "kind", rename_all = "snake_case", deny_unknown_fields)]`):
    - `Remote { url, auth_required }`;
    - `Local { command, args, env }`;
    - `Managed { id: ManagedServerId }`.

  Отдельных плоских `url`/`auth_required` больше нет, совместимого слоя тоже: старые сохранённые пакеты без `kind` при открытии дают `UnsupportedSchema`. 24C вводит `Remote` и `Local`; вариант `Managed` и `ManagedServerId` добавляет 24B, чтобы не было неиспользуемого перечисления. Нужен ли ключ, выводится методом `needs_key()`: `Remote` — по `auth_required`, `Local` — непустой `env`, `Managed` — всегда. Отдельный флаг не хранится.
- **`ManagedServerId`** (24B) — одно перечисление в Core (`GoogleWorkspace` ↔ `google-workspace`, `as_str`/`parse`, `builtin_package_hash()`). На нём построены:
  - исчерпывающие `match` списка разрешённых инструментов (Core);
  - рецепт запуска (providers импортирует тип из `ambient-core`);
  - реестр OAuth (24B).

  Новый ID не скомпилируется, пока не задан в каждом из этих мест.
- **Разрешение на вызов и обнаружение.** `ToolCallPermit` и обнаружение несут `Target` из Core вместо строки `url`:
  - `Remote { url }`;
  - `Local { command, args, env_names }` — частную папку providers строит как `<root>/<plugin key>`: ключ по правилу ADR-021 безопасен как имя папки, и Core не знает раскладку файлов;
  - `Managed(ManagedServerId)`.

  Providers пакет не читает. Обнаружение в ABI принимает `(plugin, server)`, и Core сам выбирает цель. Адрес `http://127.0.0.1:<port>/mcp` строит только ветвь `Managed` после выбора порта. `allowed()` не меняется и применяется только к `Remote`, поэтому тестовая ветвь loopback не становится лазейкой в рабочем коде. `PinnedTool` хранит ту же цель. Список разрешённых инструментов управляемого сервера проверяет Core при одобрении и при выдаче разрешения на вызов, а не в `canonical_tool`.
- **Providers** получает модуль `local_host.rs` — единственное место, где запускаются дочерние процессы, где с ними идёт обмен и где они завершаются (`std::process`, переносимо). Сигналы группе — `rustix::process::kill_process_group(Pid::from_child(..), Signal::TERM | Signal::KILL)`, проба сигналом 0 — `rustix::process::test_kill_process_group`: `rustix` 1.1.5 становится прямой зависимостью providers с feature `process`, потому что `tempfile` включает только `fs`, а `unsafe_code = "forbid"`. Разбор карты секретов (`parse_env_map`) тоже здесь: Core секретов не видит.
- **macOS:**
  - корневая папка данных;
  - просмотр и настройки, кнопка «Добавить Google»;
  - Связка ключей: значения переменных и токен Google;
  - кнопки «Установить» и «Запустить и показать инструменты», признак «устанавливается» в интерфейсе;
  - игнорирование SIGPIPE в процессе приложения при старте (см. «Транспорты»);
  - удаление частной папки плагина после удаления в Core.
- **Новых таблиц нет.** Состояние процессов нигде не сохраняется.

### Пакет

- **Распознавание записи сервера:**
  - есть `url` — `Remote`;
  - есть `command` (`type` отсутствует или `stdio`) — `Local`;
  - `{"ambient_managed": "<id>"}` — `Managed` (24B), но только во встроенном пакете Google: при просмотре и установке хэш пакета должен равняться `ManagedServerId::builtin_package_hash()` (D71); в любом другом пакете такая запись — предупреждение и пропуск сервера. При открытии сохранённая запись `Managed` проверяется только структурно (ID разбирается): иначе новая версия встроенного пакета в следующем выпуске сделала бы установленный плагин неоткрываемым. Новая версия встроенного пакета — обычная переустановка плагина;
  - запись одновременно с `url` и `command` отвергает пакет;
  - `sse` по-прежнему отвергается.
- **Локальный сервер:**
  - `command` — 1…1024 байта, без NUL;
  - `args` — до 32, каждый ≤1024 байт, без NUL;
  - имена переменных — до 16, формат `^[A-Z_][A-Z0-9_]{0,63}$`, сортируются и не повторяются;
  - имена `PATH`, `HOME`, `TMPDIR` и имена с префиксами `DYLD_` и `LD_` отвергают пакет: имена из пакета — недоверенный ввод, и они не должны переопределять окружение Ambient;
  - значения переменных из пакета игнорируются; заполнители `${VAR}` в аргументах передаются буквально, и просмотр о них предупреждает;
  - команда с относительным путём или путём в папке пакета (`./server.js`, `scripts/…`) — предупреждение и пропуск сервера; поле `cwd` игнорируется с предупреждением; аргумент с относительным путём даёт только предупреждение;
  - один проверяющий конструктор в `plugin_package.rs` используется и при установке, и при проверке во время открытия (кроме проверки происхождения `Managed`, см. выше).
- **Хэш пакета** уже покрывает спецификацию запуска: он считается по байтам входных файлов. Изменение команды, аргументов или имён переменных — новый пакет и новый просмотр. Пределы ADR-021 (≤16 плагинов, ≤4 сервера и др.) не меняются.
- **Встроенный пакет Google** (24B) входит в выпуск одним владельцем: байты встраиваются в Core (`include_bytes!`) рядом с `builtin_package_hash()`, а операция моста отдаёт их кнопке «Добавить Google» для обычного просмотра. Тест сверяет хэш байтов с константой, поэтому расхождение при выпуске даёт громкий отказ, а не тихий пропуск сервера.

### Жизнь процесса

`LocalHost` создаётся в `dispatch` моста и уничтожается в его конце на любом пути выхода. Отдельные блокирующие операции «обнаружение» и «установка» создают свой. Он хранит одну карту `(plugin, server) → Live(процесс) | Failed`, не больше 4 живых процессов.

- **Запуск.** Сервер запускается лениво при первом вызове его инструмента — тогда же, когда Core ставит `list_first`. stdio-серверу `initialize` отправляется один раз за запрос. Сервер Google через loopback HTTP получает `initialize` в каждой операции, как удалённые серверы: он работает без состояния и это допускает.
- **Отказ.** Любой отказ провода — срок, неверный кадр, конец потока, превышение предела, выход процесса — завершает процесс и помечает сервер `Failed`. Дальнейшие вызовы к нему в том же запросе сразу дают «недоступен» (`Unavailable`). Перезапусков и повторов нет.
- **Остановка.**
  1. Закрыть stdin — это мягкое завершение по спецификации MCP.
  2. SIGTERM группе.
  3. Ожидание до 300 ms.
  4. SIGKILL группе.
  5. Ожидание лидера до 2 s.
  6. После сбора лидера группа опрашивается пробой (`test_kill_process_group`) до опустения, не дольше 2 s. Сигнал группе после сбора лидера отправляется, только если проба показала живых участников.

  Лидер, не собранный за 2 s (неубиваемое состояние ядра, например зависший сетевой диск), или группа, не опустевшая за 2 s, дают в журнале вызовов итог «остановка не подтверждена», и `busy` снимается; сбор лидера доделывает фоновый поток. Это осознанное отступление от правила AGENTS «освобождать только после подтверждённого завершения» для процессов плагинов (не для локальной модели): иначе запрос помощи и плагин блокировались бы навсегда процессом, который Ambient уже не может завершить.
- **Отмена, пауза, выключение и удаление плагина** поднимают флаг отмены. Срезы ожидания по 25 ms его замечают, `dispatch` возвращается, а Drop-guard завершает процессы. Отмена во время запуска (порождение процесса и повторы готовности HTTP) работает так же.
- **Падение Ambient.** Ядро закрывает stdin дочернего процесса. Сервер, который игнорирует конец stdin, и HTTP-сервер Google могут пережить Ambient до перезагрузки. Это остаточный риск: он указан в просмотре, уборка не строится. Собственный Python-лаунчер с выходом по концу stdin добавляется для Google, только если «сироты» подтвердятся на практике.

Окружение процесса:
- **группа:** `process_group(0)`;
- **окружение:** очищается, окружение приложения не наследуется;
- **`PATH`:** фиксированный список `/opt/homebrew/bin:/usr/local/bin:<home>/.local/bin:<home>/.cargo/bin:/usr/bin:/bin:/usr/sbin:/sbin`, где `<home>` — настоящая домашняя папка пользователя, подставленная Rust (не частный `HOME` процесса). Команды из `nvm`/`fnm` не находятся, и это честно показывается;
- **рабочая папка:** пустая частная папка плагина в данных Ambient, туда же указывают `HOME` и `TMPDIR`. Её размер не ограничен (например, кэш npm), удаляется она вместе с плагином;
- **stdout:** читается только у stdio-серверов; у сервера Google и у `uv` при установке он направляется в `/dev/null`, чтобы переполненный канал не остановил процесс.
- **stderr:** отдельный поток собирает хвост 8 KiB в памяти. В модель и журналы он не попадает. Показывается только в операциях пользователя («Запустить и показать инструменты», «Установить»), и перед показом из него вырезаются точные значения секретов этого сервера.

### Транспорты

**stdio (локальные серверы из пакетов):**
- JSON, по одному сообщению на строку.
- `Session` из `mcp.rs` делится на слой провода и общую логику `initialize`/`list`/`call`:
  - провод HTTP — существующий код;
  - провод stdio и пишет, и читает через отдельные потоки с каналами (`recv_timeout(25 ms)`) и поэтому замечает флаг отмены и срок. Блокирующая запись в основном потоке недопустима: сервер, не читающий stdin, при запросе больше буфера канала (16–64 KiB) заблокировал бы `dispatch` до того, как Drop-guard успел бы завершить процесс. При отмене или сроке процесс завершается, запись получает `EPIPE` → `Unavailable`.
- Читатель ограничен **во время** чтения: строка без перевода длиннее предела операции (call 256 KiB, list 128 KiB, прочее 64 KiB) — `Invalid` и завершение процесса.
- Строка, не являющаяся сообщением JSON-RPC, — `Invalid` и завершение.
- Запрос сервера к клиенту — `Invalid`.
- Уведомления без `id` пропускаются, но учитываются в пределе.
- **SIGPIPE.** Запись в stdin уже вышедшего процесса не должна убивать приложение. Rust игнорирует SIGPIPE только в своих исполняемых файлах, а providers собран в Swift-приложение. Поэтому macOS-оболочка в своей функции запуска приложения игнорирует SIGPIPE (`std::process::Command` сам возвращает потомку обработку по умолчанию), а `EPIPE` превращается в `Unavailable`. Проверка — тест Swift-хоста, который вызывает именно эту функцию запуска (а не `signal` в самом тесте), с процессом, вышедшим до записи: Rust-тесты этого не покажут.

**HTTP через loopback (только управляемый сервер Google):**
- существующая HTTP-сессия без изменений, адрес строит только ветвь `Managed`;
- ответ больше предела провода — ошибка только этого вызова (`Invalid` в конверте ошибки); HTTP-сервер при этом не завершается и не помечается `Failed`: в отличие от stdio, поток после ответа не рассинхронизирован;
- прокси и перенаправлений нет;
- готовность — успешный `initialize`: при «connection refused» он повторяется до срока запуска, а если процесс вышел — отказ сразу, с хвостом stderr;
- порт — случайный высокий, его проверяют пробной привязкой перед запуском; ранний выход сервера (порт занят) — отказ;
- остаточный риск: процесс того же пользователя, занявший порт в короткое окно до сервера, получит токен только для чтения сроком около часа. Это описывается в документации.

### Секреты

Массив ключей `dispatch` (ADR-021 «C ABI») несёт текст секрета на время вызова. Core видит только `(plugin, server, generation)`. Как толковать текст, providers решает по виду цели из разрешения, а не по содержимому текста.

- **Google:**
  - текст — свежий access token; native обновляет его с запасом 300 s;
  - providers отправляет его как `Authorization: Bearer` в каждом HTTP-запросе к серверу;
  - `client_secret` процессу не передаётся; в окружении только публичный `GOOGLE_OAUTH_CLIENT_ID`.
- **Локальные серверы с переменными:**
  - значения вводит пользователь;
  - Связка ключей хранит их новым видом секрета `env(map)` в параметризованном владельце секретов плагинов из 24A, с привязкой к экземпляру базы и поколению;
  - имена карты должны совпадать с объявленными в пакете — лишние отвергаются; значения — печатный ASCII 33…126, непустые;
  - для передачи используется компактный JSON карты с отсортированными ключами, длиной ≤16 KiB после экранирования (правило ADR-021);
  - providers разбирает его (`parse_env_map`): отвергает повторённые имена, имена вне списка из разрешения и больше 16 имён, а значения повторно проверяет **после** разбора JSON — экранированные последовательности могли дать пробел или NUL;
  - в аргументы секреты не попадают никогда; недостающее имя при вызове даёт «не настроено».
- **Честный предел:** процесс того же пользователя может прочитать окружение другого процесса. Это покрывается фразой «работает со всеми вашими правами».

### Управляемый сервер Google

**Встроенный пакет и вид.**
- Кнопка «Добавить Google» передаёт в обычный просмотр байты встроенного пакета. Его единственный сервер — `{"ambient_managed": "google-workspace"}`.
- Сервер запускается командой `<venv>/bin/python -P -m main` с фиксированными аргументами. Модуль `main` — точка входа пакета `workspace-mcp` (`main:main`, установлен как модуль верхнего уровня). Скрипт `workspace-mcp` не используется: после переименования папки путь в его shebang неверен. `-P` не добавляет текущую папку (частную папку плагина) в `sys.path`, чтобы записанный туда файл не подменил модуль.

**Аргументы:** `--transport streamable-http --read-only --tools drive docs`. Флаг `--disabled-tools` не нужен: барьер — положительный список Core. Флаг добавляется, только если полный `tools/list` превысит 128 KiB.

**Окружение:**
- `MCP_ENABLE_OAUTH21=true`, `EXTERNAL_OAUTH21_PROVIDER=true`, `WORKSPACE_MCP_STATELESS_MODE=true`;
- `WORKSPACE_MCP_HOST=127.0.0.1`: обязательно явно, иначе в режиме OAuth 2.1 сервер слушает 0.0.0.0;
- `WORKSPACE_MCP_PORT=<порт>` (`PORT` в очищенном окружении не задан);
- `GOOGLE_OAUTH_CLIENT_ID`;
- `WORKSPACE_MCP_MAX_FILE_BYTES=131072` — целое число. Он ограничивает только скачивание файлов Drive (`get_drive_file_content`, не-нативные файлы в `get_doc_content`): больший файл даёт обычный текст «слишком большой» вместо содержимого. На `get_doc_as_markdown` и чтение нативного Google Doc он не действует — их вывод ограничивает только предел провода 256 KiB, и более длинный ответ даёт ошибку вызова (см. «HTTP через loopback»). Модель всё равно видит ≤12 KiB; чтение длинных документов по частям остаётся вне ADR-021;
- `WORKSPACE_MCP_DISABLE_LOCAL_FILES=true` (stateless-режим уже отключает локальные файлы);
- переменные `OTEL_*` не задаются.

`HOME`/`TMPDIR` — частная папка: туда попадают все домашние пути сервера (`~/.google_workspace_mcp`, `~/.workspace-mcp`).

**Список разрешённых инструментов.** Положительный список имён:
- обязательно `search_drive_files`, `get_drive_file_content`, `search_docs`, `get_doc_as_markdown`;
- по сверке `tools/list` закреплённой версии возможны `list_drive_items`, `get_doc_content`, `list_docs_in_folder`, `list_document_comments`.

Одобрение требует и имени из списка, и `readOnlyHint: true`. Список проверяется и при одобрении, и при каждом вызове: имя, убранное в новом выпуске, перестаёт вызываться, даже если было одобрено.

**Установка** — блокирующая отменяемая операция через описатель операции (см. «C ABI»), срок около 10 минут.

1. **Файл требований.**
   - Приложение собирается только для arm64, поэтому файл один (для x86_64 его и не собрать: у `cryptography` 50.0.0 нет колеса macOS x86_64).
   - Зависимости берутся из `uv export --format requirements.txt --no-emit-project --no-dev --frozen` тега v2.1.1 (хэши включаются по умолчанию); точное написание проверяется по `uv --version` при подготовке выпуска.
   - Строка `workspace-mcp==2.1.1` с хэшами колеса берётся с PyPI и сверяется с тегом: блокировка тега отстаёт от версии пакета (2.0.1 против 2.1.1).
   - Файл встраивается в providers через `include_str!`.
   - При каждом повышении версии подготовка выпуска проверяет `uv lock --check` тега, наличие колёс arm64 для закреплённого Python и изменения кода; это входит в чек-лист выпуска (`docs/verification.md`).
2. **Поиск `uv`.**
   - `uv` ищется в четырёх фиксированных местах: `/opt/homebrew/bin/uv`, `/usr/local/bin/uv`, `<home>/.local/bin/uv`, `<home>/.cargo/bin/uv`.
   - Нет `uv` — кнопка выключена, показаны «Сначала установите uv» и копируемая официальная команда.
   - Ambient `uv` не ставит (D69). `uv` нужен только для установки.
3. **Создание окружения.**
   - Перед началом удаляются оставшиеся папки `.partial` (после падения или отмены).
   - Команды: `uv venv --python cpython@3.12.<закреплённый патч>` (документированная форма запроса), затем `uv pip install --require-hashes --only-binary :all: --no-deps --index-url https://pypi.org/simple -r <файл>`.
   - Окружение `uv` очищено, PATH фиксированный, прокси не передаётся (за прокси установка честно не удаётся). Задано: `UV_NO_CONFIG=1`, управляемый Python (`UV_PYTHON_PREFERENCE=only-managed` или документированный `--managed-python`; значение подтверждается при приёмке 24B), а `UV_PYTHON_INSTALL_DIR` и `UV_CACHE_DIR` указывают в папку Ambient.
   - Хэши пакетов проверяет `uv`.
4. **Проверка до переименования.** Установка идёт в `<данные>/google-workspace-mcp/<sha256 файла требований>.partial`. Перед переименованием `<venv>/bin/python -P -c "import main"` должен пройти; проверка идёт с очищенным окружением, частными `HOME`/`TMPDIR` и `WORKSPACE_MCP_STATELESS_MODE=true`, потому что импорт `main` выполняет код верхнего уровня (настройку журнала).
5. **Переименование.** Папка атомарно переименовывается в `<sha256>`, и запуск использует папку с хэшем текущего выпуска. После успеха удаляются все папки с другим хэшем.
6. **Несовпадение хэша или отказ.** `uv` отказывает, `.partial` удаляется, сообщение «хэш пакета не совпал, ничего не установлено». Установки без хэшей нет.
7. **Обновление.**
   - Новый выпуск Ambient несёт новый хэш.
   - Пока новый сервер не установлен, Google не работает. Статус «Нужно обновить сервер Google» и кнопка «Обновить».
   - Прежняя папка удаляется после успешной новой установки.
8. **Удаление.** Кнопка «Удалить сервер» и удаление плагина Google удаляют всю папку `<root>/google-workspace-mcp`. Это делает macOS и только когда нет активной операции или `dispatch` (тот же `busy`, что при удалении плагина); отдельной операции ABI для этого нет.

**Вход Google** — реестр OAuth из ADR-021 (24B) по `ManagedServerId`, а не по хосту. Сохраняются проверенные факты входа:
- loopback 127.0.0.1, PKCE;
- `iss` = `https://accounts.google.com`;
- `client_secret` обязателен;
- без `resource`;
- без ротации refresh token;
- 7 дней в тестовом режиме.

Права: `openid`, `https://www.googleapis.com/auth/userinfo.email` (без него сервер отвергает токен), `drive.readonly`, `documents.readonly` — все только для чтения. Окно согласия Google показывает их пользователю. Сервер проверяет токен запросом userinfo к Google при каждом вызове, поэтому токен уходит в Google дважды: userinfo и API.

### «Только чтение» (D64) для локальных серверов

Механизм ADR-021 не меняется:
- обнаружение;
- одобрение инструментов с `readOnlyHint: true`;
- закреплённое определение и хэш;
- сверка при первом использовании сервера в запросе;
- массив `tools` из закреплённого.

Обнаружение у локального сервера запускает его, поэтому это явная кнопка «Запустить и показать инструменты». Окно настроек не повторяет обнаружение само: отметка «изменён» появляется только при этой кнопке или при использовании. Просмотр пакета ничего не запускает.

Честная асимметрия: отметка «только чтение» — заявление самой программы. Она ограничивает то, что модель может попросить, но не программу.

### Пределы

| Что | Предел |
| --- | --- |
| Запуск и `initialize` при первом вызове сервера в запросе | до 30 s сверх предела вызова 20 s |
| Запас Core перед вызовом | удалённый сервер — 90 s (как сейчас); первый вызов локального сервера в запросе (`list_first`) — 120 s: 20 + 30 + резерв 70 на последний POST |
| Обнаружение у локального сервера | до 120 s, отменяемо (холодный `npx -y` скачивает код) |
| Остановка | ожидание лидера и опрос группы — по 2 s, затем «остановка не подтверждена» |
| Живых процессов на запрос | 4 |
| Сообщение stdout | действующие 256/128/64 KiB, ограничение во время чтения |
| Хвост stderr | 8 KiB, не журналируется, без значений секретов |
| Пакет | команда ≤1 KiB, ≤32 аргументов по ≤1 KiB, ≤16 имён переменных |

Арифметика: цикл длится 180 s, а первый POST — до 60 s. Поэтому первый вызов локального сервера допускается, только если первый POST уложился примерно в 60 s, а второй круг с новым локальным сервером практически невозможен. Числа подтверждаются измерением холодного запуска при приёмке. Если одного запуска на запрос не хватает, это вопрос к оркестратору, а не повод для пула.

### C ABI

- **Модель** (24C). `dispatch` получает корневую папку локальных серверов (`AmbientText`, абсолютный путь ≤1024 байт без NUL; её проверяет мост). Смена сигнатуры даёт механическое переименование модели v5→v6 без совместимого слоя, вместе с тестовым двойником.
- **`ambient_plugin.h` v2** (24C — описатель и `discover`; 24B — `managed_status`, `managed_install` и выдача байтов встроенного пакета, тот же v2, выпуска между ними нет):
  - Описатель операции по образцу модели: `operation_begin`, `operation_cancel` (запрос остановки), `operation_close` (`busy` до фактического возврата). Блокирующие `discover` и `managed_install` принимают описатель, корневую папку и `(plugin, server)` или ID.
  - Смена сигнатуры `discover` даёт механическое переименование заголовка v1→v2.
  - Строка «мост не хранит состояния плагинов» уточняется: глобальная таблица операций есть, как у модели.
- **`managed_status`** (без состояния, принимает ID и корневую папку) возвращает `not_installed | installed | outdated | uv_missing`. «Устанавливается» — состояние интерфейса macOS, а не результат операции.
- **`managed_install`** возвращает JSON `{status: installed | hash_mismatch | uv_missing | failed | cancelled | timeout, stderr_tail}`. Коды C — только для ошибок аргументов, пределов и описателя, как у `discover`. Неизвестный ID отвергается до запуска чего-либо.

### Что показывает просмотр

Для любого локального сервера:
- точная команда, каждый аргумент и имена переменных окружения, которые он получит; предупреждения о `${VAR}` и относительных путях в аргументах;
- «Это программа на этом Mac, она запускается со всеми правами вашей учётной записи. Ambient не ограничивает и не проверяет, что она читает, пишет и куда отправляет»;
- «Отметка "только чтение" — заявление самой программы; Ambient её не проверяет и не ограничивает саму программу»;
- для команд, скачивающих код при запуске (D70; список: `npx`, `bunx`, `pnpm dlx`, `yarn dlx`, `uvx`, `pipx run`), — отдельно: скачивание происходит при каждом запуске, запускается текущая версия, а не просмотренная, и Ambient её не проверяет;
- когда работает: только во время запроса помощи, которому нужен, и при каждом нажатии «Запустить и показать инструменты»; после запроса останавливается;
- аргументы вызовов, а в них может быть содержимое дела, уходят этой программе и туда, куда она их отправляет;
- сервер, игнорирующий закрытие ввода, может остаться работать после аварийного завершения Ambient;
- команды из `nvm`/`fnm` не находятся;
- команды, ссылающиеся на файлы в папке пакета, не поддерживаются.

Для Google дополнительно:
- **Что скачивается:** сборка Python 3.12 через `uv` из выпусков Astral на GitHub и закреплённые пакеты с PyPI. Размер — сотни мегабайт, время — минуты; точные числа из приёмки.
- **Защита и её предел:** закрепление версий и хэшей защищает от подмены после закрепления, но не от плохого выпуска. У пакета нет подписей, дерево зависимостей нами не проверялось.
- **Сеть:** сервер слушает только 127.0.0.1 — проверено при приёмке. Он обращается к Google при каждом запросе (проверка токена и API). Учётных данных он не хранит: Ambient передаёт ему короткоживущий токен.
- **Права Google:** `openid`, email, `drive.readonly`, `documents.readonly`.
- **Данные:** текст документов уходит провайдеру ИИ в контексте. Прочитанное, на что ссылается ответ, сохраняется в памяти дела (D62).
- **Предупреждения:** о prompt injection (из README проекта); повторный вход раз в 7 дней в тестовом режиме.

Все строки EN/RU утверждает оркестратор до Localization Mechanic.

### Изменения ADR-021 и задач

**ADR-021** принимает ADR-022:
- удалённые и локальные серверы;
- строка 73 (отказ `stdio`), строка 74 (переменные окружения пакета игнорируются — теперь читаются имена, значения по-прежнему нет), строка 107 (реестр 24B по хостам `drivemcp`/`docsmcp` → по `ManagedServerId`), тест строки 219 (отказ stdio/localhost) и «Out of Scope» строки 248;
- владельцы (`local_host`), `ServerKind`, `Target` в разрешении, `env(map)`;
- обнаружение запускает локальный сервер, и окно настроек его не повторяет;
- провода stdio и loopback HTTP;
- запас по видам серверов;
- комментарий массива ≤64 ключей (текст может быть картой);
- C ABI: модель v6, `ambient_plugin.h` v2 с описателем;
- вход Google по `ManagedServerId`;
- абзац о локальных программах в приватности.

Факты живой проверки об официальных MCP Google становятся историей, факты о входе остаются в силе.

**Задачи и порядок:**
- **24A** — без изменений по существу; идёт сейчас.
- **24C — локальные серверы для любых плагинов** (полная пользовательская возможность). Состав:
  - `local_host`;
  - провод stdio;
  - `ServerKind { Remote, Local }` и `Target { Remote, Local }`;
  - разбор `command`, аргументов и имён;
  - секрет `env(map)`;
  - описатель операции и v2/v6 ABI;
  - SIGPIPE;
  - тексты просмотра;
  - кнопка «Запустить и показать инструменты»;
  - тестовые серверы на каждый сценарий;
  - ручная проверка приёмки на одном настоящем локальном сервере из кэша Codex (`npx` или `uvx`): холодный запуск, обнаружение, вызов, отмена; результаты — в `docs/verification.md`.
- **24B — Google** (переопределяется). Состав:
  - встроенный пакет и кнопка «Добавить Google»;
  - вариант `Managed`, `ManagedServerId` и список разрешённых инструментов;
  - установка и статус;
  - провод loopback HTTP;
  - вход OAuth по `ManagedServerId`;
  - тексты Google;
  - живой пилот.

  Действие пользователя — включить обычные Google Drive API и Google Docs API в проекте Google Cloud, без Preview. Задача большая: если исполнитель разделит её, первая половина (установка и провод без входа) не считается пользовательским шагом.

Порядок: 24A → 24C → 24B. Todoist 17A можно вести параллельно с 24C, если наборы файлов не пересекаются; это решается при приёмке 24A.

## Testing Decisions

До живой проверки 24B — только тестовые серверы и тестовый `uv`, без настоящих аккаунтов.

**stdio (24C).** Тестовые серверы:
- игнорирует конец stdin;
- игнорирует SIGTERM (ветвь SIGKILL);
- имеет потомка в той же группе, переживающего лидера (опрос группы);
- пишет мусор;
- пишет слишком длинную строку без перевода (ограничение во время чтения);
- не отвечает на `initialize`;
- выходит рано;
- присылает запрос клиенту;
- выходит до первой записи — тест Swift-хоста на SIGPIPE.

Ожидания: `Invalid` или «недоступен», процесс завершён и выход подтверждён, `busy` снят только после сбора лидера.

Ещё для stdio: сервер, не читающий stdin, и запрос больше буфера канала — `dispatch` возвращается по сроку; после `Failed` следующие вызовы дают `Unavailable` без нового запуска; лидер, не собранный за 2 s, даёт «остановка не подтверждена».

**Отмена, пауза, срок сессии:** во время вызова и во время запуска процесс завершается до возврата `dispatch`.

**Несколько плагинов:** не больше 4 процессов, остальные «недоступен».

**Секреты:**
- значения `env(map)` не попадают в SQLite, журналы, аргументы (`ps`) и показанный хвост stderr (вырезаются);
- повторённые и лишние имена, значения с экранированным пробелом или NUL отвергаются.

**Окружение:**
- переменные приложения не наследуются;
- `PATH` фиксирован, `~` раскрыт настоящей домашней папкой;
- `HOME`/`TMPDIR` частные;
- запрещённые имена переменных и запись с `url` и `command` одновременно отвергают пакет;
- сохранённый пакет без `kind` при открытии даёт `UnsupportedSchema`;
- команда из папки пакета пропускается.

**Обнаружение:** отменяемо, укладывается в предел 120 s.

**Loopback HTTP (24B):**
- тестовый сервер без состояния принимает Bearer;
- цель `Managed` строит адрес, а такой же адрес из пакета отвергнут;
- ранний выход и занятый порт дают отказ (тестовая точка подстановки занятого порта — только test-support).

**Установка (24B), тестовые места `uv` подставляются только в test-support:**
- нет `uv` — ничего не запускается;
- успех — проверка импорта и переименование;
- несовпадение хэша — `.partial` удалён;
- устаревшая папка и статус «Нужно обновить»;
- отмена;
- удаление папки.

**Список Google и встроенный пакет (24B):** имя вне списка не одобряется даже с `readOnlyHint: true`; имя, убранное из списка, не вызывается после одобрения; запись `ambient_managed` вне встроенного пакета — предупреждение и пропуск; хэш встроенных байтов равен `builtin_package_hash()`; установленный `Managed` открывается после смены встроенного пакета; `ManagedServerId` `as_str`/`parse` туда и обратно; ответ HTTP больше 256 KiB — ошибка вызова без `Failed`.

**Без включённых локальных плагинов** запрос модели побайтно прежний.

**Обычные проверки:** `yarn verify`, all-features Clippy, сборка, подписи, аудит экспортов, контрольные сборки.

**Ручные проверки приёмки 24B** (записываются в `docs/verification.md`, это не тесты CI):
- настоящий `uv` с подменённым хэшем — отказ;
- сервер не отвечает по адресу в локальной сети;
- stateless-режим ничего не пишет вне частной папки;
- холодный запуск и сроки, размер и время установки;
- колёса arm64;
- переименованная папка venv запускает `python -P -m main` и `-c "import main"`;
- длинный Google Doc через `get_doc_as_markdown` даёт честную ошибку вызова;
- размер `tools/list` Drive+Docs (оценка 40–70 KiB);
- проверяет ли `uv` хэш сборки Python (если нет — вопрос пользователю);
- точные права и `tools/list` закреплённой версии.

## Уточнения реализации 24C

Приняты оркестратором 21 октября 2026 как толкования внутри этого контракта.

- **Частная папка** — `<root>/<ID плагина>`: у плагина нет «ключа», ID безопасен для файловой системы и не переиспользуется. Корень на macOS — `<Application Support>/dev.ambient.foundation/plugins` рядом с базой памяти; providers создаёт его с правами 0700.
- **Схема 15:** единственное изменение DDL — `plugin_calls.outcome` 0..11 (новые исходы `NotConfigured = 10`, `StopUnconfirmed = 11`). Сохранённый JSON пакета получает метку `kind` в той же версии. Схема 14 и её WAL отклоняются только для чтения. «Новых таблиц нет» остаётся верным.
- **«Остановка не подтверждена».** После запроса Core ставит исход 11 на самой новой строке вызова этого сервера и заменяет прежний исход, в том числе «выполнен». Обнаружение журнал не пишет: в его JSON `"stop_confirmed": false`.
- **JSON обнаружения:** добавлены статусы `not_configured` и `cancelled`; `stderr` (хвост ≤8 KiB без секретов) — только при отказе локального сервера.
- **Ограничение stdout:** поток-читатель ограничивает каждую строку наибольшим пределом операции (256 KiB) во время чтения; меньшие пределы (128/64 KiB) проверяются при поступлении строк, включая уведомления.
- **Команды в папке пакета.** Core видит только пути относительно пакета, поэтому команда с относительным путём пропускается. Абсолютная команда, указывающая внутрь папки плагина (например, `codex-app-tools` в кэше Codex), для Core неотличима: она остаётся и запускается из частной папки.
- **Предупреждение об относительных путях** в аргументах не срабатывает на `@scope/package` и `-flag`.
- **Сборки не для Unix:** `local_host_other.rs` оставляет удалённые серверы рабочими и отвечает «недоступен» для локальных до адаптера Windows.
- **macOS:**
  - обнаружение идёт в собственной очереди (`PluginDiscovery`) и не держит актор памяти;
  - закрытие занятой операции возвращает 4;
  - `AmbientProcess.launch()` — первая строка `AmbientAppDelegate.init`.
- **Модель ABI v6:** `AmbientText root` идёт после `key_count` (в `dispatch` и тестовом двойнике).
- **Ручная проверка:** `uvx mcp-server-time@2026.10.19`. Холодное обнаружение 10,8–12,1 s (около 86 MB в частной папке), тёплое 0,38–0,41 s, вызов 0,36–0,38 s, отмена 0,31–0,34 s без оставшихся процессов.

## Уточнения реализации 24B

Приняты оркестратором 21 октября 2026 как толкования внутри этого контракта.

- **Встроенный клиент Google:**
  - `src/providers/build.rs` встраивает Desktop-клиент при сборке из JSON, указанного в `AMBIENT_GOOGLE_OAUTH_CLIENT`; `scripts/macos.sh bridge` по умолчанию указывает `~/.config/ambient/google-oauth-client.json`;
  - секрет есть только в выходах сборки под `target/` и в бинарном файле, но никогда не в отслеживаемых файлах;
  - сборки без файла (`yarn verify`, Windows CI) показывают «В этой сборке Ambient нет клиента входа Google»; сборки test-support используют фиксированный тестовый клиент.
- **OAuth ABI:**
  - `ambient_plugin.h` v2 получает экспорты без описателя: `oauth_begin`, `oauth_exchange`, `oauth_refresh`, `oauth_revoke`;
  - macOS хранит `state` и verifier в памяти только на один вход;
  - Rust проверяет: каждый параметр ответа ровно один раз, `state` этого входа и точный `iss`; `access_denied` даёт `denied`;
  - перенаправление — только `http://127.0.0.1:<port>/`;
  - всего 21 экспорт, вместе с `builtin`, `managed_status`, `managed_install`.
- **Отзыв:**
  - выход и удаление плагина сначала отзывают refresh token в Google: одна форма POST ≤15 s без повтора, по RFC 7009 вручную, потому что `oauth2` отказывается от не-HTTPS адреса тестового сервера;
  - затем всегда выполняются отзыв в Core и удаление из Связки ключей;
  - если отозвать в Google не удалось, показывается `plugins.google.revokeFailed`;
  - при `invalid_grant` в Google ничего не отзывается.
- **Окружение сервера:**
  - `FASTMCP_SERVER_AUTH_GOOGLE_JWT_SIGNING_KEY` — 32 случайных байта на каждый запуск, вырезаются из хвоста stderr; без этой переменной 2.1.1 не стартует, если секрет клиента не передан;
  - `FASTMCP_CHECK_FOR_UPDATES=off`.
- **Список разрешённых инструментов** (8, сверен с `tools/list` закреплённой версии):
  - входят: `search_drive_files`, `get_drive_file_content`, `list_drive_items`, `search_docs`, `get_doc_content`, `get_doc_as_markdown`, `list_docs_in_folder`, `list_document_comments`;
  - вне списка, хотя у них `readOnlyHint: true`: `get_drive_file_download_url`, `get_drive_file_permissions`, `check_drive_file_public_access`, `get_drive_shareable_link`, `inspect_doc_structure`, `debug_docs_runtime_info`, `debug_table_structure`.

  Обнаружение помечает их `approvable:false`. Одобрение отвечает `InvalidInput`. Закреплённое имя вне списка получает при выдаче разрешения конверт `not_allowed` — без сети и без строки журнала.
- **Пакет:** `{"ambient_managed": …}` вместе с любым другим полем отвергает пакет.
- **Порт:** случайный в 20000–32767 с пробной привязкой, ниже эфемерных диапазонов. Иначе собственное соединение опроса готовности могло занять порт: так было найдено под нагрузкой.
- **Провод HTTP:**
  - `Invalid` (в том числе >256 KiB), 401 (`LoginRequired`) и `ToolError` оставляют сервер живым;
  - срок, отмена и `Unavailable` (отказ соединения, не-2xx, выход процесса) останавливают его;
  - готовность — порт принимает TCP-соединение за 30 s с проверкой выхода процесса;
  - каждая операция делает свой `initialize`;
  - токена в окружении сервера нет.
- **Установка:**
  - раскладка `<root>/google-workspace-mcp/{<sha256 файла требований>, python}`;
  - на время установки — `.partial`, `home` и `cache` (около 200 MB); они удаляются после каждой попытки;
  - CPython 3.12.12;
  - `hash_mismatch` распознаётся по «hash mismatch» в stderr `uv`;
  - `uv` проверяет и хэш сборки Python (проверено подменой);
  - в режиме внешнего провайдера сервер пишет `<HOME>/Library/Application Support/fastmcp/oauth-proxy/<id>` внутри частной папки.
- **macOS:**
  - `startsProcess` управляет автоматическим обнаружением;
  - `ChatGPTLoopback(path:)`: Google `/`, ChatGPT `/auth/callback`;
  - обновление токена с запасом 300 s под `mutating`, тем же поколением;
  - `invalid_grant` — отзыв в Core, удаление из Связки ключей и «Войдите снова»;
  - дата тестового режима — `refresh_issued_at + 7 дней`;
  - удаление папки сервера — только когда ничего не выполняется.
- **Ручная проверка:**
  - установка 22,7–25,1 s, около 250 MB;
  - подменённые хэши колеса и сборки Python отвергаются;
  - адрес локальной сети отказывает;
  - вне частной папки ничего не пишется;
  - холодный старт около 2 s;
  - переименованная venv работает;
  - `tools/list` — 29,3 KB, 16 инструментов (15 в режиме OAuth 2.1).
