# ADR-005: сохранённый план и жизненный цикл дела

Статус: независимый пакет 07B по D56; Plan Simplicity Reviewer и Evidence Auditor приняли спецификацию 2026-10-19, замечание о точном completion impact исправлено и повторно проверено. Основания — D13/D17/D20 и принятая память ADR-004; полный 07 и инициативный помощник не объявляются готовыми. Реализован и принят после полного verify (8 tooling / 32 Rust / 13 Swift), сборки/подписи и Code Simplicity Review. Проверенная сборка сохранена в checkpoint07B; реальные автоматические предложения и весь билет07 не приняты.

## Граница

Настоящий ручной путь Swift → C → Rust/SQLite: записать план существующего дела, указать зависимости и проверки, сохранить известный точный промпт/ссылку, увидеть доступные шаги, скопировать сохранённый текст, отдельно завершить шаг или всё дело с итогом. «Не актуально» сохраняет дело и отключает инициативу. Это интерфейс исправления/управления собственной памятью, не требование вручную заполнять будущего помощника: извлечение плана и связывание по наблюдению остаются в полном 07.

План относится к одному общему делу; его шаги могут представлять разные задачи/агентов/источники с их точными ссылками. Зависимости между самостоятельными делами в этом пакете не добавляются; симметричное «связаны» из ADR-004 не превращается в зависимость. Общий D13 не считается полностью принятым. Нет отдельного движка волн, scheduler, автоматического исполнения, наблюдения, модели или production mock. Управление памятью доступно при остановленном помощнике; снятие ручной паузы не запускает отсутствующее облако.

## План и основания

Rust хранит шаги с постоянным положительным ID, ID дела, описанием, необязательными точным промптом и точной ссылкой, и пользовательским подтверждением завершения. Порядок отображения — стабильный ID; это не порядок исполнения. Зависимость — направленная пара разных живых шагов одного дела; дубли, неизвестный ID, self-reference и цикл отклоняются атомарно. Нельзя удалить шаг, пока на него ссылаются: пользователь сначала явно убирает эти зависимости. Это не делает последующие шаги доступными случайным каскадным удалением.

Каждая обязательная проверка имеет постоянный ID, ID шага, описание и результат `unknown / passed / failed`. Только явная пользовательская операция в этом пакете задаёт passed/failed с временем UTC и происхождением пользовательского подтверждения. Unknown не имеет подтверждения. Нельзя интерпретировать заметку об окончании агента как выполнение проверки или шага. Проверки относятся к условиям завершения своего шага: запуск последующего возможен только после завершения предшествующего и прохождения его проверок. Собственные ещё не пройденные проверки не запрещают начать работу над шагом, но запрещают отметить его выполненным.

Полнота плана хранится отдельно существующим `Completeness` (`unknown / partial / complete`). Новое дело — unknown. Пользователь явно подтверждает, что перечислены все известные зависимости; структурная правка шага/проверки/ребра переводит план в partial. Изменение результата проверки или подтверждения завершения не меняет полноту. Нет самостоятельного сохранённого ready: Rust при чтении вычисляет доступность из текущего состояния. При unknown/partial он показывает недостаточную полноту и не рекомендует следующий шаг; при complete возвращает все незавершённые шаги, чьи предшественники завершены и имеют только passed проверки. Пустой план не означает завершение дела. Несколько допустимых шагов остаются набором без выдуманного единственного порядка.

Пользователь может подтвердить известный шаг даже в частичном плане, если все его явно заданные предшественники завершены и проверки самого шага passed; это факт ручного подтверждения, не рекомендация неполного плана. Шаг без проверок не получает выдуманные проверки. Любая отметка выполнения явная; копирование текста не выполняет и не запускает шаг.

Изменение описания/промпта/ссылки/зависимостей шага, добавление/изменение/удаление его проверки или ухудшение её результата снимает подтверждение завершения этого шага и всех его транзитивных потомков. Их собственные результаты проверок сбрасываются в unknown, потому что прежнее подтверждение относилось к прежней работе; сами пользовательские заметки/источники не стираются. При явном результате passed→failed сохраняется заданный failed у этой проверки, остальные затронутые результаты сбрасываются. Снятие выполнения шага имеет тот же эффект. Завершение предшественника не подтверждает последующие автоматически. Повтор той же оценки passed/failed без изменения содержания не снимает выполнение. Изменение текста намерения также делает план partial и сбрасывает подтверждения всех шагов/проверок; связь с другим делом увеличивает ревизию, но сама не переписывает план.

Все операции проверяют ожидаемую ревизию владельца и атомарно увеличивают её. Отдельные ревизии шагов/проверок не нужны; удалённые ID терминальны, не переиспользуются. Чтение страниц возвращает ревизию снимка: UI не заменяет исходную ревизию старого черновика новой после reload. Алгоритм ограничен размером одного плана, без новой библиотеки графов и сохранённого кэша доступности.

## Завершение, полезные связи, возвращение к делу

`open / completed` и `initiative_suppressed` — независимые поля Rust. «Не актуально» выставляет suppression, сохраняет контекст и не меняет внешний источник. Явное включение напоминаний обратно доступно только пользователю. В остановленном приложении это сохранённая настройка для будущей 09, а не работающий таймер.

Только отдельная команда пользователя завершает дело. Все выполненные шаги, неактивность, завершение процесса или внешняя заметка не завершают его. Команда принимает непустой краткий итог, явно выбранные полезные связи с существующими делами и до 32 точных полезных ссылок. Не выбирает ссылки/содержание моделью. Завершение допустимо и при незавершённых шагах — пользователь может закончить или пересмотреть общее намерение; подтверждение явно сообщает об очистке подробного контекста. Проверка ожидаемой ревизии защищает от скрытой смены этого контекста.

Одна транзакция заменяет текст намерения итогом, сохраняет выбранные полезные связи/точные ссылки, очищает подробные сведения, сырые ключи источников, план/проверки/промпты и ненужные решения. Не хранить старый текст в скрытом архиве. Минимальные ID/отпечатки забывания ADR-004 остаются; другая действующая подтверждённая привязка того же источника к открытому делу продолжает работать. Для завершения вычисляется собственный точный impact: только соседние дела действительно удаляемых связей и удаляемых решений по сведениям. Сохраняемые выбранные связи в него не входят. Нельзя передать полный прежний deletion_impact, который включает и сохраняемые связи. Ограниченный completion-impact preview и команда завершения используют один предикат; внутри транзакции набор пересчитывается, недостающие/лишние IDs и устаревшие ревизии отвергаются. Только фактически затронутые чужие дела проверяются и повышаются ровно один раз; удаление ненужной связи не меняет соседнее дело без fence. Выбранные ссылки должны уже быть связанными делами; создание новой связи — отдельное существующее действие.

Завершённое дело показывает итог и полезные ссылки/связи; итог можно исправить или удалить дело. Добавление заметок/плана, перемещение туда сведений, импорт и явная привязка источника в completed отклоняются явным `TaskCompleted`, не считаются успешным импортом. Поздний исторический импорт после явного возвращения к делу всё ещё блокируют сохранённые отметки известных источников; новый пользовательский bind остаётся отдельным разрешённым действием по ADR-004.

Пользователь может явно вернуть дело в open: сохранённый итог становится текущим текстом намерения, полезные ссылки/связи остаются, план пуст/unknown. Старый подробный контекст не восстанавливается; UI говорит об этом до подтверждения. Suppression сохраняется: возвращение к делу само не включает напоминания. Изменение completed-итога не создаёт план и не восстанавливает источники. Удаление очищает также итог, ссылки и все новые записи содержания. Ошибка или предел ресурса при завершении сохраняет исходное дело целиком.

## Границы данных и ABI

Без новых зависимостей. Использовать существующие Store/Immediate transaction/TaskVersion, SQLite ограничения, parameter binding и ограниченные страницы. Схема 3 и ABI v3 заменяют версии 2 в коде; нет параллельного API, JSON transport или второй памяти Swift. Swift actor последовательно вызывает C вне UI; записи и байты принадлежат вызывающему. Fixed-width ID/enum/flags проверяются при FFI ingress; ошибки явные, без исходных текстов/ключей в логах. SourceEvidence/Origin ADR-004 не расширяется вымышленными модельными подтверждениями.

Лимиты одного дела: 64 живых шага, 8 живых проверок на шаг, 512 рёбер зависимостей и 32 полезные ссылки. По каждому новому виду идентичности до 100 000 строк с tombstone; рёбра до 100 000 глобально. Описание шага/проверки, промпт и итог — существующий предел 1..16 384 точных UTF-8 байт; ссылка — 1..2 048 UTF-8 без NUL. Optional отсутствует явно, пустое присутствующее значение недопустимо. Ссылка — сохранённый текст для копирования, не разрешение открывать произвольную схему URL. Ничего не trim/обрезать/генерировать. Все новые тексты/ссылки входят в существующие 64 MiB; ошибка сохраняет старые данные. Удаление работает при полном лимите без новой аллокации идентичности.

Списки шагов, проверок, зависимостей и полезных ссылок ограничены существующими 50 элементами/256 KiB с учётом ABI metadata; зависимые коллекции выдаются отдельными страницами, не неограниченно внутри шага. Максимумы в проверках задаются на Rust boundary, а не только UI. Число затронутых дел при завершении ограничено 1 023, как существующий deletion impact. Для завершения byte check считает конечное содержание транзакции, чтобы освобождение подробностей учитывалось корректно.

Swift использует существующий самостоятельный черновик с исходной ревизией; новая форма шага/проверки/итога принадлежит UI, не отдельному хранилищу. Save/discard/cancel при смене дела/формы и сохранение черновика при ошибке обязательны. Нельзя приклеить старый текст к новому выбранному ID. Кнопка копирования использует системный clipboard только по нажатию пользователя. Локализация EN/RU через Localization Mechanic; read-only Type Scaffolder сверяет выбранные типы перед зависимым кодом.

## Схема и проверенные сборки

Схема 1/2, чужая/повреждённая БД отклоняются read-only preflight до изменяющих pragmas/DDL; повторная проверка остаётся перед записью. Никакой автоматической миграции, удаления, скрытого нового пути или чтения пользовательских данных для теста. Новая пустая тестовая БД используется для приёмки. Проверенные сборки 06 и 07A сохранены в `target/checkpoints/Ambient-foundation-06.app` и `target/checkpoints/Ambient-memory-07a.app`, подписи PASS. Перед планированием 07B metadata-only проверка не обнаружила известный пользовательский каталог/БД. Это не разрешает удалять БД, если она появится позднее, и не доказывает проверенный перенос данных.

## Приёмка

TDD на настоящей временной SQLite и C/Swift: DAG/циклы/неизвестные ID, несколько готовых шагов, partial/unknown и пустой план, проверки/явное завершение, окончание одной части без закрытия дела, инвалидация потомков, точный промпт/ссылка, ревизии и старый черновик, suppression отдельно от завершения, restart, completion cleanup/полезные выбранные ссылки, atomically fenced foreign tasks/rollback/byte limits, completed ingestion refusal, reopen без возвращения старого содержания, забытая история после reopen, старые схемы/файл/WAL неизменны, терминальные IDs, строковые/постраничные/общие пределы. Реальные наблюдения и качество модели этими тестами не подменяются.

Полный `yarn verify`, сборка macOS `.app`, codesign и Code Simplicity Review. Визуальная проверка не запрошена; Windows и реальный перенос данных не заявлять. Полный 07 остаётся открытым; 09 получает лишь проверенное сохранение жизненного цикла/плана, а таймер, сигнал начала работы, карточки и отмена ещё отсутствуют.

## Проверенная опора реализации

Scout указал `memory_types.rs`, `schema.sql`, `Store::change`/fence, ABI v2 и Swift `MemorySession`/revision-bound draft. Librarian подтвердил пригодность существующих rusqlite 0.40.2 / bundled SQLite 3.53.2 и отсутствие нужды в новой зависимости. Read-only Type Scaffolder сверил новые состояния с `TaskVersion`, существующими лимитами и явным пользовательским происхождением.

Для рекурсивного SQL обхода использовать одну колонку ID и `UNION` (не `UNION ALL`), ограничивая все переходы своим делом. При максимуме 64 узла внутренний LIMIT 65 — sentinel: достижение 65 означает отказ, усечённый обход не доказывает отсутствия цикла. Проверка и запись внутри одной Immediate transaction; FK проверяют оба конца/принадлежность, транзитивный цикл проверяется отдельно. Подтверждено External Researcher по [SQLite WITH](https://www.sqlite.org/lang_with.html#queries_against_a_graph), [transactions](https://www.sqlite.org/lang_transaction.html#deferred_immediate_and_exclusive_transactions), [foreign keys](https://www.sqlite.org/foreignkeys.html), [rusqlite 0.40.2](https://github.com/rusqlite/rusqlite/blob/v0.40.2/src/transaction.rs#L114). Нативный буфер — [NSPasteboard.setString](https://developer.apple.com/documentation/appkit/nspasteboard/setstring(_:fortype:)); результат Bool проверяется.
