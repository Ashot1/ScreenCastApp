# ADR-011: выбранные локальные ветки как сведения дела

Статус:11A реализован и принят локально19 октября2026: verify8 tooling/99 Rust/50 Swift, feature Swift65, build/signature/review PASS. Schema6/sourceABI1; memory3/auth1/model2 сохранены. 06F принят локально; итоговые Plan Review и Evidence Audit — PASS после уточнения забывания, native проверки root и invalidation при изменении исключений. Независимая часть согласованной11 по D56; полная11, инициатива и новые коннекторы остаются открытыми.

## Problem Statement

Пользователь теряет незавершённую работу в локальных ветках. Сохранённое намерение уже может участвовать в помощи06F, но у приложения нет проверенного пути чтения настоящего локального источника. Запуск Git с read-only флагами сам по себе не ограничивает косвенное чтение конфигурации и объектов.

## Solution

Для выбранного открытого дела пользователь выбирает папку обычного Git-проекта, видит и задаёт исключения, затем явно запускает ограниченный обзор веток. Он видит найденные ветки, время наблюдения и ограничения обзора, выбирает одну и сохраняет её сведения в дело. В существующем06F можно включить это сохранённое сведение в точный preview и запросить помощь. Модель сопоставляет наблюдение с намерением; возраст, незавершённость и отсутствие PR не выдумываются из наличия ветки.

Источник не изменяется; приложение не запускает Git, не читает рабочие файлы, index, objects, историю коммитов или сетевые сервисы. Это законченный ручной путь одного нового источника. Фоновое обнаружение и доказательство «забытой работы» остаются полной11.

## User Stories

1. Я выбираю конкретный проект и вижу область чтения до начала обзора.
2. Я исключаю нужные относительные папки; эти исключения сохраняются для повторного выбора того же расположения.
3. Я вижу реальные локальные ветки и текущую связь HEAD, когда она доказана прочитанными данными.
4. Я отличаю пустой полный обзор от частичного, неподдерживаемого или неудачного.
5. Я явно выбираю ветку и дело; приложение не придумывает их связь.
6. Я сохраняю датированное сведение и могу использовать его вместе с намерением/планом в06F.
7. Я вижу, что сохранённое наблюдение не доказывает нынешнее состояние проекта.
8. Пауза, отмена, смена дела, изменение исключений или закрытие окна запрещают поздний импорт.
9. Я могу удалить сведение; прежний источник не восстанавливает его без нового явного действия.
10. Перенос проекта не маскируется под доказанное продолжение того же физического объекта.
11. Неподдерживаемый репозиторий не даёт ложного «веток нет» и не вызывает расширения доступа.

## Implementation Decisions

### Владельцы и текущие зависимости

Core владеет настройками источника, допуском операции, Git-разбором переданных байтов, нормализованным наблюдением, SourceKey, привязкой/памятью и включением сведений в помощь. Native владеет NSOpenPanel, directory/file FD, ограниченным чтением и UI. Один Store, прежняя память и журнал запросов. ChatGPTCoordinator остаётся единственным владельцем облачной сессии; новый источник не получает токен и не заводит второй облачный coordinator.

После принятия06F: schema6 заменяет5 с прежним exact-schema read-only отказом без миграции/сброса/смены пути. MemoryABI3/authABI1 сохраняются; новый local-source ABI1 отделён от modelABI2. Входы типизированы, caller-owned buffers; не вводить входной JSON или произвольный путь чтения в Rust. ModelABI2 сохраняется, если существующие selected-evidence IDs достаточны; изменение только при доказанной необходимости, до dependent edits.

### Расположение, исключения и разрешение

Единица настройки — явно выбранное расположение worktree, не физический inode. После выбора native покомпонентно открывает root без symlinks/разрешения Finder aliases и получает фактическое расположение через fcntl(F_GETPATH) с буфером MAXPATHLEN. Это только явная настройка области и метаданные root, не чтение Git-содержимого. Успех требует NUL внутри буфера, непустого strict UTF-8 и абсолютного пути; ошибка/непредставимый путь отвергается, не обрезается. Фактический путь показывается до подтверждения области и становится точной identity расположения, поскольку написание URL панели может отличаться. Core допускает до4096bytes, native дополнительно ограничен системным MAXPATHLEN. Нет поиска родительского репозитория или восстановления grant после перезапуска.

Перед чтением и принятием результата повторный F_GETPATH удерживаемого root должен совпасть с исходным; также покомпонентно nofollow открывается исходный путь, и его st_dev/st_ino сравниваются с удерживаемым root. Ошибка, отсутствие или несовпадение отменяют результат. Один F_GETPATH недостаточен: проверенный fixture после rmdir вернул прежний путь. Swift6 проба с deployment14 скомпилирована и обнаружила rename/replacement на текущем macOS27; реальное macOS14 hardware не проверено. Эти проверки не исключают move-out-and-back между проверками или изменения после них.

Core сохраняет до64 настроек расположений: точный путь и до16 исключённых относительных префиксов папок, каждый до1024bytes; вся запись не более16KiB. Префиксы состоят из непустых компонентов, без `.`, `..`, абсолютного пути и NUL; сравнение по границам компонентов, не по строковому startsWith. Суммарные настройки не более1MiB. Сохранение нового набора атомарно повышает его revision и отменяет действующий обзор. Исключения относятся к расположению и не обещают следовать за переименованным физическим объектом. Для удаления сохранённой настройки предусмотрено явное действие с понятным предупреждением, что её исключения тоже удалятся; удаление отменяет активный обзор, но не удаляет память дела скрытно.

Выбор папки и настройка области не запускают чтение её содержимого. Явное «Посмотреть ветки» создаёт один временный Core grant: task ID/revision, root settings revision, current connection epoch, операция/cancellation generation. Он не сохраняется как разрешение фонового доступа. Cloud High capability, current session/report и отсутствие паузы обязательны до первого source read; управление настройками и памятью остаётся доступным без облака. No-credit/Fast правила06F неизменны.

Native получает разрешение Core перед каждой ограниченной порцией I/O. Это точка допуска, не обещание отозвать уже начатый syscall. Pause/revoke/cancel закрывают следующий допуск и публикацию немедленно; принятый I/O остаётся занятым до фактического возврата и закрытия FD. Не освобождать worker по одному cancel и не добавлять бесконечную очередь. Один local read operation, один bounded observation; новый обзор busy до cleanup. UI не блокируется синхронным I/O. Перед сохранением проверяются task/root revisions, epoch, pause и cancellation.

Grant действует для закреплённого объекта выбранного каталога только в текущей операции. Чтение покомпонентное относительно directory FD, без следования косвенным путям. Исключения проверяются до открытия каждого дочернего пути. Detectable root replacement/move/metadata change отменяет результат. Это application-level ограничение, не системная sandbox: открытый каталог может быть перемещён, hard link может появиться после проверки. Не обещать атомарный путь или устранение всех недетектируемых файловых гонок. App Sandbox/helper не меняются.

### Разрешённые данные и пределы

Поддерживается только выбранный обычный worktree с непосредственным `.git`-каталогом. Открытие через gitdir-файл, commondir, reftable, неизвестные обязательные extensions, неподдерживаемый repository format и config includes даёт явный unsupported/partial результат без следования ссылке. Не читать global/system/environment config, alternates, objects, index, hooks, logs, remotes или рабочие материалы. Нет Git CLI, Repository::open, ODB и выполнения команд проекта.

Native открывает компоненты через openat с O_NOFOLLOW/O_DIRECTORY/O_CLOEXEC; файлы — O_RDONLY/O_NOFOLLOW/O_NONBLOCK/O_CLOEXEC, затем fstat regular-file и st_nlink==1 до первого чтения. Сверяет dev/ino/size/nanosecond mtime/ctime до/после; обнаруженное изменение отвергает этот обзор. Это наблюдение в интервале времени, не атомарный Git snapshot. Системный read не имеет гарантированного короткого срока даже на local volume; cancellation lifetime остаётся честным.

Allowlist: `.git/config`, `.git/HEAD`, `.git/packed-refs`, прямое ограниченное дерево `.git/refs/heads`. Проверка наличия неподдерживаемого `.git/commondir` выполняется без чтения цели. Config до64KiB, HEAD/каждый loose ref до4096bytes, packed-refs до512KiB. Общие прочитанные bytes до1MiB; не более256 файлов,256 каталогов,4096 directory/packed entries,256 branch records, глубина16, полный относительный путь2048bytes. Каждый предел применяется до следующего чтения/накопления; один дополнительный byte может использоваться для обнаружения превышения и входит в общий лимит. Никакой скрытой обрезки.

Превышение/исключение/недоступность даёт явную причину неполноты; unsupported format/config/read race не превращаются в нормальный список. При частичном обходе допустимы только действительно прочитанные факты с общей Partial, без утверждений об отсутствии остальных веток. Исключение веточного пути применяется также к его логическому refs/heads имени; при любом исключённом поддереве refs/heads весь packed-refs консервативно пропускается, чтобы не читать исключённые ветки из общей упаковки. HEAD, указывающий исключённую ветку, не публикует её имя или отношение как основание другой ветки. Данные и ошибки без raw config/ref bytes в логах. Время начала/окончания наблюдения задаёт native; Core проверяет форму/порядок, не выдаёт локальные часы за доверенное внешнее время.

### Готовые Git-парсеры

Использовать только публичные byte-only API проверенных `gix-ref0.69.0`, `gix-hash0.28.0`, `gix-config0.62.0`. Default features отключены; у ref/hash включены sha1/sha256. File::from_bytes_no_includes, loose Reference::try_from_path(FullName,bytes,Kind), packed::Iter::new(bytes,Kind). Эти входы скомпилированы на Rust1.99.1 в изолированной пробе. Не заменять их самописным Git-парсером и не использовать соседние файловые API.

Config определяет поддерживаемый format/hash/ref storage; includes и неизвестные extensions не игнорируются молча. Packed input проверяется на порядок/дубли, все ошибки итератора обрабатываются; loose refs имеют приоритет над packed ровно для того же full ref. HEAD может быть direct/detached или symbolic; unborn и недоступная цель различаются. Symbolic branch ref вне непосредственно прочитанных local refs не разрешается через файловую систему; недоказанное отношение HEAD отмечается unknown. Циклы/ограничение разрешения symbolic связей дают неполноту, не выдуманный OID. Данные названий strict UTF-8, FullName validation; непредставимое имя явно ограничивает охват.

Core нормализует только exact full ref, tip OID если доказан, отношение HEAD если доказано, observation interval, coverage/reasons и provenance. OID не доказывает наличие объекта, дату/автора коммита, чистоту worktree, незавершённость или отсутствие PR. В интерфейсе нет эвристики «старая/забытая» по этим данным.

### Источник памяти и помощь06F

SourceKey: namespace `local-git-branch-v1`; scope — SHA-256 отдельного версионированного length-prefixed кодирования exact выбранного root path; object ID — exact validated full ref. Версия — доказанный tip OID, если есть. Hash решает ограничение scope256bytes, не скрывает угадываемый путь. Один и тот же путь/ref сохраняет ключ при повторном grant, новый OID не создаёт новую идентичность. Изменившееся расположение/ref — новый ключ; физическая непрерывность и неизвестные aliases не угадываются. Это соответствует ADR-004, который обещает забывание известных точных ключей, а не узнавание всех физических aliases.

Нет автоматической привязки нового расположения или ветки. Пользователь выбирает одну ветку, видит полный нормализованный текст/место/время/полноту и отдельной кнопкой сохраняет её к выбранному делу. Сохранение из Core-owned observation, а не отредактированного native текста; перед сохранением повторная проверка grant/task/root revisions. Явная привязка и историческое обновление остаются разными существующими операциями. Удалённая пара «дело + точный ключ» терминальна: даже bind_source возвращает Deleted. Явно связать тот же ключ можно с другим живым делом; новый ключ после изменения расположения/ref также требует отдельного действия. Late historical result для forgotten key остаётся Forgotten, не оживляет ID или пользовательское исправление. Не менять существующий договор ради повторной привязки к той же удалённой паре.

Сохраняется одно сведение существующего SourceEvidence на branch/task, а не архив raw config/refs. Текст ограничен16KiB и ясно описывает датированное наблюдение, exact root/ref, OID/HEAD и ограничения; observation interval/coverage не скрываются. Результаты модели не сохраняются как факты. Неподдерживаемый/неудачный обзор без доказанной ветки не создаёт фиктивный источник.

06F получает ровно выбранные сохранённые manual notes и сведения зарегистрированного local-git-branch-v1 источника; неизвестные namespaces остаются запрещены. Полный immutable context/preview включает source identity/version/время/полноту/тип утверждения. Общий предел32 выбранных evidence и256KiB/320KiB сохраняется. Передача — отдельное явное действие06F после сохранения, без hidden source reads и без второго транспорта/журнала. Сохранённое наблюдение может использоваться как историческое основание; оно не объявляет текущее состояние репозитория и не требует фиктивного watcher. Изменение/удаление памяти/плана, pause/epoch/cancel по-прежнему инвалидируют snapshot/receipt/copy. Source grant не становится разрешением на будущие чтения после завершения обзора.

Существование namespace само по себе не разрешает отправку. Prepare и dispatch06F сопоставляют scope с текущей сохранённой настройкой расположения; отсутствующая/удалённая настройка или исключённый root/.git/логический branch path запрещают использование source evidence. Исключение общих metadata путей также не должно передавать уже производные от них факты: для первого среза такое ограничение консервативно запрещает использование сведений этого root в06F до снятия ограничения. Snapshot/receipt сохраняет ревизии всех использованных настроек; изменение/удаление любой инвалидирует prepare/dispatch/result/copy, даже когда task revision не изменилась. Историческое сведение остаётся доступным локально; эта проверка не читает файлов и не восстанавливает grant. Повторный prepare снова проверяет актуальную область, не принимает прежнюю ревизию как разрешение.

UI сохраняет независимые черновики, показывает чтение/неполноту/ошибки, позволяет отменить. EN/RU обновляются одновременно. Меню не объявляет полноценное наблюдение работающим по одному ручному обзору.

## Testing Decisions

Высокая проверяемая граница: настоящий временный каталог с Git metadata → native FD-reader → C/Core byte-parsers → SQLite SourceEvidence → существующий local HTTP/SSE06F → grounded result/copy. Test-only HTTP/credentials допустимы, production mock нет. Temporary fixture создаётся тестом; не запускать Git и не читать пользовательские проекты. До/после сравнить fixture contents, mtime/mode/identity и отсутствие новых файлов/lock files/записей адаптера. Access time может обновить сама ОС от чтения и не считается записью адаптера.

Meaningful RED→GREEN: direct/symbolic/unborn/detached HEAD, loose+packed precedence/SHA1+256; malformed/duplicate/unsorted/config includes/gitdir/commondir/reftable; exact prefixes/symlinks/hardlinks/FIFO/exclusions; bounds/partial vs empty; modified root/ref during read; pause/closed cloud gate ноль source reads, cancel/cleanup/late import; exact same key after regrant and changed OID, forgotten/history versus explicit new binding, renamed location never automatic binding; stale task/root revision; manual+source exact preview/citations и delete-before-copy. Проверять стабильное внешнее поведение, не внутренние setters.

Отдельно: исключение/удаление настройки до preview, между preview и POST и перед copy блокируют использование source evidence, не удаляя само историческое сведение. Проверить packed обход исключённого loose-поддерева, повторное открытие удалённого root при успешном устаревшем F_GETPATH и отказ revival той же удалённой пары даже через explicit bind.

Полный yarn verify, app build/signature, code simplicity review, test-hook absence во всех Mach-O app, неизменность всех восьми checkpoints после принятого06F. Scoped Type Scaffolder read-only перед типами, Localization Mechanic, Librarian/Scout reuse текущих фактов. Native permission dialogs, реальные проекты, новые model/Jev requests, визуальный UI и Windows не проверяются и не объявляются пройденными.
