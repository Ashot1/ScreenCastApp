Последние поправки review убрали второй native deadline модельной проверки и отделили ошибку чтения журнала от ошибки сохранения выполненной попытки. Оба случая воспроизведены и проверены. ## Результат и границы

В настройках Ambient пользователь проверяет собственное подключение ChatGPT одной явно запущенной попыткой. Приложение отправляет фиксированный синтетический текст, проверяет фактически возвращённые модель/effort/tier и показывает результат вместе с известным либо неизвестным потреблением. История попыток переживает перезапуск. Дела, файлы, экран и голос не читаются и не передаются.

Это реальный путь Swift → C → Rust → HTTP → Rust/SQLite → Swift. Локальные тесты используют настоящий HTTP и временную SQLite; тестовые провайдеры не попадают в production. Проверка не является работающим анализом, не включает источники и не закрывает полный06/G5. Даже успешное подключение оставляет помощника остановленным до интеграции остальных обязательных возможностей.

Проверка относится к управлению восстановлением подключения, доступному при его недоступности. Ручная пауза запрещает новую попытку. Нет автоматического вызова при старте, открытии Settings, смене учётных данных или снятии паузы; нет retries, refresh внутри модельной попытки, fallback, Jev или платного API-ключа.

## Пользовательский путь

1. Сохранён собственный вход нативного Ambient; отсутствующая или истёкшая сессия требует существующего входа/обновления06B. Регистрация стенда и Codex credentials не используются.
2. Пользователь один раз за запуск сообщает, что проверил запрет дополнительных списаний для этой нативной регистрации в ChatGPT. Подпись прямо говорит, что это сообщение пользователя, а не прочитанное API состояние. Флаг живёт только в существующем ChatGPTCoordinator, без новой копии identity, таблицы или Keychain-поля. Он не переносится со стенда, сбрасывается при выходе, новом входе/смене подключения и перезапуске процесса. Успешный refresh той же проверенной привязки его не сбрасывает. Отдельный POST по-прежнему требует явного запуска; выполнение попытки расходует её одноразовый допуск, а не этот флаг. Кнопка управления лимитами ведёт в официальный ChatGPT интерфейс, не обещая недокументированного deep link.
3. Кнопка сообщает: одна попытка запросить Luna Low Fast через собственное подключение ChatGPT, только проверочный текст; фактический режим ещё проверяется, запрос может потреблять включённый доступ. Она не обещает подтверждённый Fast или бесплатность по одному факту входа. Ручная пауза, отсутствие сессии/сообщения о запрете кредитов, незавершённая операция, закрытие или ошибка журнала запрещают dispatch.
4. Во время работы доступны отмена и глобальная пауза. UI различает запрос остановки и фактическое завершение. Новый запрос нельзя начать до возврата предыдущего и сохранения его результата либо сообщения об ошибке сохранения.
5. Результат различает: конфигурация подтверждена; конфигурация отличается/не подтверждена; ошибка поставщика/доступа; неверный/неполный ответ; отмена/таймаут; локальная ошибка до отправки. Usage отображается независимо от успеха конфигурации.
6. Видны последний исход и агрегаты этого нативного журнала: число попыток, известные input/output/total tokens, число неизвестных потреблений. Это не остаток подписки, не доллары и не общий расход аккаунта. Старые результаты стенда остаются отдельными неизменными доказательствами.

## Владение

Core владеет допуском явной попытки, сохранёнными состояниями/счётчиками и чтением ручной паузы из прежнего Store. Providers владеет точным запросом и проверкой ответа. Bridge связывает один Store с одной короткоживущей операцией, удерживает её до фактического возврата и не держит registry памяти во время HTTP. Native владеет UI и единственным существующим ChatGPTCoordinator/Keychain, предоставляет access token только принятой операции и не сохраняет второй набор credentials.

Не создавать общий scheduler, универсальный provider framework, второй memory store, зеркало подписочной квоты или денежный ledger Jev. Не расширять allowlist существующего OIDC Transport модельными адресами. Использовать тот же проверенный шаблон reqwest/Tokio в узком отдельном модельном transport; отсутствие общего helper допустимо, если его введение только связывает разные контракты.

## Допуск, сохранение и остановка

Использовать существующую SQLite Store; схема4 заменяет3 без миграции/сброса пользовательского файла. Неподдерживаемая схема отвергается прежним read-only preflight, включая сохранность WAL. Контрольные сборки остаются неизменными. Перед планированием06D проверено только наличие production-каталога/БД: оба отсутствуют; пользовательские данные не читались.

Журнал содержит только фиксированное назначение connection_check, монотонный ID, время UTC, этап отправки, исход, ожидаемую конфигурацию, проверенную фактическую конфигурацию и usage при его наличии. Нет токенов доступа, account claims, промптов, ответа модели, HTTP body или путей. Фиксированные enum предпочтительнее произвольных диагностических строк. Не более1024 записей, ограниченные строки и не более1MiB данных журнала; заполнение запрещает новую попытку, не удаляет неизвестные записи. Суммы вычисляются проверяемо, переполнение является ошибкой.

До сетевого dispatch Core атомарно проверяет ручную паузу/одноразовый допуск и сохраняет запись возможной отправки. При невозможности commit POST запрещён. Crash между записью и сетью сохраняет консервативное unknown, а не выдаёт неподтверждённое отсутствие расхода. Доказанный отказ до допуска не создаёт отправленную попытку. На старте незавершённая сохранённая попытка становится unknown и не отправляется повторно.

Один явный запуск разрешает максимум один POST. Новая отдельная явная проверка создаёт новую запись и не меняет предыдущие unknown. Неизвестное потребление подписки не переводится в доллары и не считается нулём. Автоматических повторов нет. UI не скрывает неизвестные записи при следующем успехе.

Пауза отменяет связанную операцию и закрывает её допуск. Конкретная граница dispatch должна иметь определённую точку принятия: повторно проверить текущую паузу и cancellation непосредственно перед сетью. Уже принятая отправка может закончиться позже; это не разрешает новую помощь. Сохранённый валидный usage может уточнить расход после отмены/выхода, но успех старой операции не подтверждает доступность новой сессии и не включает анализ.

Выход, отмена, смена сессии и shutdown используют существующего владельца06B: закрывают допуск, инвалидируют UI-результат старой сессии и ждут действительного возврата Rust/cleanup перед освобождением операции. Не возвращать access token произвольным UI-клиентам. Отдельная model operation нужна для отдельного протокола, но второй session manager не нужен. Пауза/история доступны независимо от полного чтения дел, по06C.

Memory close не может уничтожить Store, пока принятой попытке нужно сохранить итог. Фиксировать порядок registry locks и не держать общий mutex во время HTTP/ожидания. Буферы FFI проверяются до принятия одноразовой операции. Новая узкая model ABI1 не передаёт JSON, SDK objects или Swift callbacks; прежние layouts memory ABI3 и auth ABI1 не меняются. Новые коды ошибок/lifecycle-условия документируются и проверяются в реальном Swift–C–Rust пути.

## Запрос и обработка ответа

Endpoint — POST `https://api.openai.com/v1/responses`. Bearer только из собственного готового входа; Content-Type application/json, Accept text/event-stream. Без organization/project headers, redirects и скрытых retries. Никаких дополнительных GET моделей: каталога недостаточно для подтверждения фактического Fast, а проверка ответа выполняется по закреплённой конфигурации.

SIWC не обещает Fast отдельным полем своей документации; priority взят из официального клиента и каталога проверенного аккаунта, а прежние реальные ответы вернули default. Поэтому эта попытка проверяет доступность выбранной конфигурации, а не опирается на уже доказанный Fast. Общий API-тариф Fast не переносится на SIWC и не используется для расчёта долларов. Настройка запрета дополнительных списаний проверяется пользователем для собственной native-регистрации; локальный флаг явно остаётся user_reported.

Фиксированный запрос: model=gpt-6-luna, reasoning.effort=low, service_tier=priority, store=false, stream=true, tools=[], input=[user: «Reply exactly: AMBIENT_OK»]. Нет system item, max_output_tokens, temperature, metadata, previous_response_id. Нет произвольного input снаружи или переключателя endpoint в production. High будет отдельной последующей проверкой; Low не доказывает High.

Transport использует имеющиеся reqwest0.12.28/rustls и Tokio1.53.3. Один current-thread runtime на вызов; client/response не переживают runtime. Отключить retries и redirects явно. До подключения проверить cancellation; проверить его между чтениями. Connect≤5s, read≤10s, вся операция≤60s по монотонному времени. Отмена должна прерывать ожидание сетевого чтения доступным штатным механизмом, а busy сохраняется до настоящего cleanup. Deadline/разрыв клиента не обещают остановку удалённой генерации или максимальное число серверных токенов.

Поток ограничен2MiB, отдельный SSE frame512KiB,4096 событиями и8 completed items суммарно64KiB; текст результата≤256UTF-8 bytes. Проверки выполняются до накопления. HTTP error body≤16KiB и не записывается в журнал. Лимиты локальные, не заявленные лимиты OpenAI. Произвольные ошибки транспорта/SDK отображаются закрытыми кодами без секретов.

Использовать Response.chunk(), а не неограниченное bytes/read_to_end. serde_json уже есть в lockfile; сделать нужной обычной зависимостью, отдельная SSE-библиотека не обязательна. Разбирать CR/LF/CRLF и многострочные data, проверять UTF-8 после сборки полного фрагмента; конечный неполный frame/повреждённый JSON не становится успехом. Delta не сохраняются как журнал. Отсутствующий MIME допустим только при строгом SSE разборе; явно иной MIME — отказ.

Успех требует response.completed, полного согласованного набора items и точного текста AMBIENT_OK. Уникальные непрерывные output_index; незавершённые/конфликтующие/повторные items отвергаются. При пустом terminal.output допустимо восстановление из output_item.done, подтверждённое настоящим стендом01. Непустой terminal.output сверяется с наблюдёнными done items. response.failed/incomplete/error/EOF без completed не становятся успехом; учитывать отдельные ошибки квоты внутри SSE.

Фактические model=gpt-6-luna, reasoning.effort=low и tier=priority либо fast обязательны для подтверждения. Default, отсутствие значения или другая модель — неподтверждённая конфигурация. Requested и actual не подменяются друг другом. Не оценивать внутренние рассуждения модели по метаданным effort.

Проверять usage как неотрицательные целые с checked суммами, total=input+output; вложенные counters не превышают соответствующих итогов. Валидный usage сохраняется даже при configuration mismatch/неверном синтетическом ответе. Отсутствующий, противоречивый или недостоверный usage остаётся unknown. Ошибка сохранения результата не стирает исходную durable unknown запись.

## Проверка

TDD через реальные временные SQLite, реальный локальный HTTP и существующие native test seams: один POST; запреты до dispatch; лимит/ошибка записи; crash/reopen unknown; последующая отдельная попытка не стирает неизвестный расход; mismatch с известным usage; valid completed; empty terminal.output; malformed/duplicate/conflicting items; ошибки SSE/квоты; неверные usage; chunked/oversize/stall/timeout; отмена до/во время HTTP; pause/signout/shutdown и отсутствие позднего успеха; busy до фактического cleanup; old schema/WAL неизменны. Test-only endpoint/keychain fixtures не включаются в production.

Сохранить прежние memory/auth/pause проверки. Нужны Scout, Librarian, Researcher, Type Scaffolder read-only, Endpoint Registry Mechanic для проверенных констант, Localization Mechanic EN/RU и Code Simplicity Reviewer готовой логики. Полный yarn verify, native app build/signature и сохранность всех пяти checkpoints. UI/настоящий аккаунт/Windows/macOS14 hardware не считать проверенными без отдельного исполнения.

Пользователь разрешил целевые subscription tests по D57. В этом пакете live POST не выполнялся: собственный native consent и no-credit настройка ещё не подтверждены; разрешение на тесты само по себе не доказывает эти факты. Журнал стенда с7POST/1021known tokens/3unknown и бюджет Jev не изменяются. После локальной приёмки отдельно фиксируется, что осталось для первого настоящего native запроса.
