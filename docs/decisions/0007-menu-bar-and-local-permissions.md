# ADR-007: индикатор, пауза и локальная проверка прав

Статус: независимый пакет06C реализован и принят после Plan Simplicity Review/Evidence Audit и code review. Тред `01a151e0-47d5-7bd0-bc60-d8e67116cd63` завершён. Итоговые verify/build/signatures exit0: 8 tooling / 46 Rust / 33 Swift tests; координатор прочитал фактический общий operation/shutdown путь. Основания — согласованные индикатор/пауза/настройки и D56, а не новая функция офлайн-помощника.

## Результат и граница

В строке меню macOS всегда доступен индикатор Ambient, сохранённая ручная пауза, открытие памяти и настроек, обычный выход из приложения. Для проверки состояния и паузы не нужно открывать память. Настройки по кнопке проверяют текущие Screen Capture и Accessibility права самого процесса Ambient, без запросов разрешений и чтения содержимого.

Анализ остаётся остановленным: production Responses/проверенный Fast/наблюдение ещё не соединены. Сохранённый вход, разрешения ОС и снятие ручной паузы не означают работающий анализ. Индикатор не показывает Running. В этом пакете нет модели, capture, источников, фонового опроса, авто-восстановления, автозапуска при входе в macOS, новой БД или фиктивного режима помощи. Эти полные критерии06 остаются открытыми. Ненужный пока admission API не вводится: у него ещё нет реального потребителя; он появится с первым чтением/dispatch.

## Владение и штатные механизмы

Один `AmbientAppDelegate.model` уже используется окном с ID `memory` и Settings. `MenuBarExtra` получает тот же объект, не создаёт AssistantModel/MemorySession/Store. Используются SwiftUI MenuBarExtra и openWindow(id:) (macOS13+) и SettingsLink (macOS14+), доступные при текущем минимуме macOS14. Обычный NSApplication terminate должен проходить через delegate и ждать завершения memory/auth операций; меню не создаёт свой shutdown. При приёмке06B координатор проверил actual delegate: он ждёт model.close и chatGPT.shutdown, а auth shutdown — принятый Rust вызов и закрытие всех listener connections/handle. Локальные lifecycle tests и итоговый build прошли; этот путь сохраняется в06C.

Core остаётся единственным владельцем сохраняемой ручной паузы. Текущие `ambient_v3_manual_pause` и `ambient_v3_set_manual_pause` достаточны; новых Rust/ABI функций или schema version нет. Статус входа остаётся у владельца06B, его credentials/поколения не копируются в память и не перечитываются ради TCC. Индикатор UI сочетает сохранённую паузу с фактом отсутствующего рабочего анализа; это не второй runtime policy engine.

## Пауза без загрузки содержания

Сейчас `toggleManualPause` требует MemorySnapshot и перечитывает страницы памяти; до snapshot она ничего не делает. Это заменяется узким чтением через тот же MemorySession/handle. `MemorySession.manualPause()` читает existing ABI, проверяет 0/1 и возвращает Bool. Существующий setter остаётся единственной записью.

У `AssistantModel` одна наблюдаемая проекция `manualPause: Bool?`; nil означает, что значение ещё не получено, а не отсутствие паузы. `manualPause` удаляется из MemorySnapshot и из полного memory load. Начальное чтение, явное перечитывание и переключение паузы меняют только эту проекцию, не snapshot/выбранное дело/страницы/черновик. При успешной записи показано подтверждённое значение; ошибка записи сохраняет прежнее, ошибка первого чтения сохраняет nil и видимую ошибку. Старый API/дублирующее поле не сохраняются ради совместимости.

Пауза использует тот же единственный отслеживаемый путь операций `busy/inFlight/closing`. Его результат может различать memory snapshot и pause value (частный UI-result, не новый доменный протокол). Не добавлять отдельную неотслеживаемую pause Task, второй сериализатор или цикл опроса. Close ждёт принятую FFI работу и не публикует позднее состояние после закрытия; запрос отмены не является доказательством завершения.

Начальная загрузка меню и появление окна могут совпасть. Они должны присоединяться к одному принятому начальному чтению, а не отбрасывать загрузку окна из-за busy: после чтения паузы окно действительно получает свой snapshot, меню само не запрашивает содержание. Применение результата и освобождение busy выполняются до завершения общей ожидаемой операции. Параметры отложенного reload, включая допустимость замены черновика, вычисляются после ожидания начального чтения; решение, принятое до await, не применяется к изменившемуся редактору. Пока пауза неизвестна, её переключение выключено; обычные повторные UI мутации сохраняют существующее правило одной операции. Не вводить новую постоянную очередь/планировщик ради этой стартовой зависимости.

## Строка меню и настройки

Label содержит доступное текстовое имя Ambient и состояние, а не одну недоступную для чтения иконку. Известная manualPause=true показывает «На паузе»; false показывает «Остановлен — анализ не подключён»; nil показывает неизвестное состояние сохранённой паузы при остановленном анализе. Успешный вход06B не меняет это на Running. Пункт паузы использует одну команду с окном/настройками, выключен при неизвестном значении, busy или closing. Ошибка доступна в меню/настройках и не выдаётся за выполненное действие. Открытие окна не меняет самостоятельный черновик, выбранное дело и страницы.

Настройки показывают два независимых локальных результата: Screen Capture и Accessibility. До явной кнопки «Проверить разрешения» они «Не проверено». При каждом нажатии снова выполняются `CGPreflightScreenCaptureAccess()` и `AXIsProcessTrustedWithOptions` с prompt=false; true/false означает только предоставленный/не предоставленный доступ. Эти APIs не различают все причины отказа, поэтому «ещё не спрашивали», «запрещено пользователем» и «отозвано» не выдумываются. Самостоятельного фонового обновления и чтения других приложений нет; изменение системных настроек видно после повторной кнопки.

Preflight не вызывает CGRequestScreenCaptureAccess, AX prompt=true, ScreenCaptureKit capture, AX UI element read или permission deep links. Не добавлять usage strings для отсутствующего capture. Результаты не сохраняются на диск и не означают доступность полного текста/границ сайта/папки или согласие на облачную передачу. Auth/Keychain лишний раз не читается этим действием. Важно сохранить настройки входа06B и уже работающий путь памяти.

## Приёмка и передача

Один владелец native пакета после освобождения06B: `src/platforms/macos/**`, связанные build/test файлы при необходимости, module README и раздел06C issue06. Core/bridge/provider protocol не менять; общий статус/product/privacy/ADR обновляет координатор. Важный Swift код пишет GPT-6.1 Sol. Использовать принятые Scout/Librarian/read-only Type Scaffolder результаты; перед конкретными изменениями non-UI declarations Type Scaffolder только на чтение; новые тексты через Localization Mechanic во всех EN/RU. Code Simplicity Review готовой логики обязателен.

Значимые TDD случаи: pause-only чтение/запись на свежей модели при snapshot=nil и повторное открытие реальной временной SQLite; отсутствие смены snapshot/черновика/страниц при паузе; ошибки чтения/записи без ложного false/успеха; совместный старт меню/окна без потерянной загрузки или дублированного чтения содержания; занятая/закрывающаяся модель; close ждёт принятую pause операцию и не публикует позднее; повторная проверка прав заменяет только свой локальный результат. Машинно-зависимое значение TCC не фиксировать в тесте как обязательное granted/denied; тестовые doubles не попадают в production.

Полный yarn verify, macOS build/codesign, сохранность checkpoints06/07A/07B/06B. Визуальная macOS menu/focus/Spaces проверка не запрашивалась и не объявляется выполненной сборкой; Windows и macOS14 hardware отдельно не проверены. Приложение не запускать для автоматического UI прогона. Ни одна проверка пакета не отправляет model/Jev запрос, не открывает browser consent и не запрашивает TCC. Реальная полезность индикатора в ежедневной работе ещё требует пользовательской эксплуатации.

## Проверенная реализация

Приняты menu/shared model, отдельная pause projection, присоединение initial read, сохранность draft/pages и ожидание принятой операции до close. Проверены полный verify, app build и подписи текущей app/четырёх прежних checkpoints; их36 файлов побайтово сохранены. Координатор создал `target/checkpoints/Ambient-controls-06c.app` и проверил подпись.

Явный prompt=false сохранён. SDK27 импортирует kAXTrustedCheckOptionPrompt как изменяемую C-глобальную переменную, которую strict Swift6 запрещает читать напрямую. Локальный static-inline accessor возвращает заимствованный системный ключ с CF_RETURNS_NOT_RETAINED; Swift создаёт штатный словарь с false. Type Scaffolder проверил владение, compiler — импорт CFString, nm всех executable Mach-O images — отсутствие нового экспортируемого accessor. Core и публичные memory/auth ABI не изменены. Nil-options не выбран: исследование первичных Apple docs не подтвердило гарантию эквивалентности false.

Scout/Librarian, Type Scaffolder read-only, Localization Mechanic, Researcher и Code Simplicity Reviewer выполнены; code review без замечаний. Новых model/Jev запросов нет; visual UI, реальные TCC/consent/refresh/ACL, macOS14 hardware и Windows не проверены. Полный06 остаётся открытым.

## Проверенная опора

- Scout: `AmbientApp.swift` — единый delegate.model, Window memory, Settings; `AssistantModel.perform/close/toggleManualPause` и существующий MemorySession setter; начальный snapshot=nil действительно блокирует старую команду.
- Librarian: installed SwiftUI interface подтверждает MenuBarExtra/openWindow и SettingsLink при macOS14; CoreGraphics/AX headers — no-prompt preflight. Для одного preflight новый capture usage string не нужен.
- Type Scaffolder: глобальная пауза не относится к снимку содержимого; одна UI проекция и общий tracked operation result устраняют две копии и ненужное перечитывание дел. Новая ABI/БД не нужна.
- Независимый Plan Simplicity Reviewer: без подтверждённого cloud runtime реальное наблюдение нарушило бы полную остановку; следующий пакет должен показывать реальные условия и сохранять управление, не притворяться работающим анализом. Положительное admission пока не имеет production потребителя.
