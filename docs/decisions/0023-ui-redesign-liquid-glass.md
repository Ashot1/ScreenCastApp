# ADR-023: новый интерфейс macOS по дизайну «Ambient · финал»

Статус: **принят для задач 25A–25H, 21 октября 2026.** Обзоры:
- **Finished Plan Review — PASS с исправлениями:** два блокера закрыты, исправления внесены.
- **Evidence Audit:** неверные утверждения исправлены.
- **Повторные проверки исправленных частей** — PASS с поправками без блокеров; поправки внесены, см. «Решения обзоров».

Основание:

- опись дизайна [25-ui-design-inventory](../features/assistant-behavior/evidence/25-ui-design-inventory.md) — холст https://claude.ai/artifact/HPRQLuAiVj4p5fPEhehsQu, страница «Ambient · финал», 22 макета;
- опись интерфейса по коду [docs/design/ui-inventory.md](../design/ui-inventory.md);

## Problem Statement

Интерфейс macOS собран из стандартных `GroupBox` и раскрывающихся блоков в одной прокрутке:
- нет своей системы цветов и шрифтов;
- главное окно — длинная колонка;
- настройки — одна прокрутка 480×680;
- лента у края — обычная панель.

Пользователь сделал дизайн на системном стекле Liquid Glass (macOS 26+). В нём есть вкладки дела, страница шага, лента со сворачиваемыми карточками, настройки с боковой панелью и строка меню со статусом.

## Solution

Минимальная версия macOS-приложения поднимается до 26 (D72). Небольшой слой оформления добавляет:
- цвета светлой и тёмной тем;
- нужные роли шрифтов;
- несколько повторяющихся компонентов.

Экраны перекладываются на системные элементы:
- `NavigationSplitView` со стеклянной боковой панелью;
- вкладки дела;
- системные кнопки-капсулы и стекло;
- системные меню и диалоги (D75).

Отмена чтений источников переходит из экранов в модель и на корень окна. Так переход между вкладками не прерывает чтение (D76), а остальные проверки остаются рядом с теми же вызовами модели. Новые данные ядра не добавляются (D73), экраны «на будущее» не делаются.

## User Stories

1. Вижу главное окно со стеклянной боковой панелью: дела, «Предложения N», свёрнутые «Завершённые», статус с паузой.
2. Выбор другого дела по-прежнему спрашивает о несохранённых изменениях, а выделение в списке не прыгает раньше ответа.
3. Дело открывается вкладками «План / Заметки / Связи / Источники / Помощь». На вкладке плана есть блок «следующий шаг», а у шага — отдельная страница.
4. Начатое чтение источника продолжается, пока я смотрю другие вкладки этого дела, страницу шага или редактор (D76).
5. Лента у края — стеклянная панель:
   - карточки сворачиваются в строку;
   - панель по-прежнему не забирает фокус, а ответ печатается.
6. Настройки — окно с боковой панелью разделов, включая Todoist.
7. В строке меню статус показан символом, меню системное. При выходе меню показывает завершение. Если главное окно открыто, в нём видна полоса хода завершения.
8. Тёмная тема получается из системных цветов (D74). «Уменьшить прозрачность» и «Увеличить контраст» работают системно.
9. Тексты новых элементов есть на английском и русском.

## Implementation Decisions

### Решения развилки

**Принят независимый план Plan Simplicity Reviewer:**
- слой оформления внутри цели `AmbientMacOS`;
- навигация выводится из `AssistantModel`;
- стили задаются на корнях;
- проверки остаются на месте;
- задачи идут последовательно.

**Отличия:**
- **Цвета в коде, а не в `.xcassets`** (Pattern Librarian предлагал каталог). Своих цветов всего четыре пары, ресурсов изображений нет, а риск сборки `actool` в конвейере `yarn` отпадает.
- **D76: отмена чтений источников переносится в модель и на корень окна.** Pattern Librarian и Finished Plan Review: скрытая смонтированная вкладка хрупка. Она отменила бы чтение при открытии страницы шага, грузила бы все источники при открытии дела и оставляла скрытые элементы в порядке фокуса.

**Отклонены:**
- ручное CSS-стекло;
- свои `ButtonStyle`;
- отдельный пакет оформления, протокол `Theme`, объект окружения, маршрутизатор;
- `NavigationStack` для страницы шага;
- `List(selection:)` на локальном `@State`;
- свои меню и диалоги с затемнением, `MenuBarExtra(.window)`, второй `NSStatusItem` (D75);
- своя полоса вкладок;
- тесты снимков экрана (стекло не рисуется в `ImageRenderer`, UI-тестов нет);
- режим «выход» внутри `closing`;
- скрытая смонтированная вкладка «Источники»;
- компоненты, у которых ещё нет потребителей.

- **Голосовой помощник:**

  - `VoiceHelper/Info.plist` `LSMinimumSystemVersion` → 26.0.
- **Xcode и Rust:**
  - `MACOSX_DEPLOYMENT_TARGET` 14.0 → 26.0 в обеих конфигурациях `Ambient.xcodeproj` (`project.pbxproj:146, 164`);
  - окружение Rust `scripts/macos.sh:6`.
- **CI** (`.github/workflows/macos.yml`, `runs-on: macos-latest`): нужен раннер с macOS 26+ и SDK 26+. Тестовая цель с minos 26 выполняется на ОС раннера. Если такого раннера нет — BLOCKED к оркестратору.
- **Тексты о «минимум macOS 14»:** `README.md:41`, `src/platforms/macos/README.md:74, 98, 106`, `docs/development.md:6`, `docs/project-status.md:11`. Исторические `docs/verification.md`, `spec.md`, execution и evidence остаются историей.

### Ранние пробы — в начале 25A

Пробы — одноразовые маленькие приложения SwiftUI/AppKit в `target/verification/25a/probes/`. Это не приложение Ambient, поэтому данные пользователя (`Application Support/dev.ambient.foundation`, записи Связки ключей) не затрагиваются.

Исполнитель собирает и запускает каждую пробу, проверяет программно (`canBecomeKey`, `isKeyWindow`, `NSApp.isActive`, `hitTest`, рамки) и снимками экрана самих проб (D78). Итог и снимки — в `target/verification/25a/`. Сначала проверяется, что `.glassEffect(in:)`, `GlassEffectContainer` и `.buttonStyle(.glass)` компилируются с Xcode 27.1 при цели `.v26`.

- **R1 — настройки с боковой панелью.** `NavigationSplitView` внутри сцены `Settings`: размеры, панель инструментов.
  - Запасной путь: сцена `Window(id:)`, открываемая через `openWindow(id:)`, вместо `SettingsLink` (`AssistantView:22`, `AssistantMenu:46`).
- **R2 — лента у края.** `NSPanel` без активации (`.titled`, прозрачный и скрытый заголовок, `.fullSizeContentView`, `isOpaque = false`, `backgroundColor = .clear`):
  - корень SwiftUI с `.glassEffect(in: .rect(cornerRadius: 30))` внутри `NSHostingView` — основной путь;
  - `NSGlassEffectView` — запасной путь.

  Проверяется: печать в `TextEditor`, панель не активирует приложение, прозрачные области не перехватывают нажатия.
- **R3 — главное окно.** Скрытый заголовок и кнопки окна над стеклянной боковой панелью `NavigationSplitView`; вид белого листа содержимого; срабатывает ли `.onDisappear` корня сцены `Window(id:)` при закрытии окна и что происходит при повторном открытии. От этого зависит отмена чтений при закрытии окна.
- **R4 — строка меню.**
  - Метка `MenuBarExtra` с символом SF Symbol по состоянию.
  - Видны ли иконки пунктов меню на macOS 27 при `.menuBarExtraStyle(.menu)` (стиль задаётся явно) и `labelStyle(.titleAndIcon)`.
  - Если иконки скрыты и SwiftUI их не возвращает — пункты без иконок. API AppKit 27 для этого не используется.

Если поведение расходится с документацией — QUESTION с наблюдением, а не скрытый обход. Если выбран запасной путь R1 — меняются `AmbientApp.swift`, ссылка на настройки в 25B и меню 25H.

### Слой оформления (`Design/`)

**`Theme.swift`** (25A):
- **Нейтральные цвета** — системные семантические (`.primary`, `.secondary`, `.tertiary`, фон текста для белого листа, `controlBackgroundColor` или `.quaternary` для вложенных заливок). Светлая тема и тёмная (D74) получаются сами.
- **Четыре пары своих цветов (заливка, текст):**
  - готово — `#E8F4EC` / `#17663A`;
  - устарело — `#FCEEDB` / `#8A470C`;
  - ошибка — `#FDEDEB` / `#A1231A`;
  - уточнение — `#E6EEFB` / `#1F4F9E`.

  Тёмные варианты — системные `.green` / `.orange` / `.red` / `.blue`: заливка с малой непрозрачностью, текст — сам цвет. Реализация — один помощник `Color(light:dark:)` на `NSColor(name:dynamicProvider:)`.
- **Цвет присутствия** — системный `.orange`.
- **Шрифты** — SF Pro и SF Mono; роль заводится, только если используется в трёх и более местах. Опорная шкала дизайна:
  - заголовок дела 26/600;
  - «следующий шаг» 18/500;
  - текст карточки 15,5;
  - основной 14;
  - элементы управления 13;
  - подписи 12;
  - моноширинный 11,5.

  Остальное — системные стили текста.
- **Радиусы:** лист 20, карточка 22, строка 14, поле 12, лента у края 30, кнопки и метки — капсула. Радиусы окна и меню — системные (D75). Отступы — константы, только если повторяются.

**`Styles.swift`** (25A):
- `AmbientInsetGroupBoxStyle` — вложенная заливка, радиус 18;
- `View.ambientTheme()` задаёт этот стиль и оттенок. Применяется на трёх настоящих корнях:
  - содержимое сцены `Window(id: "memory")`;
  - содержимое сцены `Settings`;
  - корень `NSHostingView` ленты у края.

  Меню `MenuBarExtra` стилей не принимает.
- Кнопки — только системные стили:
  - на стекле — `.glass`;
  - на белом листе — `.bordered` / `.borderedProminent` с `.buttonBorderShape(.capsule)`;
  - опасные действия — `Button(role: .destructive)`.

**Компоненты** — каждый появляется в задаче, где у него первый потребитель:
- `Callout` — блоки ошибки, предупреждения, сведения, несохранённого (25B, вместо красного текста `AssistantView:30-42`);
- `PageControls(first:next:)` с необязательным `first` — семь рядов листания, пять пар и два «только далее»: `AssistantView:155-167, 287-299, 345-357, 309-313`; `ManualPlanView.swift:223/229` и около `:295/301` (`PlanDraftFields`); `IntegrationSourcesView:135`. Вводится в 25B, дальше используется там, где ряд переделывается (25C, 25D, 25F);
- `StatusRing(state)` — `Circle().stroke` по трём нынешним статусам `statusKey` и выводимому «завершение» (25B). Только внутри окон, всегда с символом или подписью;
- `Pill` — смысловая метка (25C);
- `WorkRow` — ход работы с отменой; замыкание и признак `disabled` приходят от вызывающего (25E);
- пустые состояния — системный `ContentUnavailableView`, без своего компонента.

Стекло не кладётся на стекло; связанные стеклянные элементы — в `GlassEffectContainer`; внутри листа содержимого стекла нет (HIG).

### Как сохраняются проверки

- **Перечень проверок.** Перед каждой задачей исполнитель снимает перечень

  `rg -n "\.disabled\(|\.onChange\(|\.onDisappear|\.task\(id|\.alert\(|\.confirmationDialog\(|\.sheet\(" Sources/AmbientMacOS`

  (сейчас около 111 строк), а после задачи — сравнивает. Каждое исчезнувшее или перенесённое выражение объясняется в handoff. Единственный разрешённый перенос смысла — отмена источников в модель и на корень (25C).
- **Сначала перенос, потом оформление.** Код переносится в новые файлы без изменений с проверкой сборки, оформление меняется вторым шагом.
- **Блокировка взаимодействия.** `.disabled(model.busy || model.closing)` (`AssistantView.swift:52`, `:503` в `AssistantStatusView`, `AssistantMenu.swift:38`) остаётся; на новом корне окна он покрывает и боковую панель. Модельные охраны `requestSelection`, `discardChanges`, `canToggleManualPause`, `select` уже проверяют `!busy && !closing`.
- **Остаются как есть:**
  - `.alert` на `pendingSelection` (`AssistantView:66-93`);
  - `confirmationDialog` удаления (`:94-120`);
  - `.onChange` → `chatGPT.selectedTaskChanged()` и `.onChange(manualPause)` → `resetAssistance` (`:57-65`, с прежним значением `model.isCreatingTask ? nil : snapshot?.selectedTask`);
  - `.onChange(of: source.target)` в `IntegrationSourcesView:55`;
  - защита предпросмотра 08B по `taskID`/`revision` (`SelectedAssistanceView:55-56`; у этого экрана своей отмены нет, D76 его не касается).

### Отмена чтений источников (D76, 25C)

Сейчас обработчики у экранов разные:
- `LocalProjectsView:123-126` — исчезновение, смена дела, пауза, недоступность помощи;
- `CodexSourcesView:144-148` — то же и `.task(id: task)`;
- `IntegrationSourcesView` (GitHub, Jira, Todoist) — только исчезновение и недоступность помощи; `.task(id: task.id)` отменяет лишь собственную загрузку метаданных.

Решение:
- **Что убирается.** Из экранов источников уходят `.onDisappear { cancel() }`, `.onChange(of: task)`, `.onChange(of: manualPause)` и `.onChange(of: assistanceReady)`. Остаётся `.onChange(of: source.target)`.
- **В модели** (`AssistantModel`):
  - `snapshot` получает `didSet`, который сравнивает прежнее и новое `selectedTask` (ID и ревизию);
  - `manualPause` получает `didSet`;
  - при изменении оба вызывают `cancelSourceViews()` (существует, `AssistantModel.swift:111-117`, отменяет все пять источников).

  Так отмена работает и без окна, и её можно проверить тестом.
- **На корне** `AssistantView` остаётся то, чего модель не видит:
  - `.onChange(of: chatGPT.assistanceReady)` при `false`;
  - `.onDisappear` корня (закрытие окна, по итогу R3).

  Оба вызывают `cancelSourceViews()`, который становится внутренним.
- **`close()`** по-прежнему закрывает все пять источников; корень его не дублирует.
- **Переходы.** Вкладки, страница шага, страницы редактора и раздел «Предложения» — обычные условия `switch`. Переход между ними не отменяет чтение; результаты (наблюдение, предпросмотр, выбор) живут в моделях. Открытие шага или редактора перезагружает снимок через `selectPlan`, но не меняет значение `selectedTask` — это проверяется тестом.
- **Строже, чем сегодня.** GitHub, Jira и Todoist теперь отменяются и при паузе, и при смене дела — по списку D76. Правка текущего дела тоже отменяет чтение (смена ревизии — например, сохранение текста дела или выполнение шага на другой вкладке). Так сегодня работают локальные проекты и Codex: чтение привязано к версии дела, и ядро всё равно отклонило бы сохранение.

### Окна и сцены

**Главное окно (`AssistantView`):**
- **Каркас** — `NavigationSplitView` вместо `HStack` в прокрутке. `.defaultSize` сцены (сейчас 660×700 при минимуме 740) пересматривается под боковую панель 244.
- **Боковая панель** — `List(.sidebar)` с системным стеклом, по порядку:
  1. «Предложения N» (`.badge`);
  2. новое дело;
  3. открытые дела;
  4. «Завершённые» (`Section(isExpanded:)`);
  5. `PageControls`;
  6. ссылка на настройки;
  7. капсула статуса с паузой (`safeAreaBar(edge: .bottom)` или `safeAreaInset`).
- **Выбор дела.** Привязка списка:
  - `get` возвращает `nil`, если открыт раздел «Предложения» или создаётся новое дело; иначе — `snapshot.selectedTask?.id`. Это нынешняя логика галочки `AssistantView:146`.
  - `set(id)`: если `id == snapshot.selectedTask?.id && !model.isCreatingTask`, только показывается раздел дела. Во всех остальных случаях, включая открытый редактор нового дела, — `Task { await model.requestSelection(.task(id)) }`.
  - Раздел переключается на дело в `.onChange(of: model.snapshot?.selectedTask?.id)` и `.onChange(of: model.isCreatingTask)` корня. Так он следует за любым путём выбора, включая кнопки окна несохранённого. Если там нажали «Отмена», пользователь остаётся там, где был.
  - Повторное нажатие выбранного дела при открытой странице шага или редакторе ничего не меняет: у них приоритет.
- **Раздел содержимого** — `@State section: {suggestions, case}`.
  - Переход в «Предложения» при несохранённом черновике разрешён: черновик живёт в модели, строка дела помечена как несохранённая. Сейчас лента и редактор видны на одной странице одновременно.
- **Страница дела выбирается по приоритету:**
  1. `editorKind` — проекция только для чтения существующего закрытого `Editor` (`AssistantModel.swift:32-43`, 10 случаев; булевы признаки `:104-110, 552-559` из него уже выводятся). Редакторы: новое дело, заметка, проверка, новая проверка, новый шаг, зависимость, завершение. Проверка и новая проверка загружаются с выбранным шагом, поэтому `editorKind` важнее `selectedStep`.
  2. `snapshot.selectedStep` — страница шага.
  3. Иначе — вкладки дела.
- **Тесты на `editorKind`.** `MemorySessionTests.swift:202, 329, 332` переписываются на `editorKind` в 25D в том же изменении. Выражение `.onChange` (`:57`) переносится с тем же значением.
- **Страница шага:**
  - открыть шаг — `requestSelection(.step(id))`: модель сразу входит в правку шага с заполненным черновиком, а окно шагов начинается с этого шага;
  - у завершённого дела страница шага недостижима (`selectPlan` отвечает `.completed`), поэтому план завершённого дела — список только для чтения;
  - «Назад к плану» — `requestSelection(.task(current))`.
- **Режим правки текста дела и шага** — признаки `editingTask` и `editingStep` в `@State` самого `AssistantView`, не в `CaseDetailView`: смена раздела их не теряет. Модель в обоих случаях уже в правке (`editor == .task` / `.step`), поэтому признак только показывает поля. Поля видны при `editingTask || (editorKind == .task && model.hasUnsavedChanges)`, для шага так же: несохранённый черновик всегда виден. Признаки сбрасываются:
  - при сохранении;
  - при `discardChanges()` той же сущности;
  - при «Сохранить» или «Не сохранять» в окне несохранённого;
  - при смене сущности (`.id(step.id)`, смена дела).
- **Вкладки дела** — системный сегментный `Picker`, содержимое строится условно. В 25C вкладки «Заметки», «Связи», «Источники», «Помощь» показывают прежние разделы как есть, а редактор шага остаётся встроенным. Новые страницы приходят в 25D и 25F.
- **«Следующий шаг»:**
  - это первый шаг загруженной страницы, у которого `MemoryStep.ready` и нет `completedAtUTC`;
  - блок показывается только на первой странице шагов (D81, реализация в 25D): на дальней странице раньше может быть другой готовый шаг;
  - если на загруженной странице такого нет, а `steps.nextAfter != nil`, блок скрыт — дальше не читается;
  - готовность в Swift не выводится, только из ядра;
  - «ждёт шаг N» показывается, только когда нужные страницы зависимостей загружены (как порядковые номера в #16).
- **Диалог выхода:**
  - новый метод `AssistantModel.beginClosing()` ставит `closing = true`; `applicationShouldTerminate` (`AmbientApp.swift:44`) вызывает его первым, до `chatGPT.shutdown()`. Сейчас `closing` ставится только в `close()` после него, и в этом промежутке модель принимала ввод;
  - отдельного признака нет: если закрыть память не удалось, `close()` по-прежнему сбрасывает `closing` (`AssistantModel.swift:432`); если не удалось закрыть вход, сессия и так закрыта — как сегодня;
  - видно меню с состоянием «Завершение…» и недоступными пунктами; полоса хода без затемнения — только если главное окно открыто;
  - своего окна и затемнения нет (D75).
- **Остальные диалоги** — системные `.alert` / `.confirmationDialog`.

### Несоответствия дизайна — решения по умолчанию

Правило: существующие тексты и поведение из кода важнее; тексты дизайна — только для новых поверхностей; данных, которых нет в ядре, нет и на экране (D73). Номера — из раздела 5 описи.

- **#1.** Одна шкала: заголовок дела 26, заголовки редакторов 22, поля листа 32×36.
- **#2.** Результат проверки — всплывающее меню (F11), три прежних значения.
- **#3.** Цвет голоса — токен ошибки.
- **#4, #5.** Вкладки источников — только имена, без статуса каждого источника; подзаголовок плагина — как в F34.
- **#6.** Листание — только если есть что листать.
- **#7.** «N из 32» — предел выбора.
- **#8, #9.** Прежние тексты повторного открытия и выхода.
- **#10.** Неизвестный исход входа — прежний блок и системное подтверждение.
- **#11, #12.** Ошибка рисунка F33 не переносится; `status.cloudUnavailable` — прежний текст.
- **#13.** Меню «⋯» дела: «Изменить», «Завершить» или «Открыть снова», «Отключить» или «Вернуть напоминания», «Удалить» — существующие действия.
- **#14, #15.** Редакторы — отдельные страницы, один за раз; зависимости — под списком плана.
- **#16.** Порядковые номера шагов — только при загруженном плане.
- **#17, #18.** Прежние элементы переноса заметок и настроек источников внутри новых вкладок.
- **#19.** «Следующий шаг» — по правилу выше.
- **#20.** Развёрнутая карточка ленты: цель ответа, иначе явное нажатие, иначе первая не устаревшая.
- **#21.** «Предложения» — `chatGPT.feed.count`; заголовок ленты у края считает видимые строки.
- **#22–25.** Существующие компоненты.
- **Прочее:**
  - заголовок карточки ленты — текст дела, если оно на загруженной странице, иначе прежний номер;
  - заголовок дела — усечённый `MemoryTask.text`, полный текст выделяемый ниже;
  - показываются уже существующие данные: дата проверки `MemoryCheck.confirmedAtUTC`, если есть, статус и дата связи `MemoryLink.actionAtUTC`;
  - тёмная тема, «Уменьшить прозрачность», «Увеличить контраст», фокус, наведение — системные.

## Уточнения реализации 25C

Принято оркестратором 21 октября 2026 ([приёмка](../../target/verification/orchestration/25c-parent-inspection.md)).

- **«Ждёт шаг N»** показывает номера шагов (ID) — те же числа, что в «Шаг №», в строках «A → B» и в редакторе зависимостей. Порядковые номера им противоречили бы.
- **Вкладки завершённого дела:** только «План», «Заметки» и «Связанные задачи». Если выбранной вкладки нет, показывается план (вычисляемая привязка, без своего состояния).
- **Обновление доступности помощи** (`reloadAssistanceAvailability`) перенесено из `SelectedAssistanceView` в контейнер дела: `.task(id: open ? task.id : nil)`. Иначе «Источники» оставались бы закрытыми, пока не открыта «Помощь».
- **Отмена в модели.** `didSet` у `snapshot` сравнивает ID и ревизию выбранного дела, у `manualPause` — значение. Тест наблюдает отмену через `generation` моделей источников (`private(set)`).
- **Редактор нового дела** не отменяет чтение текущего дела: это редактор. Сохранение нового дела выбирает его, и тогда чтение отменяется.
- **Вкладка не сбрасывается** при смене дела.

## Уточнения реализации 25D

Принято оркестратором 21 октября 2026 ([приёмка](../../target/verification/orchestration/25d-parent-inspection.md)).

- **Приоритет страниц** — вычисляемое `AssistantModel.casePage` (`editor` / `step` / `tabs`) по `editorKind` (`MemoryEditorKind`, 10 случаев без данных).
  - Правка дела и шага — режимы, а не страницы.
  - Страницы редактора: новое дело, заметка, новая заметка, новый шаг, новая проверка, проверка, зависимость, завершение. Заметка — тоже страница: встроенного редактора больше нет.
  - Отмена редактора проверки возвращает на страницу шага.
- **Поля шага** видны при `editorKind == .step && (editingStep || hasUnsavedChanges)`, для дела условие то же.
  - Причина: после действия плана на странице шага `changePlan` возвращает модель в правку дела, а страница шага остаётся.
  - Поэтому «Изменить шаг» в этом случае сначала снова открывает шаг.
- **Сброс признаков правки** — прежний список плюс уход модели из правки этой сущности (`.onChange(of: model.editorKind)`). Это прочтение «смены сущности»: без него поля дела появлялись бы снова без запроса. Явные сбросы из списка ADR оставлены.
- **«Отменить изменения»** доступна всегда: на странице редактора это и путь назад. Прежнее условие делало бы страницу пустого нового шага, зависимости или завершения тупиком.
- **Действия шага** (копирование промпта и ссылки, выполнить или вернуть, удалить, проверки) переехали со строки плана на страницу шага. Строка плана — кнопка, открывающая страницу.
- **Результат проверки** — системный `Menu` из трёх прежних значений (текущее недоступно).
- **Обновление доступности помощи** — на внешнем контейнере дела. Возврат к тому же делу из редактора нового дела больше её не перечитывает.
- **«Следующий шаг» (D81):** `AssistantModel.nextStep` = `stepsAfter == 0 ? snapshot.nextStep : nil`.
- **План завершённого дела.** Ядро при завершении очищает план (`clear_plan`), поэтому список только для чтения пуст. Вкладка плана, как в 25C, показывает полезные ссылки. «3 из 3 выполнено» из макета F17 не показывается: данных нет (D73).
