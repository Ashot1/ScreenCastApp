# ADR-003: постоянная память Rust и первая нативная граница

Статус: реализован и проверен в независимой основе 06 по D56, 2026-10-19. Полная 06 и облачный помощник ещё не приняты.

## Контекст

Нужен настоящий путь сохранения намерения, удаления и ручной паузы без зависимости от облачного вывода. Следующий согласованный срез добавляет несколько дел и связи. При принятии решения Rust crate и Swift package были пустыми; архитектура требовала выбрать постоянное хранилище до первой записи.

## Решение

Память хранится в SQLite, единственный владелец — Rust. Используем `rusqlite` с `bundled`: одна собранная версия SQLite вместо зависимости от системной библиотеки macOS. Начальный выбранный релиз — 0.40.2 (bundled SQLite 3.53.2 через libsqlite3-sys 0.38.2), точная версия и транзитивные зависимости фиксируются в Cargo.lock. Реализация обязана проверить доступность и сборку; несовпадение подтверждённого контракта возвращается координатору, не скрывается другой библиотекой.

Поддерживаемая версия Rust этого среза — 1.99, установленная и проверяемая на рабочем Mac. MSRV самой библиотеки — 1.88; это не заявление о проверке проекта на 1.88. Старое декларативное 1.85 из пустого каркаса не сохраняется ценой закрепления устаревшей зависимости. Проверка на Windows остаётся отдельным условием: локальная сборка не подтверждает её выполнение.

Транзакция атомарно меняет содержимое и ревизию намерения. Удаление удаляет текст, оставляет только минимальное состояние удаления/ревизию; ручная пауза хранится отдельно. Ошибки открытия, чтения, транзакции и неподдерживаемая версия схемы возвращаются явно. Не создаём пустую память вместо повреждённой, не перезаписываем неизвестную схему, не добавляем автоматические миграции или совместимость с отсутствующим старым продуктом. Будущие изменения схемы получают явное решение перед внедрением.

Для обычных таблиц включается `secure_delete=ON`, используется проверенный `journal_mode=DELETE`; обновления не создают прикладной архив старого текста. Это логическое удаление и снижение остаточных копий, не обещание физического стирания SSD, резервных копий или снимков ОС. Никаких ключей, токенов, снимков или аудио в этой БД нет. Native shell выбирает закрытый каталог Application Support; пользовательский текст не попадает в обычные логи.

Нативный app target Xcode использует SwiftUI и существующий Swift package. Rust bridge собирается как `staticlib` и импортируется через C. Node/Yarn остаются только средствами разработки. Не вводим генератор проекта, отдельный сервер, универсальную шину событий или вторую память Swift.

Первая C ABI граница обслуживает только реальные операции открытия/закрытия, чтения и изменения памяти/паузы. Версия ABI, ограниченные UTF-8 буферы с явной длиной, ошибки и владение фиксируются перед реализацией. Type Scaffolder проверяет контракт только на чтение; важный код пишет Sol. Вызовы последовательны вне UI-потока, фоновых Rust workers и callbacks в этом срезе нет. Закрытие происходит после завершения принятых вызовов; не выдумываем асинхронную отмену там, где её нет. Core сохраняет запрет unsafe, FFI изолирован в bridge.

## Альтернативы

- Один JSON-файл проще для одного значения, но требует собственного порядка атомарной записи, обработки конкурентных записей и связанной памяти следующего согласованного среза. SQLite предоставляет нужные транзакции без собственного файлового протокола.
- Только пустая оболочка не проверяет пользовательское действие через ядро и не даёт необходимой основы 07.
- Полный 06 до начала памяти сохранял бы ненужную зависимость от облака и системных разрешений; D56 прямо разрешает раздельную разработку с сохранением полной приёмки.

## Проверка

Настоящая временная БД и настоящий Swift–C–Rust путь: сохранение/изменение/повторное открытие, удаление без возврата текста, отдельная ручная пауза, явные ошибки/повреждённая схема, границы UTF-8/байтов, безопасное владение/закрытие. Тестовые двойники допустимы только в тестах. Собранный `.app` и успешные unit/integration tests не доказывают ненавязчивость UI, G5, полную G7 или Windows parity.
