# Первичные источники прямого SIWC-клиента

Проверено 2026-10-18; материалы по GPT-6 Luna/Fast/effort и реализация D55 сверены 2026-10-19. Документация описывает контракт; она не подтверждает согласие, квоту или доступ модели конкретного аккаунта.

- [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in): dynamic registration, стабильный host ID, выданный client ID, loopback callback, state/PKCE/nonce и проверка ID token. Для возвращающегося аккаунта требуется повторное использование его issued ID и проверка выбранной идентичности; безопасное повторение начальной регистрации на каждом запуске из этого не следует.
- [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions): привязка client ID к проверенной личности сохраняется отдельно от токенов. Возвращение без ID-token hint поддерживается через выбор аккаунта и сверку issuer/subject. Стенд хранит одну такую привязку с правами 0600, а одну полную сессию — в macOS Keychain. Полноценная система нескольких аккаунтов не вводится. Блокировка после неопределённой первой регистрации — консервативное правило стенда, не обещание провайдера.
- [OIDC discovery](https://auth.openai.com/.well-known/openid-configuration): анонимный GET 200 вернул issuer `https://auth.openai.com`, authorize `/api/accounts/authorize`, token `/api/accounts/oauth/token`, JWKS `/.well-known/jwks.json`, алгоритм `RS256`. Клиент сверяет эти значения и останавливается при несовпадении. Документ не содержит credentials пользователя.
- [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference): право direct inference берётся из реально выданного scope; access token и ID token имеют разные назначения/audience. Стенд не декодирует access token для принятия доменных решений. Refresh использует issued client ID, refresh token и тот же resource; новый срок берётся из фактического `expires_in`, replacement refresh token обязателен. Scope и ID token в refresh могут отсутствовать; прежние права и личность не выводятся из непроверенных новых данных. `earliest_refresh_at` не используется из-за неподтверждённых единиц.
- [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference): тот же bearer для `GET /v1/models`, ответ `models[]`, видимые slug; прямой `POST /v1/responses`, `store:false`, `stream:true`. Terminal events и ошибки квоты после начала потока нужны для оценки результата.
- [GPT-6 Luna model](https://developers.openai.com/api/docs/models/gpt-6-luna): выбранный slug `gpt-6-luna`; reasoning effort `low` и `high` описаны для модели. Это не подтверждает доступность slug в конкретном аккаунте или SIWC.
- [Responses API reference](https://developers.openai.com/api/reference/resources/responses/methods/create): ответ содержит `reasoning.effort`; поле может отсутствовать или быть null. В тестовом результате оно сохраняется как метаданные ответа. Совпадение со значением запроса не является свидетельством о фактически выполненном внутреннем рассуждении модели.
- [Fast mode](https://developers.openai.com/api/docs/guides/fast-mode): `service_tier: fast` запрашивает Fast; ответ сообщает фактический tier, а `priority` — название той же быстрой обработки. Возвращённый `default` или отсутствующий tier не считается подтверждением Fast. SIWC совместимость требует отдельного фактического результата.
- [SIWC errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery): `subscription_sharing_unsupported_capability` допустим как ошибка неподдерживаемой возможности; пробник сохраняет известный код и не повторяет запрос.
- [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations): доступные поля отличаются от платного API. Выходной `max_output_tokens` не используется; старый тест принудительного incomplete не переносится. Для HTTP нельзя рассчитывать на сохранённую историю через previous_response_id.
- [Using your ChatGPT plan in other apps and sites](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites): cap приложения ниже 100% предотвращает использование кредитов. Другой достаточный запрет — общий Allow apps to use credits OFF. Настройка не равна остатку, не резервирует отдельную квоту и проверяется через Settings → Usage. Баланс 0 и автопокупка — другие параметры. Прямого документированного API проверки cap не обнаружено.
- [openId-client 6.8.8: enableNonRepudiationChecks](https://github.com/panva/openid-client/blob/v6.8.8/src/index.ts): публичная функция включает проверку JWS подписи token response, помимо runtime-проверок issuer/audience/claims в code и refresh grant. Refresh не включает DPoP; ветка библиотечного повтора только для DPoP nonce здесь недостижима. Используется `clockTolerance:0` и RS256, подтверждённый metadata. [jose 6.2.12](https://github.com/panva/jose/tree/v6.2.12) подписывает только локальные тестовые примеры как прямая devDependency; отдельного production JWT-пути нет. Обе библиотеки MIT, точные версии и транзитивные зависимости закреплены scoped lockfile.


- [OIDC Core, Refresh Token Response §12.2](https://openid.net/specs/openid-connect-core-1_0.html#RefreshTokenResponse): ID token при refresh необязателен; при его наличии сверяются прежние issuer/subject, audience и срок, nonce — если он присутствует. Библиотека выполняет signature/issuer/audience проверки, Node дополнительно связывает subject/nonce с исходным входом; отсутствующий token не запускает userinfo.
- Локальный Apple SDK `Security.framework/Headers/SecItem.h`: `kSecUseKeychain` — destination только для Add; `kSecMatchSearchList` — список `SecKeychainRef` для ограничения запроса. Это основание изоляции реального временного-Keychain теста без изменения default/global search list. Использованы SecItem CRUD и file-based generic-password. Legacy `SecKeychainCreate/Delete` применены только в помеченном test fixture. В [Apple Security StorageManager](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/StorageManager.cpp) `shouldAddToSearchList` допускает автоматическое добавление только login/System, а не private `isolated.keychain`; тест отдельно сравнивает metadata default/search list до/после создания, CRUD и удаления. Контракт/команды: [native-keychain/README.md](../../../../../tests/feasibility/01-cloud/native-keychain/README.md).

- [Official SIWC devkit responses.ts](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/main/packages/local/src/responses.ts#L44-L51), проверено 2026-10-19: POST Accept:text/event-stream; MIME нормализуется split/trim/lowercase. Direct route может вернуть корректный SSE без Content-Type; явный другой MIME отвергается. Успех требует response.completed. Это подтверждённое отличие прежнего guard стенда, но не установленная причина исторической пробы с неизвестным Content-Type.

- [Official SIWC devkit output accumulation](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/main/packages/local/src/responses.ts#L53-L75), повторно проверено управляющим и External Researcher 2026-10-19: devkit накапливает response.output_text.delta и требует response.completed. Это основание отдельной диагностики промежуточного текста; наш terminal-only validator и проверка Fast в этом пакете не ослаблены. Реальная проба 38ac… показала valid none candidate при terminal output=[], но default tier остаётся отказом.

## Условия данных и оставшаяся неопределённость

На вход OpenAI отправляются только собственный синтетический текст, инструкции/схема и при выбранном графическом случае PNG. Ответ приходит потоком. Browser OAuth отдельно передаёт провайдеру сведения о входе, аккаунте, устройстве и разрешениях; приложение получает нужные для проверки ID claims. Сам вход не открывает разговоры и память ChatGPT. [SIWC information shared / privacy](https://help.openai.com/en/articles/20001410-sign-in-with-chatgpt).

[SIWC Terms, 2026-09-29](https://openai.com/policies/sign-in-with-chatgpt-terms/#3-privacy--security) включают Terms of Use и Service Terms, требуют минимизации данных и согласий. Они не задают отдельный срок хранения промптов или обещание no-training. Общие [Terms of Use](https://openai.com/policies/terms-of-use/#content) и [model-performance policy](https://openai.com/policies/how-your-data-is-used-to-improve-model-performance/) различают режимы обработки, но явно не классифицируют direct SIWC как обычный бизнес/API-режим.

Поэтому `store:false` здесь **не обещает отсутствия журналов, кэша или обучения**. Применимость конкретных сроков и настроек обучения к direct SIWC не подтверждена. Локальное удаление файлов не подтверждает удаления копий OpenAI. Исторические «API no-training / до 30 дней» из [history-sources.md](history-sources.md) не переносятся на подписочный OAuth. Эти пределы приемлемости нужно явно оценить перед использованием личного контекста; нынешние входы только синтетические.
