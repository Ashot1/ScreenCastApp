## Проверенный контракт

Проверено External Researcher и исполнителем по первичным источникам 18.10.2026. Это документированные возможности, не результаты модели.

- Box требует `jev-1.14.0`/preview; 1.14 опубликована 14.10.2026, `jev-latest` указывает на 1.13.0. Английский — основной язык; русский отдельно не гарантирован. Для будущей пробы предлагается фиксированный ID 1.14.0, без автоматического перехода на alias. [Models](https://docs.typesafe.ai/models)
- Images/Box экспериментальны, поставщик не считает их готовыми для production. Требуется `TypeSafe-Danger-Zone-Images: true`. Статические PNG/JPEG, каждая сторона 280–1568 px, файл ≤16 MiB. Тело, обработанные изображения и раскрытый ввод имеют отдельные пределы 32 MiB. Выход за пределы отклоняется, автоматического resize нет; EXIF orientation не применяется. Повтор ссылки повторно добавляет изображение в контекст. `usage.input_tokens` включает изображения по обычному входному тарифу; формула их предварительного подсчёта пока не дана. [Images](https://docs.typesafe.ai/images)
- Box даёт один прямоугольник с краями `top/bottom/left/right` в `[0,1]` от верхнего левого угла, даже без объекта. Отдельный Noul/Choice может проверять присутствие/несколько целей; это всё ещё та же модель. Рамка и confidence не доказывают наличие. Точного контура и универсального порога нет. [Box](https://docs.typesafe.ai/primitives/box)
- HTTP API требует Bearer key; ответ содержит model, answers, usage. Документированы 400/401/413/415/422/429/529. SDK делает повторы по умолчанию; поэтому в будущем прогоне их нужно выключить и допускать каждую попытку отдельно. Таймаут не доказывает отмену или нулевой расход. [API](https://docs.typesafe.ai/api), [SDK retries](https://docs.typesafe.ai/sdk/python/api/retries)

## Офлайн-клиент: PASS, живой G4: BLOCKED

Реализация изолирована в [probe.mjs](../../../../../tests/feasibility/05-jev/probe.mjs) и [budget.mjs](../../../../../tests/feasibility/05-jev/budget.mjs). Никаких изменений общего runtime, production-бюджета, манифестов или новых зависимостей нет. Нативные Node fetch/FormData/Blob готовят настоящий multipart с PNG, pin версии и обязательный Images header. В память ответа допускается максимум 64 KiB, redirects/повторы запрещены. Ответы тестового HTTP-сервера существуют только в `.test.js` и проверяют границу клиента; они не выданы за ответы Jev.

`yarn vitest run tests/feasibility/05-jev/probe.test.js tests/feasibility/05-jev/budget.test.js` — **35/35 PASS**, машинный результат последнего прогона — [offline-tests.json](offline-tests.json). TDD: ожидаемые падения до реализации builder (2), validation (11), ledger (5), admission/HTTP (9), восстановления ID/свидетельства резерва (1), затем предупреждения 80% (5); новое уменьшение cap/аудит/обязательная причина также дали ожидаемые 13 падений до исправления. После каждого шага проверки стали зелёными. Покрытие:

- Настоящие multipart-байты принимаются локальным HTTP-сервером, включая сцену и образец; разметка/координаты эталона не отправляются. Русский текст формируется, но его понимание Jev не измерено.
- Presence/count/Box проверяются вместе; отсутствие, неоднозначность, противоречие, старый hash, нечисловые/неупорядоченные координаты и неверная версия не разрешают подсветку. Неполный usage остаётся null. Преобразование обрезки проверено на независимых числовых эталонах.
- Отсутствующие ключ, подтверждённая верхняя стоимость, условия или бюджет блокируют отправку до транспорта. HTTP 429, неправильный JSON, ответ сверх лимита, timeout и redirect сохраняют весь резерв без повтора.
- SQLite выполняет резерв до отправки в `BEGIN IMMEDIATE`; два независимых процесса не могут вместе превысить предел. Неизвестные расходы остаются при повторном открытии, существующий журнал не переинициализируется, settlement требует свидетельство и не переписывается. Расход выше резерва записывается и закрывает дальнейший допуск.
- Предупреждение 80% появляется при **$0.80** из подготовительного $1 с учётом уже подтверждённых расходов, неизвестных резервов и новой попытки. Preflight только возвращает warning; после COMMIT атомарного резерва реальный запуск печатает одно структурированное событие в stderr до fetch. Это сумма расходов и резервов, не объявленная фактическим списанием. Новые тесты проверили одну миллиардную доллара ниже границы, точную границу, значение выше неё, смешанные расходы/резервы и порядок «сохранённый резерв → одно предупреждение → настоящий loopback fetch → HTTP-приём».
- Старый журнал с cap $2.50 понижается до $1 атомарно без потери opening, фактических расходов и NULL-резервов. Недостающие старые поля аудита остаются NULL; сумма выше $1 даёт отрицательный остаток и блокирует следующий вызов. Перед каждым новым POST уже записаны case ID, явная причина, модель, фактический endpoint, верхний резерв и его свидетельство. После ответа/ошибки charged остаётся NULL (unknown) до сверенного счёта; отдельное дублирующее outcome-состояние не добавлено. Ключи/изображения/сырые ответы в базе отсутствуют.
- Рабочий CLI имеет один канонический журнал для всех задач/волн. Альтернативный путь разрешён модульным тестам только с HTTP `127.0.0.1` и буквально фиктивным `test-only-key`; рабочий Jev URL с другим журналом блокируется.

`node tests/feasibility/05-jev/probe.mjs plan` — код 0, перечислены 11 доступных офлайн-заготовок, не назначен полный платный прогон: [offline-plan.json](offline-plan.json). `preflight P-ru` с явной причиной первого случая — ожидаемый код 2, `network_calls: 0`, общий остаток null: [offline-preflight.json](offline-preflight.json). Блокеры: missing_api_key, live_disabled, unconfirmed_upper_bound, unconfirmed_account_terms, missing_or_invalid_shared_ledger. Это успешная офлайн-подготовка с закрытым платным допуском.

Путь настройки без секретов: `tests/feasibility/05-jev/live-settings.json`, пример — [live-settings.example.json](../../../../../tests/feasibility/05-jev/live-settings.example.json). Реального файла пока нет. Ключ будущей пробы задаётся только через **TYPESAFE_API_KEY** из разрешённого хранилища. Журнал — **docs/features/assistant-behavior/evidence/05-jev/jev-tests.sqlite3**, ещё не создан: сначала нужна явная общая сверка opening exposure всех задач, а не вымышленный ноль. Пороги presence/unique в примере null: значения в тестах синтетические и не перенесены в рабочую конфигурацию. До калибровки клиент возвращает `unverified` с проверенными числовыми свидетельствами; даже `candidate` содержит `highlight_permitted: false`.
