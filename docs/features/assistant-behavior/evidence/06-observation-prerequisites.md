# Предпосылки наблюдения — 20 октября 2026

Исследование следующего пути полной06 и реального сигнала активности для09. Спецификация и реализация ещё не выбраны. 14A выполняется; 08B готова после её приёмки. Ни один новый системный доступ не запрашивался.

## Что есть в приложении

Codebase Scout подтвердил: production LocalPermissions только читает состояние Screen Capture/Accessibility по кнопке с prompt=false. Нет AX reader, foreground watcher, input monitor или ScreenCaptureKit capture. NSWorkspace используется для браузерного входа, а scenePhase в LoginItemView — для обновления статуса автозапуска.

Пауза хранится в Core; AssistantModel/MemorySession передают её изменение. Core требует session, user-reported no-credit, текущую High capability и снятую паузу. AppDelegate завершает карточку, ChatGPT и память. Закрытие карточки не останавливает ассистента.

Опоры: `LocalPermissions.swift`, `AssistantModel.swift`, `ChatGPTCoordinator.swift`, `AmbientApp.swift`, `EdgeCardController.swift`, `LoginItemView.swift`; Core `assistance_store.rs`. Смена фокуса, вход в macOS и wake не являются установленным сигналом работы.

## Что доказал стенд03

[Отчёт03](03-native/report.md) и [протокол](../../../../tests/feasibility/03-native/protocol.md) фиксируют отсутствие Accessibility/Screen Capture/Input Monitoring у проверенного процесса. Подготовлен отдельный test-only reader, но реальное чтение Jira, остановка по вводу, отзыв прав и матрица приложений не пройдены.

AXDocument/AXURL могут отсутствовать и не доказывать URL активной вкладки. Снимок окна не содержит весь документ. Разрешения тестовой сборки не означают разрешения готового приложения. Эти ограничения нельзя обходить списком зашитых браузеров или объявлять прочитанный фрагмент полным содержимым.

Следующее исследование штатных API проверяет владение AX-наблюдением, срок и остановку IPC, определение app/site/folder до чтения содержимого и признаки активности без записи клавиш. Реальные TCC, UI, окна и личные данные не проверяются. До готового контракта новый production путь не запускается.

## Штатные механизмы по установленному SDK

Pattern Librarian проверил заголовки AppKit/ApplicationServices/CoreGraphics:

- `NSWorkspace.frontmostApplication` и `didActivateApplicationNotification` дают PID/bundle ID до чтения AX-текста. Это сигнал выбора контекста, а не доказательство работы.
- `AXObserverCreate`/`AddNotification`/`GetRunLoopSource` наблюдают один PID. Focused-window/element notifications могут быть неподдержаны; глобального системного AX observer для всех приложений нет.
- `AXUIElementCopyAttributeValue`, bounded `CopyAttributeValues` и `CopyParameterizedAttributeValue` читают поддержанные приложением роли/детей/значения/диапазоны. Наличие `AXDocument`/`AXURL` в SDK не гарантирует их поддержку или однозначную идентичность вкладки.
- `CGEventSourceCounterForEventType` и `SecondsSinceLastEventType` дают счётчик/давность ввода без текста клавиш. Сам ввод не доказывает работу по делу. Более широкий event tap для одного такого признака не нужен; реальные условия TCC не испытаны.
- `AXUIElementSetMessagingTimeout` ограничивает отдельный IPC, не отменяет его и не задаёт общий срок всего обхода. Вызовы нельзя блокирующе делать на UI-потоке; запрос остановки не означает фактического завершения.

До содержимого проверяется app, затем надёжная область сайта/документа. Неизвестная область не считается разрешённой. Проверки до/после чтения не создают атомарности: вкладка может смениться между ними. Эту границу нужно проверить и честно учесть до обещания общего соблюдения исключений. Ни SDK, ни test-only reader не доказывают готовый production capture.

## Независимый вариант и незакрытая граница

Plan Reviewer предложил следующий самостоятельный путь: явное «Помоги с этим окном» → проверка области → ограниченный AX-фрагмент без навигации → точный просмотр → явное сохранение нужного как внешнего наблюдения в выбранное дело → прежняя помощь/лента08B. Дело не определяется PID или фокусом. Screenshot fallback не решает проверку исключений и пока не предлагается.

Это приближает содержательное наблюдение, но не доказывает WorkStarted и не реализует09. Reader должен иметь одного владельца, общий срок/пределы, выполнять IPC вне MainActor и удерживать занятость до фактического завершения. Отдельный процесс не вводится без доказанной необходимости.

**До спецификации остаётся вопрос привязки:** как AX-контент гарантированно относится к разрешённому документу/сайту, если область может смениться между проверками, в том числе A → исключённая B → A. Стабильные PID/окно и одинаковый URL до/после сами этого не доказывают. Primary-source исследование проверяет доступную native границу; требование не ослабляется до «сначала прочитать, затем отфильтровать».

Реализацию нельзя объявить доказательством G2: реальные тестовые окна, Jira, разные приложения, исключения/отзыв и настоящий Fast остаются отдельной приёмкой после предоставления доступа. Новый тикет06G пока не выпускается.

## Результат проверки привязки к области

External Researcher не нашёл документированной общей AX-границы, которая связывает предварительный допуск сайта/папки с неизменным поддеревом на всё чтение. Управляющий отдельно прочитал установленные `AXUIElement.h` и `AXAttributeConstants.h`: multiple-attribute API описывает несколько значений одного элемента и обработку ошибок, но не атомарность; AXURL обязателен для disk/network item, не для всякой вкладки или её потомков.

[Apple AX model](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/OSXAXmodel.html) и [уведомления](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/ImplementingAccessibilityforCustomControls.html) оставляют свойства и публикацию изменений приложению. Это не барьер на смену документа. Ссылка на AX-объект и PID устанавливает app-границу, но не неизменный origin/путь.

Исследованы текущие публичные Chromium/WebKit handlers URL/attributes; они тоже не предоставляют внешнему AX-клиенту транзакцию по области. Их текущие main не доказывают поведение установленного браузера. Совместное получение URL и текста не заменяет проверку до чтения: текст к тому времени уже получен.

Поэтому кандидат06G **пока не готов к реализации по текущему privacy-контракту**. Нужна доказанная граница на стороне источника либо отдельное согласованное изменение требования; последнее самостоятельно не вносится. Это ограничение общего screen-reader пути, не блокер уже проверенных файловых источников,08B или дальнейших объектных API-коннекторов. Реальных разрешений/окон/API аккаунта не проверяли.
