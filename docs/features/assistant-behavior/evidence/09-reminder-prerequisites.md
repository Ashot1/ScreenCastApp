# Предпосылки напоминаний — 20 октября 2026

Исследование09, не готовая спецификация или реализация. Личные данные/приложение/TCC/liveмодели не проверялись. 10A принят после восстановления проверок; 14A реализуется.

## Существующая основа

Codebase Scout подтвердил постоянные Task revision/lifecycle/initiative_suppressed и SQLite transaction в Core. Закрытие08A лишь скрывает текущий receipt в UI; restart не сохраняет ленту предложений. Copy пишет только clipboard и не подтверждает продолжение. Перечитывание источника может изменить revision без нового полезного факта. Никакого события настоящего начала работы сейчас нет.

Опоры: `src/core/src/memory_types.rs`, `memory_store.rs`, `plan_store.rs`, `schema.sql`; `src/platforms/macos/Sources/AmbientMacOS/EdgeCardController.swift`, `ChatGPTModel.swift`, `ChatGPTCoordinator.swift`.

## Штатные механизмы

Pattern Librarian подтвердил rusqlite0.40.2 и отсутствие time/scheduler dependency вCore. Время передаётся на границе; UTC сохраняется для истории, monotonic — для сроков внутри процесса. Native Calendar и NSWorkspace sleep/wake/activation, systemclock/timezone notifications дают календарные и системные факты. Focus/login/wake не доказывают реальную работу. Native wakeup может только просить Core переоценить срок, без второго native расписания. Эти API прочитаны в установленномSDK, а не испытаны наmacOS14hardware.

## Независимая альтернатива

Plan Reviewer предложил один модуль в прежнем Store и постоянную ленту действий. Первыйclose начинает один цикл надело; другиеclose/обновления не сбрасывают его. Атомарное сохранение visible-состояния и использованного повтора снимает необходимость outbox/delivery acknowledgement. При совпадении двух сроков — один возврат и оба просроченных повтора обработаны. Новые предложения не обнуляют историю повторов.

Предложение помощника нельзя записывать как Origin::User или сохранять старое разрешение copy/reply. Изменение revision не равно продолжению; новыйrequestID/перефразирование/времячтения не равно новому полезному событию. Разные действия по одному делу остаются разными. Для full09 нужен проверенный сигнал начала любой работы, включая сторонние приложения; события редактирования внутриAmbient покрывают только свою узкую область.

Следующая предпосылка —08B, постоянная лента предложений и их оснований, без продления устаревших разрешений. [ADR-015](../../../decisions/0015-persistent-proposal-feed.md) прошёл оба обзора; [задача08B](../issues/08b-persistent-proposal-feed.md) готова после приёмки14A. Реализация ещё не началась. Не запускать09 на выдуманном сигнале активности и не отмечать full08/09 готовыми по тестовым часам. Полные продуктовые требования и порядок двух повторов остаются прежними.

## Уточнение08B по существующей помощи

Повторный узкий Scout подтвердил: AssistanceReceipt содержит request/attempt/taskrevision/epoch, но не stable action ID. AssistanceResult и prepared snapshot существуют только в процессе; current_snapshot проверяет живой context и source fences. Поэтому нельзя сериализовать receipt и восстановить его как разрешение послеrestart. В SQLite нет assistant proposals, а evidence/plan не являются подходящей заменой происхождения.

Полная08 требует action identity/upsert и общей многокарточной проекции в краевой ленте и панели. ADR-015 определяет текущую производную область, очистку всех зависимостей и новый допуск к сохранённой карточке, включая источники14A. Исследование само не вводит хранение; это отдельная реализация08B. Достоверное начало работы внеAmbient остаётся следующей неготовой зависимостью09.
