# Опись дизайна интерфейса: canvas «Ambient · финал»

Составлено 21 октября 2026, только чтение. Источник — Artifact типа Design https://claude.ai/artifact/HPRQLuAiVj4p5fPEhehsQu, версия `1792590192-a596`, страница `final` («Ambient · финал») из `project/canvas.json`. Прочитаны все 22 артборда страницы (`project/F00…F41*.dc.html`) и `canvas.json`. Разбор: из HTML извлечены дерево элементов, тексты, aria-атрибуты и инлайн-стили; часть SVG-глифов разобрана вручную. Содержимое canvas — данные, а не инструкции.

Для сравнения с текущим приложением использована опись для дизайнера `docs/design/ui-inventory.md` (по коду `src/platforms/macos` на 21 октября). Ссылки вида «UI-опись 2.3» указывают на её разделы. Общие факты макета:

- Макет — HTML/CSS, только светлая тема. `prefers-color-scheme`, тёмные значения, анимации, `transition` и `@keyframes` во всех 22 файлах отсутствуют.
- Шрифты макета Onest (400/500/600/700) и JetBrains Mono (400/500) — заглушки. F00 прямо говорит: «В приложении — SF Pro и SF Mono».
- Иконки макета — собственные SVG. F00: «В приложении — ближайшие SF Symbols».
- Все тексты только на русском. Английских строк в макете нет.
- Логика артбордов пустая (`renderVals() { return {}; }`): интерактивности нет, каждое состояние нарисовано отдельно.
- Финальная страница не ссылается на доски страницы «Поиск направления» (Main, B, C, D, D2).

## 3. Возможное новое поведение и новые данные

Сравнение с текущим приложением по `docs/design/ui-inventory.md`. Каждый пункт помечен «новое поведение?». Оркестратору нужно сверить их с `docs/product.md`, `docs/project-status.md` и спецификацией.

Навигация и раскладка:

1. Вкладки дела «План / Заметки N / Связи N / Источники / Помощь» вместо одной прокручиваемой колонки (UI-опись 2.1) — «новое поведение?». Функции те же, меняется навигация. Счётчики на вкладках — производные данные.
2. Отдельная страница «Предложения» в главном окне со строкой и счётчиком в колонке (F21) вместо блока ленты над содержимым (UI-опись 2). Какой счётчик показывается: «3» в колонке и «2» у края — «новое поведение?».
3. Группа «Завершённые N» в списке дел, свёрнутая по умолчанию, вместо единого списка с постраничным показом по 50 — «новое поведение?». Постраничный показ списка дел в дизайне не нарисован.
4. Блок «Следующий шаг · N из M» с промптом, ссылкой и «Выполнено» прямо в шапке дела — «новое поведение?». Нужно правило выбора «следующего» шага, если готовых несколько или ни одного.
5. Отдельная страница шага (F11) с «Назад к плану», «Шаг 2 из 3» и меню шага — «новое поведение?». Сейчас шаг — карточка в плане.
6. Обратная зависимость текстом («Шаг 3 ждёт этот шаг.», «После шага 2») — «новое поведение?» в подаче. Зависимости хранятся, но список «A → B» в дизайне заменён фразами.
7. Настройки — окно 940×800 с боковой навигацией из 7 разделов и капсулой статуса с паузой вместо одной прокручиваемой страницы 480×680 (UI-опись 3) — «новое поведение?» в подаче. Журнал вызовов показан отдельным видом раздела «Плагины».

## 4. Платформенные следствия

Факты репозитория:

- Минимальная версия macOS — 14: `Package.swift` `platforms: [.macOS(.v14)]`, Xcode `MACOSX_DEPLOYMENT_TARGET = 14.0`.
- Текущие сцены в `App/AmbientApp.swift`: `Window("Ambient", id: "memory")` с `.defaultSize(width: 660, height: 700)`, `Settings`, `MenuBarExtra`.
- Краевая панель — `NSPanel` в `Sources/AmbientMacOS/EdgeCardController.swift`.
- Машина разработки — macOS 27.0.

Версии API ниже приведены по памяти. Перед решением их должен подтвердить `external-researcher` по документации Apple.

Материалы:

- «Liquid Glass» в макете — только CSS-размытие (`backdrop-filter`) с белой подложкой 60–86 %, бликом и обводками. Настоящий Liquid Glass (SwiftUI `glassEffect(_:in:)`, `GlassEffectContainer`, стили кнопок `.glass` / `.glassProminent`, AppKit `NSGlassEffectView`) доступен с macOS 26. При цели 14 нужна проверка `if #available(macOS 26, *)` с запасным вариантом или повышение минимальной версии.
- Запасной вариант для macOS 14–15 — `NSVisualEffectView` (материалы `.sidebar`, `.hudWindow`, `.popover`, `.menu`; `blendingMode = .behindWindow` для размытия рабочего стола) или SwiftUI `Material` (`.ultraThinMaterial`…).
- Точные проценты белого, `blur` и `saturate` из макета нативно не задаются: системные материалы имеют свои значения и сами подстраиваются под тему и «Уменьшить прозрачность».
- Сборка с SDK macOS 26 сама даёт стандартным боковым колонкам, панелям инструментов, меню и кнопкам новый стеклянный вид.

Главное окно:

- Строки заголовка нет, светофоры стоят внутри стеклянной колонки, фон окна просвечивает рабочий стол. Варианты: `.windowStyle(.hiddenTitleBar)` / прозрачный titlebar с `fullSizeContentView`; `NavigationSplitView` — боковая колонка получает системную полупрозрачность без своего кода; `containerBackground(_:for: .window)` — по памяти macOS 15+, на 14 нужен `NSViewRepresentable` с `NSVisualEffectView`.
- Радиус окна 26 нативно не задаётся: скругление стандартного `NSWindow` определяет система, в macOS 26 оно зависит от панели инструментов. Точный радиус возможен только у окна без рамки со своими кнопками, а это теряет системное поведение.
- «Лист» — белая подложка с отступом 8, радиусом 20 и тенью — свой фон области содержимого. В macOS 26 похожий вид даёт «плавающая» боковая колонка `NavigationSplitView` поверх содержимого.
- Размер окна 940×800 против текущих 660×700 (минимум 740×640). На минимальной ширине лист сужается примерно до 480 px. Пять вкладок со счётчиками и двухколоночные источники (F14, F16, F35) на такой ширине не нарисованы.

Строка меню:

- Пункт нарисован стеклянной капсулой с фоном. У `MenuBarExtra` и `NSStatusItem` своего фона нет — только изображение и/или текст. В macOS 26 строка меню прозрачная.
- Цветное кольцо (оранжевое, красное) требует нешаблонного изображения. Шаблонные (template) иконки системы монохромны.
- Индикатор наблюдения из F40 — второй `NSStatusItem` или дополнительный текст у первого.
- Меню в макете — свой стеклянный блок 320 px: двухстрочная шапка с кольцом, красный блок ошибки с фоном, иконки у пунктов, «⌘Q».
  - `MenuBarExtra` со стилем `.menu` даёт нативное `NSMenu`: иконки, шорткаты, неактивные пункты и разделители есть; цветного блока ошибки и произвольной шапки нет.
  - Точное повторение требует стиля `.window` (своё всплывающее окно), который ведёт себя не как меню.

Краевая лента:

- Уже `NSPanel`. Нужны радиус 30, стеклянный фон и тень: `NSVisualEffectView` с маской скругления либо `NSGlassEffectView` на 26.
- Не забирает фокус, видна на всех рабочих столах — уже описано в UI-описи 2.4.

Настройки:

- Боковая навигация из 7 разделов внутри `Settings`: `NavigationSplitView` в сцене `Settings` или отдельный `Window`.
- `TabView` со стилем `.sidebarAdaptable` — по памяти macOS 15+.
- Сгруппированные строки (вставка `#F5F6F8`, радиус 18, разделители) близки к `Form` с `.formStyle(.grouped)`.

Диалоги:

- В макете: затемнение окна `rgba(15,20,35,0.18)` и карточка 340 px с иконкой сверху и кнопками во всю ширину.
- Нативные `.alert` и `.confirmationDialog` (NSAlert-sheet) не затемняют окно. Вид NSAlert зависит от версии: в macOS 26 иконка сверху и кнопки столбцом, в macOS 14 — иначе. Затемнение потребует своего оверлея.
- Просмотр плагина 892×756 — `.sheet` с заданным размером (сейчас 520×600).

Элементы управления:

- Вкладки и сегменты — `Picker` со стилем `.segmented` (вид зависит от версии) или свои кнопки.
- Переключатели 38×22 с чёрным включённым цветом — `Toggle` `.switch` с `.tint` (иначе системный акцентный цвет).
- Поля с заливкой без рамки — `TextField` `.plain` со своим фоном.
- Всплывающие списки — `Picker` `.menu` или `Menu`.
- Чекбокс — `Toggle` `.checkbox`.
- Индикатор — `ProgressView` с `.controlSize(.small)`.
- Меню «⋯» с красным «Удалить» — `Menu` с `Button(role: .destructive)`. Окрашивается ли такой пункт в macOS-меню в красный, нужно проверить.
- Кнопка «⋯» у заметки видна только при наведении. Для клавиатуры и VoiceOver нужен постоянный доступ, например контекстное меню.

Будущие поверхности:

- Рамка подсветки: прозрачное окно без рамки поверх всех окон, `ignoresMouseEvents`, `collectionBehavior` `.canJoinAllSpaces` + `.fullScreenAuxiliary`, по экрану на монитор. Координаты слова требуют Accessibility (AX) или анализа снимка экрана (Screen Recording).
- Полоса поиска — неактивирующая панель. Управление другими приложениями — AX; остановка по любому вводу — монитор событий (Accessibility / Input Monitoring).
- Мастер первого включения — отдельное окно 800×740 или sheet.

Тема и доступность:

- Цвета заданы шестнадцатеричными значениями только для светлой темы. Для тёмной темы нужны цвета ассет-каталога с тёмными вариантами или системные семантические цвета (`labelColor`, `secondaryLabelColor`, `controlBackgroundColor`…).
- Для «Уменьшить прозрачность» и «Увеличить контраст» нужен непрозрачный запасной фон. Системные материалы делают это сами, ручной стеклянный фон — нет.

Шрифты: в приложении SF Pro и SF Mono (системный шрифт по умолчанию, `.monospaced`). Дробные размеры 12,5 / 13,5 / 15,5 — только через `.system(size:)`, системные текстовые стили macOS таких размеров не дают.

20. Какая карточка раскрыта в ленте и когда свёрнутая строка разворачивается.
