# 17A: Выбранная активная задача Todoist

Spec: [ADR-018](../../../decisions/0018-selected-todoist-task.md) (редакция на общем движке), [ADR-020](../../../decisions/0020-integration-layer-contract.md). Decisions: D56/D57, [D60, D61, D65–D67](../decisions.md). Evidence: [Todoist](../evidence/17-todoist-integration-research.md).

**What to build:** Личный профиль Todoist → явно выбранная активная задача, её проект и ограниченные комментарии → точный просмотр 1–32 выбранных объектов → атомарное сохранение в существующее дело → помощь 08B с происхождением и неполнотой. Todoist — третий HTTP-адаптер общего движка интеграций и пятая встроенная интеграция с переключателем в «Настройки › Интеграции». Импорт не вызывает модель и ничего не записывает в Todoist.

**Blocked by:** нет — 24A, 24C и локальная часть 24B приняты; пересмотренный ADR-018 принят 21 октября 2026 после обоих обзоров и повторных проверок. Реальные Fast/аккаунт остаются полной 17/G6.

**Status:** accepted — принят оркестратором 21 октября 2026 в локальном объёме ([приёмка](../../../../target/verification/orchestration/17a-parent-inspection.md), [handoff](../../../../target/verification/17a/handoff.txt)); настоящий аккаунт Todoist и полная 17/G6 открыты.

- [x] Вид `todoist` (5) в Core, providers, bridge и macOS; пятый переключатель; следующая схема с замороженной fixture прежней; прежняя схема отклоняется только для чтения, включая WAL.
- [x] Секрет — общий конверт Keychain, форма Bearer как у GitHub; замена, отзыв, удаление и 401 — общие правила движка. Личный токен честно обозначен как потенциально имеющий запись.
- [x] Аккаунт записывается в профиль один раз при первом `GET /user` (`Step::Pin`, D65): без повышения ревизии; отказ при исключении, дубликате, неверном формате (1–128 байт); отмена до ответа не даёт записи; другой аккаунт в `GET /user` — 409; хранимый `scope` при сохранении читается в мосту из Core.
- [x] Фиксированные GET REST v1 без конечного `GET /user` (D67), точная identity пользователя и начальной/конечной задачи, `max_requests` 9, общий резерв конечной проверки. Общие задачи не отвергаются из-за `task.user_id`. Нет redirects/retries/proxy/write/public_key/Sync POST.
- [x] Пауза сервера по D66: при 429/503 читаются заголовок `Retry-After` и тело ошибки ≤64 KiB (поле реестра `error_body`, чтение по возможности, `Adapter::pause` получает ответ), берётся больший будущий срок; 503 ставит паузу только при наличии заголовка `Retry-After`, неоднозначном заголовке или ключе `error_extra.retry_after`; сырое тело нигде не сохраняется (проверка канарейкой); общий метод `retry_after_deadline` для Jira, GitHub и Todoist.
- [x] Проект и комментарии частично доступны при отказе категории; пагинация, нестабильные дубликаты и неизвестный cursor видны; конфликтующий дубликат непригоден для привязки; ошибка якоря запрещает всю привязку.
- [x] Буквальный Markdown, missing/null/invalid/пустой текст, due/date-only/floating, удалённые и только вложение — без выдуманного факта, UTC или полной истории.
- [x] SourceKey с аккаунтом и однозначные JSON-кортежи ID; версия зависит от содержимого; метаданные, хэш и размер проверяются при открытии.
- [x] Предпросмотр, сохранение одной транзакцией, отзыв 08B (включая основания без цитат), выключение интеграции, пауза, отмена и сроки — общие правила движка, проверенные на GitHub/Jira, плюс сквозная проверка Todoist; сведения Todoist видны в карточке 08B; промпт модели не меняется.
- [x] Настоящий путь Swift → C → Rust → временная SQLite/изолированный Keychain/loopback и помощь 08B проверены. Нет production mocks, реальных credentials, UI/TCC и вызовов модели/Jev.
- [x] Обязательные специалисты, RED/GREEN, code simplicity review, проверки, сборка, подписи, EN/RU; хэши исходников, логи, handoff, список изменений общих документов (раздел «Документация» ADR-018) и неизменность контрольных сборок по базе оркестратора.
- [x] Full 17/G6, завершённые задачи и история, тариф, настоящие права/UI/Fast/Windows явно остаются открытыми.
